# brainstorm: HTML-first 日报主文重排

## Goal

把日报从“多段并列、互相抢结论”的阅读方式，重排成以 HTML 为主的决策产品。读者先看到唯一的次日结论和推导骨架，再顺着市场效应、市场氛围、板块结构、资金方向、候选裁决和最终对象，读完整条推导链。Markdown 继续保留为辅助输出，但不再承担主布局。

## What I already know

* 用户明确希望：HTML 为主，Markdown 为辅，之后逐步替代成 HTML。
* 用户当前最强烈的不满不是“数据少”，而是“标题太多、层级太散、同一件事被反复讲、看不出重点和顺序”。
* 用户要的阅读路径是：先看市场效应和市场氛围，再看板块结构、热点和资金方向，最后才落到龙头/最终标的与次日推导。
* `N1-N9` 这套展示方式现在对用户来说太重，用户怀疑它已经把主线冲散。
* “候选流水账”如果继续放在前台，会把过程证据误看成正文重点。
* 现有实现已经有可复用基础：`html_report_view.py`、`html_report_renderer.py`、`front_page_v2_renderer.py`、`two_layer_decision_payload.py`、`selection_workflow.py`，以及 06-04 / 06-05 replay。
* 现有结构里，HTML 渲染已经是结构化视图驱动，不是纯 Markdown 直出；这意味着主文结构可以改，但不需要重做数据源。
* 用户更在意“这篇日报是不是能直接看懂当下发生了什么”，而不是把每个内部节点都摊开。
* 用户明确要求：不影响后续引用和推导的前提下，尽量把不必要的前台内容无效化、下沉或折叠，不要删掉有价值的数据结论。

## Assumptions (temporary)

* 主文应该采用“总-分-总”的金字塔式结构，而不是把 N1-N9 平铺成九个并列章节。
* 主文中的大多数重复小标题都可以合并，只保留能推动下一步判断的那一层。
* “历史判断纠偏”最好保留，但不需要独立抢一级标题，可以作为开场后的紧跟小节。
* 过程证据、候选池明细、步骤清单、数据来源说明可以继续存在，但应从正文退到证据层、折叠层或附录层。
* 对用户来说，真正重要的是：市场 -> 板块 -> 资金 -> 候选/最终对象 -> 次日动作。

## Open Questions

* 主文一级结构是否收成 4 个块？我推荐 4 个：开场裁决、市场/资金/板块主线、候选裁决、次日行动。历史纠偏放在开场裁决之后的小节里。

## Requirements (evolving)

* HTML 必须成为第一展示层，Markdown 只做辅助导出与兼容展示。
* 主文必须先回答“明天怎么做”，再解释“为什么这么做”。
* 主文必须保留一条顺滑的推导链：市场效应/氛围 -> 板块结构 -> 资金方向 -> 超车/失速/窗口 -> 龙头/最终对象 -> 次日动作。
* `N1-N9` 这类编号如果还保留，只能作为内部证据索引，不能再作为前台主叙事骨架。
* “候选流水账”不能再作为前台重点章节，只能下沉为过程证据。
* 所有仍有价值的数据结论必须迁移到新结构中，不能因为重排而丢失。
* 允许被无效化/下沉的前台内容包括：
  * 重复的编号式步骤标题。
  * 重复的“个股解读 / 备用观察 / 明日候选”并列段。
  * 重复表达同一事实的多段总结。
  * 只是在重复说结论、但不再推进推导的说明段。
* 不允许被删除的内容包括：
  * 市场效应、市场氛围、板块结构、热点、资金方向。
  * 最终对象与它的执行/观察条件。
  * 候选胜负原因。
  * 历史判断纠偏。
  * 与 replay 一致性相关的事实证据。
* 输出必须仍然能解释“这只标的从哪来、经过哪些筛选、为什么是它、为什么不是别的”。

## Acceptance Criteria (evolving)

* [ ] HTML 日报的主文顺序更收束，读者能从开头一路读到次日动作，不需要在多个并列标题里自己拼顺序。
* [ ] 前台不再出现“候选流水账”作为主叙事。
* [ ] 市场、板块、资金、最终对象、次日动作能串成一条清晰推导链。
* [ ] 有价值的数据结论被迁移或折叠，不因重排而消失。
* [ ] Markdown 辅助输出与 HTML 主结构保持同一套事实，不出现两套不同的最终对象。
* [ ] Replay 样例（至少 06-04、06-05）在新结构下仍能对齐既有事实。

## Definition of Done (team quality bar)

* 结构重排完成后，用户能一眼看出日报重点是什么、过程是什么、最终对象是什么。
* 同一条推导链在 HTML、Markdown、附录里保持一致，不再各说各话。
* 相关测试更新，且最小回归验证通过。
* 若有内容下沉到附录或折叠层，必须保留可追溯入口，方便后续引用和排错。

## Out of Scope (explicit)

* 不重写全部数据采集。
* 不改动当前选股引擎的核心判断，只重排日报表达和主文结构。
* 不恢复旧的本地库或旧发布路径。
* 不为了“更短”而删除有证据价值的数据结论。
* 不新增新的仓位档位或新的交易口径。

## Technical Notes

* 当前 HTML 输出由 `scripts/report/html_report_view.py` 提供结构化视图，再由 `scripts/report/html_report_renderer.py` 渲染。
* `scripts/report/front_page_v2_renderer.py` 仍在拼接较长的前台叙述，容易和结构化 HTML 的职责重叠。
* `scripts/report/two_layer_decision_payload.py` 已经在提供“前台结论 + 推导审计层”的双层结构，适合继续收束而不是拆散。
* `scripts/report/selection_workflow.py` 和相关 replay 已经把“最终对象唯一性”钉住，说明这次更适合改展示层和层级，而不是改对象契约。
