# Research: 三例一分钟曲线、公式与交易窗口复核

## Question

用真实一分钟数据重新回答四个问题：三个指定案例实际长什么样；哪个公式或公式类别最接近；三个既定窗口在当时能知道什么；这些结果能否支持 T+0 识别、T+1 条件参与、T+2 处理的日报研究方向。

## Sources

- 通达信公共行情协议 `KLINE_TYPE_1MIN`：
  - 主服务器 `115.238.56.198:7709`
  - 复核服务器 `218.75.126.9:7709`
  - 个股使用 `get_security_bars`，上证指数使用 `get_index_bars`
- 腾讯 `appstock/app/day/query`：复核 2026-07-10 两只个股的逐分钟收盘与累计量额。
- 腾讯 `fqkline`：复核三例日线 OHLC 和个股日量额。
- `tests/fixtures/quant_pressure_replay/raw/sh000001_20260521.json`：新浪五分钟上证冻结事实。
- 项目当前 Tushare 账号：实测 `freq="1min"` 的三例历史请求。

- 固定交易分钟横轴为 `09:31-11:30`、`13:01-15:00`，午休不计入曲率。
- 通达信会用极小浮点值表示无成交，三例 `14:59` 已归零并保留来源说明。
- 通达信指数 `vol` 近似 `amount/100`，不是真实成交股数；一分钟 fixture 中统一保存为 `null`，指数分析不用成交量。
- 上证实际日内低点发生在 `14:53`。旧五分钟记录的 `14:55` 是所在五分钟 bar 的结束标签。

### Tushare 结果

- 官方股票历史分钟接口是 `stk_mins`（doc 370），指数历史分钟接口是 `idx_mins`（doc 419）；两者都支持 `1min/5min/15min/30min/60min`，单次最多 8000 行，并可取十年以上历史分钟。
- 当前项目通道实测：两只股票的兼容端点 `stock_mins` 返回空表，正式 `stk_mins` 显示当前账号未开通历史分钟数据；上证指数的 `idx_mins` 返回空表。
- 项目现有分钟封装会在 `stock_mins` 空表后提前结束，不再尝试 `stk_mins`；指数路径也没有调用 `idx_mins`。最终三例均为 0 个可用 bar。
- 因此本轮不能把 Tushare 写成有效来源，也不能把空结果当成目标日期无行情。

## Formula Findings

### 公式方向修正

- 普通对数 `a+b log(1+kt)` 在下跌振幅为负时是前快后慢。
- 临界对数使用 `-log(1-t/T)` 作为正向形状，再由负振幅形成后段加速下跌。
- 归一化有限时刻幂律：

  `D(t)=A[1-(1-t/T)^m]/m`

  - `m=1`：线性。
  - `0<m<1`：后段越来越陡。
  - `m≈0.5`：根号临界，接近椭圆端点的局部外观。
  - `m→0`：逼近临界对数。
- `sqrt_ellipse_proxy` 只是固定起点的四分之一椭圆；新增 `shifted_ellipse_arc` 允许峰位左右移动，更公平地检验“鸭蛋”全天外观。

### 实际排名

| 案例 | 全日第一 | 下降段第一 | 分段点（全日 / 下降段） |
|---|---|---|---|
| 兆易创新 | 单变化点分段 | 单变化点分段 | 14:18 / 14:18 |
| 长电科技 | 单变化点分段 | 单变化点分段 | 14:48 / 10:04 |
| 上证指数 | 平移椭圆弧 | 单变化点分段 | 13:45 / 13:55 |

- 上证平移椭圆弧的全日中心参数为约 `0.20`，对应全天交易进度约 20%，与实际 `10:14` 高点接近。这支持用户的“鸭蛋”作为全天包络观察。
- 三例从客观收盘峰值到其后收盘低点都由单变化点分段模型第一，但换挡方向相反：兆易创新 `-4.775 → -10.746 bp/分钟`、上证指数 `-0.832 → -2.951 bp/分钟`，属于后段加速；长电科技 `-26.617 → -3.269 bp/分钟`，属于明显降温。共同冠军只说明一条直线不够，不支持“同一个量化公式支配三例”。
- 上述速度是只允许一个断点后的区间平均。长电科技在 `10:04` 后全段平均降温，不否认 `14:30-14:55` 再次加速；一个断点不能描述全部多轮换挡。
- 长电科技全日 `14:48` 分段点命中搜索上边界，不能把这个全日断点当成稳定的自然阶段位置。
- 兆易创新的全日/下降段最优分段点在 `14:18`，不能拿它解释早盘已经出现的压力；最佳几何断点不等于事件首次发生或真实触发时刻。
- 最优模型残差一阶相关约 `0.77-0.90`。一分钟点数多不等于独立证据多；AICc 和 ΔAICc 只能作事后形状比较，网格择优还会放大领先强度。

## Window Findings

### 09:30-09:35

- 兆易创新 `+1.74%`，长电科技 `+2.11%`，上证指数 `+0.14%`。
- 只有五个完整分钟，适合看开盘冲击、量额和相对强弱，不足以识别椭圆、Gompertz 或多轮压力。
- 三例在该窗口都因十五分钟样本不足而没有形成压力候选。

### 09:45-10:10

- 必须保留用户指定的完整窗口：`09:45-09:50` 前哨观察，`09:50-10:10` 主执行。
- 兆易创新到 `10:10`：窗口 `-2.15%`，十五分钟斜率 `-18.59 bp/min`，已是明确早发型下压。
- 长电科技到 `10:10`：窗口 `-1.86%`，十五分钟斜率 `-19.31 bp/min`，最后五分钟转正，属于下压中的短线回抽，不能把一小段反弹写成压力解除。
- 上证指数到 `10:10`：窗口 `+0.40%`，十五分钟斜率 `+1.54 bp/min`，仍是上行表象；早盘窗口无法预知午后才出现的鸭蛋弧下跌。
- 透明候选规则为“十五分钟斜率为负且进入下压类表象”，连续三个分钟结束点才确认：兆易创新 `09:47` 首次候选、`09:49` 首次三点确认，但 `09:54` 失效，之后 `10:00` 重来、`10:02` 再确认；长电科技 `10:02` 首次候选、`10:04` 确认；上证指数 `09:46` 短暂候选、`09:47` 即失效，到 `10:10` 未形成持续确认。
- 事后验收显示，到 `10:10` 兆易创新和长电科技的客观峰谷下降只完成约 `20.7%`、`23.9%`，上证指数因客观峰值尚未出现而为 `0%`。这说明早盘窗口确实早于主要风险完成，但三例不足以证明候选规则具备稳定的可交易领先量。

### 14:30-14:55

- 兆易创新 `-1.37%`，十五分钟仍为负但最后五分钟回抽。
- 长电科技 `-3.15%`，五分钟斜率 `-36.52 bp/min`，是明显尾部加速。
- 上证指数 `-0.67%`，距当时已知峰值约 `-2.95%`，连续下压成立；但此时已经太晚，只适合隔夜风险和尾部处理，不能写成早盘提前识别。
- 截至 `14:55` 的持续段实际分别从兆易创新 `14:24`、长电科技 `14:30`、上证指数 `13:50` 开始；不能把窗口边界误写成压力起点。
- 事后验收显示三例主要下降已完成约 `94.5%`、`96.5%`、`100%`，所以该窗口更接近尾部确认和隔夜处理，不是主要压力的提前预警。

三个窗口作为“开盘观察 → 早盘诊断背景 → 尾盘处理”的研究采样角色与三例不冲突；但早盘存在假候选，三例尚不能证明窗口时点本身有效。把三个窗口都写成能够提前发现量化踩踏不成立。

## Strategy Impact

- T+0：识别压力表象、降温和修复质量。加速本身先用于回避，不直接产生次日抄底资格。
- T+1：只有板块、相对强度和承接继续确认才讨论 B1；B2 只在进一步确认后补。
- T+2：固定卖出仍是待验证假说，必须与压力半衰期和可成交性一起回测。
- 2026-07-10 两例的 T+1 是 `2026-07-13`，T+2 是 `2026-07-14`；截至研究日均尚未发生，只能前瞻登记，不能填收益。
- 单账户若每天都有信号，会发生旧仓尚未卖出、新信号又要求买入的资金重叠。必须比较跳过重叠信号、两个 50% 资金槽、T+2 开盘先处理旧仓三种版本。

## Recommendation

1. 盘中识别只保留单侧滚动斜率、局部曲率、分段变化、反弹失败和修复质量。
2. 收盘后以有限时刻幂律作为统一生活化解释，再保留平移椭圆、分段、指数、Gompertz、临界对数和普通对数作为竞争模型。
3. 每个窗口把当时可知的价格斜率、曲率、成交额、近十分钟下跌占比、首次候选和持续确认放在一组；客观峰谷完成比例、后续最低和未来 `5/10/20` 分钟收益单列为事后验收，禁止回填当时判断。
4. 先把本轮作为不改变正式交易决定的研究报告；扩大普通下跌、消息重估、单一大资金执行、快速修复等保护样本后，再讨论接入日报研究段。
5. 三例不能证明量化账户身份、量化成交占比约 40% 或稳定套利收益。

## Impact

- PRD: 三例、一分钟粒度、三个窗口、Tushare 当前可用范围和未来日期限制均已落入验收。
- Design: 保持独立研究模块，不改五分钟阈值，不进入正式日报决定链。
- Implementation: fixture、公式、窗口和 HTML 均由同一 Python 3.14 计算结果生成；测试只读本地事实。
