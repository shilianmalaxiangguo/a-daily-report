# Design: B1/B2 与集合竞价 1x 执行回测

## Scope And Boundaries

本任务是独立历史重放研究。输入是冻结的 T0 正向对象和通达信一分钟/日线事实，输出是 JSON 与 Markdown 研究报告。它不调用日报生成主链，不更新数据库，不回写候选或仓位规则。

新增边界：

- `scripts/research/b1_b2_auction_backtest.py`：采集、校验、分析、渲染的单一独立入口。
- `tests/fixtures/b1_b2_auction_backtest/cases.json`：冻结事实，默认分析输入。
- `tests/test_b1_b2_auction_backtest.py`：时间因果、仓位、分类、费用与汇总测试。
- `reports/research/b1-b2-auction-backtest-20260721.{json,md}`：结果产物。
- `.trellis/tasks/07-21-b1-b2-auction-backtest/`：需求、研究、设计和执行记录。

现有 `scripts/report/`、`scripts/portfolio/`、`scripts/selection/`、Wiki 和正式报告均不修改。

## Contracts / Data Flow

### 1. 决策清单

脚本内维护 14 条不可变 `DecisionCase`，字段：

- `case_id`
- `report_date`
- `report_path`
- `source_format`：`legacy_explicit` 或 `standardized`
- `security_code`
- `security_name`
- `planned_position_x`：1 或 2
- `evidence_labels`

采集前从报告正文复核对象名称、代码和计划档；不读取后验结果字段。

### 2. 行情采集

`--collect` 才连接通达信：

1. 每个唯一代码分批请求日线和一分钟记录。
2. 从日线交易日序列推导报告日之后的 T+1 入场日和 T+2 退出日。
3. 选取 T0 前至少 7 个交易日日线、T+1 与 T+2 全部分钟。
4. 验证每个目标日 240 条分钟、时间格完整、分钟聚合与日线 OHLC 一致。
5. 保存来源元数据、原始行与规范化内容 SHA-256，原子写入 fixture。

服务器连接失败时可尝试研究中列明的复核服务器；fixture 仍记录实际服务器，不静默混源。

### 3. 特征计算

对 T+1 分钟按顺序计算：

- 开盘缺口、累计 VWAP、T0 MA5/MA7；
- 09:35 与 10:10 状态；
- B1 首次条件成立时刻；
- B2 首次条件成立时刻；
- 开盘位置档与早盘路径；
- 到统一退出前的 MFE/MAE。

累计 VWAP 只使用当前及此前成交额/成交量。所有条件函数接收截止索引，不得访问后续行。

### 4. 执行方式重放

每种方式返回零至两条 `FillLeg`：

- `weight_x`
- `signal_time`
- `fill_time`
- `fill_price`
- `reason`

聚合成交价按 `weight_x` 加权；收益按实际持有 x 计入账户暴露，同时提供每 1x 归一收益。

### 5. 退出与费用

统一退出价是 T+2 `14:30-14:55` 的成交额加权均价；若成交额不可用则使用成交量加权，二者都不可用时停止该样本。费用计算独立于行情逻辑，可通过 CLI 参数覆盖。

### 6. 输出

JSON 保存机器可审计的：

- 版本与参数；
- 来源覆盖和限制；
- 样本明细、特征、逐腿成交与收益；
- 全 14 笔和统一字段 12 笔汇总；
- 按开盘位置、早盘路径和组合的切片；
- 2 万元账户一手可成交性；
- 结论证据与反例。

Markdown 只从 JSON payload 渲染，不进行第二次计算。

### 7. 逐日账户账本与上证对比

逐笔结果不能直接复合为账户累计收益。新增独立的逐日账本，按交易时间处理同一账户中的所有成交腿：

1. 每个 `1x` 使用账户基线的50%，所有未退出持仓与当日新买合计最多 `2x/100%`；容量不足时按可用容量裁剪或不执行后续腿。早盘新仓先执行，旧仓在尾盘退出，因此旧仓仍占用当日早盘容量。
2. 入场日贡献从实际成交代理价计到当日收盘；后续持仓日按前一标记收盘到当日收盘；退出日按前一标记收盘到 `14:30-14:55` 退出价。买卖费用在发生日扣除。
3. 同日旧仓退出与新仓入场分别计算后相加，现金收益为0；账户净值按每日收盘和已实现现金统一标记。
4. 同源上证指数使用相同成交时刻、相同退出窗口和相同资金权重建立对照账本，另展示上证全日涨跌作为市场背景。
5. 同时输出标准化50%资金腿和2万元整手账户两套账本；逐笔独立复合保留，但明确不是账户累计。累计超额同时记录“账户累计收益减基准累计收益”的百分点差与相对净值超额。

冻结事实新增 `benchmark`，包含上证指数代码、来源、查询日、日线、目标日期一分钟记录和规范化内容哈希。缺少任一实际持有日期或成交时刻时停止生成，不跨源拼接。

## Compatibility / Migration

- 无迁移；新增文件不被正式日报导入。
- 分析依赖 Python 标准库与项目已有 `pytdx`，离线分析不依赖 `pytdx` 连接。
- fixture schema 使用 `b1_b2_auction_cases.v2`；结果 schema 使用 `b1_b2_auction_backtest.v2`。

## Tradeoffs

- 使用开盘价作为集合竞价代理可获得统一历史价格，但不能证明个人真实成交。
- 价格行为条件可回答入场时点问题，但缺少板块分钟同步，因此不能代表正式规则的全部条件。
- 14 笔全样本保留旧格式信息，覆盖更广但解释风险更高；12 笔保护样本字段更一致但仍无文件冻结时间证明。
- 固定 T+2 尾盘退出牺牲个股最优卖点，换来入场方式之间的公平比较。
- 单脚本减少当前任务的重复结构；如果未来正式接入主链，再另立任务抽取通用模块。

## Rollback / Roll-forward

- 回滚：删除本任务新增的独立脚本、测试、fixture、报告和任务目录，不影响正式日报。
- 向前修正：保留 v2 参数和结果，后续变更新增 schema/策略版本；不得覆盖 v2 后声称旧结果从未存在。
- 数据源异常：停止重新采集，继续保留已验证 fixture；报告标注查询日和来源状态。
