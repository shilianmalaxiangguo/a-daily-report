# B1/B2 与集合竞价 1x 执行回测

状态：逐日账户累计收益与上证对比已完成，等待提交确认

## Goal

用 2026-06-01 至 2026-07-21 已有日报中的正式明日对象和同源一分钟事实，比较集合竞价一次买入 1x、等待 B1 条件后买入 1x、把 1x 拆成两笔以及正式 1x/2x 计划四种执行方式，回答各类开盘位置和早盘走势下哪种买法更合适、收益与回撤分别是多少，而不预设 B1/B2 必然优于集合竞价。

## User Story

- **角色**：使用日报策略、当前本金基线约 2 万元的交易者
- **场景**：日报已经在 T0 选出次日唯一对象，但集合竞价一次买入 1x 与等待分时确认之间存在分歧
- **目标**：看见规则固定、逐笔可复核、没有事后挑点的历史比较
- **成功标准**：能够按开盘高低和 10:10 前走势读懂具体买法，并知道小样本能说明什么、不能说明什么

### 用户旅程

1. 读取报告首页的总体比较，先看样本数、净收益、最大回撤和未成交数。
2. 按大幅高开、中高开、平开、中低开、大幅低开与早盘走势查看逐类结果。
3. 下钻到每一笔，核对报告日、对象、计划仓位、触发时刻、成交代理价、退出价和未参与原因。
4. 根据保护样本和失败样本判断是否保留、修改或否定某种执行方式。

## What I Already Know

- 2026-06-01 至 2026-07-20 共存在 35 份正式执行摘要；2026-07-21 日报尚未生成。
- 其中 14 份存在可核验的唯一明日对象与正仓位：旧格式 2 份、统一字段格式 12 份；无对象日期必须留在覆盖统计中，但不伪造成交易。
- 当前正式仓位契约是 `0=0%`、`1x=50%=B1`、`2x=100%=B1+B2`。
- Wiki 同时存在“0x 新目标先买 0.5B、剩余 0.5B 等确认”的旧单位表达，与 `B1=1x` 不是同一口径；本任务把它作为“拆分 1x”实验，不反写正式仓位契约。
- Tushare 当前账号的历史分钟能力实测不可用，AkShare 小样本连接被远端断开；通达信公共行情已实测可覆盖 2026-06-03 至今的一分钟个股数据。
- 通达信一分钟时间戳为区间结束，完整交易日应有 240 条记录；`09:31` 记录代表首分钟。
- 仓库内历史日报未进入可追溯的 Git 新增提交，报告日期不等于文件冻结时间，因此结果属于历史重放研究，不是严格的当日前瞻样本。
- A 股 T+1 约束使入场日新买仓位不能当天卖出；本任务的主要退出统一使用下一交易日 `14:30-14:55` 窗口成交均价代理。

## Requirements

- [x] R1: 建立 2026-06-01 至 2026-07-21 的日报覆盖账本，保留 35 个已有日报日期、14 个正向对象、无对象与格式不完整状态，不从过程候选或后验复盘推断交易。
- [x] R2: 为 14 个正向对象冻结报告日、次日入场日、下一交易日退出日的一分钟和日线事实，记录 `query_date`、`source_date`、服务器、接口、时间戳语义与原始内容哈希。
- [x] R3: 在查看收益前冻结四种比较方式：集合竞价 1x、条件成立后 B1 1x、拆分 1x、按正式计划执行 B1/B2；另以集合竞价直接买完整计划作为同最大仓位对照。
- [x] R4: 所有盘中条件只使用当时已结束的分钟；条件在某分钟结束后成立时，统一使用下一分钟开盘代理成交，禁止在同一根分钟记录里同时观察并成交。
- [x] R5: 按开盘缺口五档和 10:10 前分时路径分类，输出每类具体买法、取消条件、样本数、收益、回撤、胜率和逐笔证据。
- [x] R6: 主要比较使用同一退出价；同时报告买入日收盘、下一交易日开盘与下一交易日尾盘观察值，不能通过为不同方式选择不同卖点制造优势。
- [x] R7: 同时输出标准化 1x 收益、费用前后结果、2 万元账户一手可成交性、每笔 MFE/MAE、未参与与错过上涨；费用假设必须显式且可通过参数调整。
- [x] R8: 报告必须分开呈现 14 笔全样本和 12 笔统一字段样本，并明确样本少、报告冻结时间不可证明、板块分钟同步事实缺失等限制。
- [x] R9: 本任务只产出独立研究脚本、冻结事实、测试和研究报告，不改变日报候选、最终对象、仓位、B1/B2、退出动作或 Wiki 正式规则。
- [x] R10: 将连续两日持有和不同对象重叠的收益放回同一账户逐日记账；1x按50%资金、总暴露不超过2x/100%，入场日按实际买点到收盘、退出日按前收盘到尾盘退出价计算，并逐笔扣费。
- [x] R11: 冻结同源上证指数日线与目标日期一分钟事实，输出逐日账户收益、同持有时段上证收益、逐日超额和累计净值；原独立样本复合只保留为逐笔旁证，不再称为账户累计收益。

## Non-functional Requirements

### 可复现性

- 所有 Python 命令使用 `.generated/venv-py314/bin/python3.14`。
- 分析默认只读冻结事实，联网采集必须通过显式 `--collect` 执行。
- 同一冻结输入重复运行应生成字节稳定的 JSON 和 Markdown 主体；生成时间不得进入计算哈希。

### 数据诚实性

- 集合竞价成交价只能标记为“开盘价代理”，不能写成真实个人撮合成交。
- 缺少板块同步、真实盘口排队、停牌或涨跌停可成交事实时必须单独列出，不得默认为已满足。
- 任何缺失日、缺失分钟、日线交叉检查失败或未来信息混入，都必须使对应样本停止进入汇总。

### 兼容性

- 不依赖数据库写入，不读取或输出密钥。
- 不改变项目现有依赖与环境配置。
