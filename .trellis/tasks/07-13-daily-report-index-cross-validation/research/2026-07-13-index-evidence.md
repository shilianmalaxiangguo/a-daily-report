# Research: 2026-07-13 指数日期错位证据

## Question

`2026-07-13` 日报中的上证 `3996.16 / -1.00%` 是否属于目标日；六个报告指数的真实目标日数值是什么；错误从哪一层进入日报。

## Sources

- Tushare `index_daily`，查询 `20260701` 至 `20260713` 的六个指数原始行。
- 腾讯 `fqkline` 日 K，查询 `2026-07-10` 至 `2026-07-13` 的六个指数。
- PostgreSQL `daily_report_facts` 对 `2026-07-13` 的回读结果。
- `reports/2026-07-13_A股日报_完整版.md`。
- `scripts/market_data/tushare_service.py`。
- `scripts/input/tushare_runtime.py`。
- `scripts/domains/market_state/request.py`。

## Findings

| 指数 | 2026-07-13 收盘 | 2026-07-13 涨跌幅 | 错误日报使用日期 | 错误日报数值 |
|---|---:|---:|---|---|
| 上证指数 | 3913.7940 | -2.0612% | 2026-07-10 | 3996.1616 / -1.0015% |
| 深证成指 | 14522.8547 | -3.4813% | 2026-07-10 | 15046.6695 / -2.2863% |
| 创业板指 | 3723.5166 | -3.1023% | 2026-07-10 | 3842.7314 / -4.3662% |
| 中证全指 | 6001.6528 | -3.4345% | 2026-07-13 | 6001.6528 / -3.4345% |
| 中证500 | 8138.1443 | -4.3018% | 2026-07-10 | 8503.9705 / -1.7199% |
| 中证1000 | 7787.8529 | -5.0066% | 2026-07-10 | 8198.3078 / -1.2261% |

- Tushare 与腾讯六项方向和数值一致；腾讯日 K 因小数位较少存在不超过约 `0.005` 点的舍入差异。
- PostgreSQL 明确保留了五个 `trade_date=2026-07-10` 的错误指数载荷，中证全指为 `2026-07-13`。
- `_latest_index_payload()` 对窗口 K 线排序后无条件取最后一根；没有比较目标日期。
- 市场请求层只检查字典非空或点位大于零，因而把日期错位载荷标记为成功。
- 当前生成前检查不包含主要指数和中证500，也不验证任何指数的 `trade_date`。
- 错误上证涨跌幅被整份日报多个段落复用，证明问题发生在上游事实而不是单个渲染表格。

## Recommendation

以目标日期严格匹配作为第一条件，再用腾讯日 K 对六指数的日期、收盘和涨跌幅逐项核对。核对结果持久化，并在报告生成前重新确认当前载荷与核对证据一致。任一项失败时停止生成，不静默切换来源。

## Impact

- PRD: 六个报告指数全部纳入，不只修上证单项。
- Design: 核对事实需要跨采集、持久化回读和生成前检查。
- Implementation: 先修目标日选择，再接双源核对，最后重采并覆盖当前日期错误事实。
