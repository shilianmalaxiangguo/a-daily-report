# Design: 盘前买卖决定固定，盘中只执行或取消

## Scope And Boundaries

本任务只收紧日报的明日动作契约和可见表达：

- 明日买入决定：当晚已经确定为不买、50%条件执行、100%核心进攻之一。
- 明日卖出决定：当晚已经确定为持有、减仓、退出或等待修复之一。
- 盘中条件：只判断原计划是否仍可执行；不满足则取消、降风险或继续观察。
- 观察对象：只用于盘中观察、收盘复盘和下一份日报，不产生同日新买入决定。

不改动候选池打分、市场数据采集、成交模拟和券商执行。

## Contracts / Data Flow

日报动作链路按以下含义统一：

```text
T0 收盘事实
  -> 日报最终动作
  -> T+1 盘前已知计划
  -> T+1 盘中执行资格检查
  -> T+1 收盘复盘
  -> 下一份日报重新决定
```

### Final Action Contract

- `position_pct == 0`：明日买入决定是不买新仓。任何股票只能作为观察、过程证据或旧持仓处理。
- `position_pct in {50, 100}`：明日买入决定已经成立，必须有对象、仓位、执行窗口和取消条件。
- 执行窗口和确认条件不是“再决定买”的入口，只是检查原计划是否仍有执行资格。
- 取消条件命中后，结果是取消执行或回到 `0%不参与`，不是改买观察对象。

### Wording Contract

旧口径要替换为交易动作口径：

| 旧表达 | 新表达 |
|---|---|
| `条件成立才评估50%条件执行` | `已决定50%条件执行；盘中不满足取消，回到0%不参与` |
| `盘前0%；参与窗口命中后才评估50%条件执行` | `明日买入决定：不买新仓；观察对象只复盘，不参与` |
| `固定交易窗口条件成立才参与` | `只按昨晚预案检查执行资格；不满足取消` |
| `观察对象重新成立` | `观察对象只进入复盘和下一份日报判断` |

### Audit Contract

验收审计要拦截：

- 0% 结果下出现任何“观察对象盘中满足后再参与 / 再评估 50%”。
- 正仓位结果下把执行窗口写成“明天满足条件才决定买”。
- 观察对象被写成同日新增买入对象。

审计允许：

- `已决定50%条件执行；盘中不满足取消，回到0%不参与`
- `明日买入决定：不买新仓；观察对象只复盘，不参与`
- `盘中条件只用于取消、降风险或确认按原计划执行`

## Compatibility / Migration

- 保留 `50%条件执行` 这个仓位标签，因为它是现有报告语言的一部分；改变的是解释：它表示当晚已经决定的有条件执行计划。
- 保留观察对象和过程表，但所有过程表在 0% 结果下必须保持观察 / 复盘语义。
- 旧测试中期待“条件成立才评估50%条件执行”的断言需要同步改为新语义。

## Tradeoffs

- 不新增新的复杂动作枚举，避免一次性改动过大；先用文案契约和验收审计保护最关键的用户可见结果。
- 正仓位仍允许“条件执行”，因为真实交易需要执行资格检查；但检查失败只能取消，不能临盘创造买入决定。
- 观察对象表现再强也不在同日升级，这会牺牲部分临盘机会，但符合用户要求的纪律和可复盘性。

## Rollback / Roll-forward

- 回滚方式：恢复本任务改动的渲染文案、审计常量和测试。
- 前滚方式：如果发现还有生成入口输出旧口径，先补验收审计样例，再按相同契约替换该入口。
