# 日报新仓旧仓动作与空仓语义收口

状态：✅ 功能、2026-07-16 正式产物、Bear HTML 与提交前审计已完成；工作区保留未提交，等待用户决定提交范围

## Goal

让日报把“明日不新增参与”“已有旧仓如何处理”“何时要求账户归零”分别写清，避免把新仓 0% 误写成账户已经空仓，也避免市场偏弱时机械提前卖掉仍有独立强势的旧仓。显式 `明日空仓` 是独立的账户归零指令：它要求次日不买新股、集合竞价卖清全部可卖旧仓、成交后账户仓位为 0 且不做 T；未卖清时继续尽早卖，不能提前声称已经空仓。

## User Story

- **角色**：使用固定交易窗口、希望减少盘中盯盘的 A 股短线交易者。
- **场景**：日报给出明日新仓 0%，但模拟账户可能有前日报明日标自动形成的 1x 旧仓、明确外部待核实记录，或持仓事实尚未输入。
- **目标**：在开盘前知道是否不买、是否在上午退出旧仓、是否只做一次 10:10 复核，以及收盘前账户应保留多少仓位。
- **成功标准**：用户不需要从“空仓”一词猜测买卖含义；日报、持仓策略、HTML 和验收检查对同一账户事实给出一致动作。

### 用户旅程

1. 日报先给出明日新仓比例，不用它反推已有持仓。
2. 系统核对旧仓事实，区分显式真实旧仓、前日报明日标自动形成的模拟 1x 旧仓、明确外部待核实记录、明确无旧仓和持仓未输入。
3. 对已确认旧仓，区分已经失败、待 10:10 复核和正常存活三类。
4. 已失败旧仓在 `09:50-10:10` 完成退出；待复核旧仓只在该窗口检查一次，三层承接成立才保留到 `14:30-14:55`；正常 T+2 样本按尾盘预案退出。
5. 报告写明收盘目标仓位；窗口外不生成临时动作。
6. 只有报告显式给出 `明日空仓` 时，旧仓延后处理路径才被账户归零指令覆盖，改为次日集合竞价卖清；`明日新仓 0%`、`明日标的为空` 和持仓未知都不得触发这条覆盖规则。

## What I Already Know

- 当前候选与仓位结论中的 `0%不参与`主要表达不新增参与，不能证明账户已有持仓为零。
- 当前日报可能同时写“持仓未输入”和“账户风险暴露 0x”，这是不可同时成立的账户事实。
- 现有 `.trellis/spec/backend/daily-report-decision-loop.md` 已定义 `old_position_plan.v1`，但代码尚未形成统一的结构化旧仓动作产物。
- 现有正式买卖窗口仍是 `09:30-09:35`、`09:50-10:10`、`14:30-14:55`。
- `13:45-14:10` 只作日终与 replay 研究，不新增人工查看或临时卖出。
- 2026-07-13 长电科技说明“市场差就开盘立即卖”不成立，也说明板块与指数同步恶化可以使旧仓从独立强势转为退出样本。
- 用户还经历过早盘退出后旧仓尾盘创日内高点甚至涨停的反例；该反例要求保留“10:10 三层承接成立则允许尾盘处理”的成功路径，不能用单一案例把所有旧仓改成上午清仓。

## Requirements

- [x] R1: 日报账户动作必须分开输出明日新仓比例、旧仓事实、旧仓判断、旧仓动作和收盘目标仓位，不得用 `明日新仓 0%` 或 `明日标的为空` 代替账户空仓；显式 `明日空仓` 必须展开成完整账户归零动作。
- [x] R2: 复用并落实 `old_position_plan.v1`；显式持仓与前日报明日标在次交易日自动形成的模拟 1x 旧仓都进入 `已经失败`、`待10:10复核`、`正常存活` 判断。只有 `external_trade_pending` 等明确外部待核实记录保持实际 0x，不能进入旧仓动作。
- [x] R3: 已经失败的旧仓使用 `09:50-10:10` 作为最后退出窗口；待复核旧仓在同一窗口核对个股相对昨收/分时均价、相对指数强弱和板块核心同步承接，条件成立才允许继续到 `14:30-14:55`，否则在 10:10 前退出。
- [x] R4: 正常 T+2 样本仍按 `14:30-14:55` 退出；没有明确 T+2 或旧仓生命周期事实时，不伪造 T+2 身份或精确退出结论。
- [x] R5: 持仓未知时，账户风险暴露和收盘目标仓位必须写待确认；上一份日报明日标在次交易日默认必买完成，直接成为真实 100% / 1x 模拟旧仓，无需额外成交确认。某日报没有新明日标只表示不新增，不自动清除最近未结束的旧仓；只有明确当前空仓、已执行明日空仓或退出事实才结束继承。
- [x] R6: 日报首页、明日执行结论、账户日序表、持仓策略和 Bear HTML 必须使用同一账户动作含义；最终新仓 0% 可以与正常存活旧仓并存，不视为结论冲突。
- [x] R7: LLM Wiki 必须记录新仓与旧仓分离、三类旧仓动作、10:10 三层复核、尾盘例外和事后涨停不能反推当时动作对错。
- [x] R8: 验收检查必须拒绝“持仓未输入但风险暴露为 0x”“已确认旧仓但只写不新增参与”“待成交计划被写成旧仓卖出”“上午清仓却没有 10:10 前动作”等矛盾。
- [x] R9: 候选生成、`selection_workflow` 最终对象、评分、B1/B2、明日新仓仓位计算和一分钟市场语言研究结论不得因本任务改变。
- [x] R10: LLM Wiki 正文、静态模型上下文和知识路由必须使用同一优先规则：显式 `明日空仓` 要求次日集合竞价卖清全部可卖旧仓、不买新股、不做 T，成交后账户仓位为 0；未卖清时继续尽早卖且不能称空仓。该规则不得由 `明日新仓 0%`、`明日标的为空`、当前空仓事实或持仓未知自动触发。

## Non-functional Requirements

### 兼容性

- 显式结构化持仓事实优先；模拟账户中的前日报明日标在次交易日统一归一为已持有 100% / 1x。明确 `external_trade_pending` 仍按待核实、实际 0x；模糊文案保持事实不足，不得冒充任一确定类别。
- Markdown 与 Bear HTML 保持相同顺序和含义，窄屏展示不得横向溢出。

### 可追溯性

- 旧仓动作必须保留证据来源；没有分钟、板块或指数事实时不得声称三层复核已经通过。
- 所有 Python 命令使用 `.generated/venv-py314/bin/python3.14`。
