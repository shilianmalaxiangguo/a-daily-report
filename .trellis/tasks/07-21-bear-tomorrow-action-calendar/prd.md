# Bear 最近25条明日操作日历

状态：✅ 功能、正式 Bear HTML、真实数据库复核与提交前审计已完成；工作区保留未提交，等待用户决定提交范围

## Goal

在每日 Bear HTML 的账户甘特图上方增加最近 25 条明日操作日历，让用户按实际执行日直接看到当日是空仓、不新增还是持有哪个标的，以及按每笔 `1x/50%`、连续两个交易日计算的账户当日涨幅和跑赢上证幅度；所有历史事实以 PostgreSQL 为主来源，展示不得反向改变日报决策。

## User Story

- **角色**：每天用 Bear HTML 复核日报计划与后续表现的 A 股交易者。
- **场景**：用户需要快速回看最近 25 份日报给下一交易日安排了什么，并判断这些安排当天相对上证的表现。
- **目标**：在甘特图前按交易周扫描日期、星期、操作、当日涨幅和跑赢上证，不再逐份打开历史日报核对。
- **成功标准**：日报日与执行日不会错位，跨周末和法定休市日正确；数据库事实不足时明确留缺，不从 HTML 或 Markdown 猜测。

### 用户旅程

1. 用户打开 Bear HTML，先看到最近 25 条明日操作日历，再看到原账户甘特图。
2. 用户按实际执行日查看每格的日期、星期、空仓/不新增/持仓腿、每腿仓位与第几日、账户当日涨幅和跑赢上证。
3. 用户在日历底部区分明日标的计划日和账户实际持仓日，并查看平均当日涨幅、平均跑赢上证、累计账户收益、累计上证收益、累计跑赢上证和跑赢天数占比。
4. 对未来执行日或事实不足记录，用户看到明确状态，该记录不进入收益汇总。

## What I Already Know

- 真实数据库中 `strategy_performance_ledger` 当前为空；最近 25 日最终明日决定存于 `strategy_factor_snapshots` / `strategy_factor_snapshot_fields`，以 `(mode, report_date, field_path)` 唯一。日历优先读取最终对象、仓位立场、股票代码/名称和明确账户归零动作，旧策略账本只作无快照历史时的兼容读取。
- 个股目标交易日开盘价和收盘价存于 `stock_daily_quotes_recent.open/close`；本日历按同日开收到收计算，不使用 `pct_chg` 的昨收到今收口径。
- 上证历史日线存于 `index_daily_bars`；基准也按同日 `open/close` 计算，保证与账户日收益比较口径一致。
- PostgreSQL 当前没有独立交易日日历表；项目已有上证交易日线与 TuShare `trade_cal` 开市日能力。
- `明日空仓`、`明日新仓 0%` 和无明日标的不是同一层含义：账户结果按执行日活跃腿判断；当日没有任何活跃腿就显示 `空仓`。计划层仍保留 `不新增`，因此“空仓 + 不新增计划”可以同时出现；若上一份标的仍有第 2 日腿，则显示持仓标的并注明 `本日计划：不新增`。
- 用户所称的 Bear 甘特图是顶部 `.position-timeline-shell` 账户日序时间轴，并非附录 Mermaid 流程图；日历必须位于该时间轴前，并保持原 Markdown 内容与顺序不变。

## Requirements

- [x] R1: Bear HTML 在顶部账户日序时间轴上方渲染最近 25 条数据库明日操作记录；按执行日从旧到新展示，记录不足 25 条时如实显示实际条数。
- [x] R2: 每条记录优先从 PostgreSQL `strategy_factor_snapshot_fields` 的最终明日决定读取报告日、标的代码/名称、仓位立场和账户结果；无快照历史时才兼容读取 `strategy_performance_ledger`，不以 Bear HTML、Markdown 或 JSON 快照作为历史主来源。
- [x] R3: 报告日决定归属于下一实际交易日；日期映射必须跳过周末和法定休市日。历史映射优先使用 PostgreSQL 已有上证日线中的下一日期；仍无法确定时显示事实不足，不用下一自然日猜测。
- [x] R4: 每份具体明日标的从下一实际交易日起连续参与两个交易日，每腿为 `1x/50%`；同一执行日最多两腿。账户当日涨幅为 `Σ 0.5 × ((个股收盘 / 个股开盘) - 1) × 100`，上证当日涨幅为 `((上证收盘 / 上证开盘) - 1) × 100`，跑赢上证为两者之差。明确空仓日账户涨幅为 `0.00%`。
- [x] R5: 账户结果与明日计划分层：执行日没有任何活跃持仓腿时显示 `空仓`；当日计划仍可为 `不新增`。若上一份具体标的仍有第二日 `1x/50%` 持仓，则显示该标的并注明 `本日计划：不新增`；明确 `明日空仓` 同样清除当日全部持仓腿。
- [x] R6: 未来执行日显示 `待发生`；任一活跃腿或上证的目标日开收事实缺失、非有限或冲突时显示 `事实不足`。未来和缺失记录均不进入收益汇总，不得按 `0` 计入。
- [x] R7: 日历底部汇总有效天数、明日标的计划日、账户持仓日、空仓日、不新增日、平均当日涨幅、平均跑赢上证、累计账户收益、累计上证收益、累计跑赢上证、跑赢天数/有效天数和事实不足数。累计账户与累计上证只使用同一组完整有效日分别逐日复利，再相减得到累计跑赢上证。
- [x] R8: 日历使用 5 列交易周布局；单元格稳定显示全部字段，桌面可快速横向扫描，窄屏只允许日历自身横向滚动，页面不得横向溢出。
- [x] R9: 日历仅为历史展示，不修改 `selection_workflow`、`final_target_resolution`、明日执行对象、仓位、执行性质、B1/B2 或退出动作。
- [x] R10: 正式 HTML 和 replay HTML 都能消费同一结构化日历载荷；`mode` 必须明确，禁止把 replay 与正式记录混为一组。

## Non-functional Requirements

### 数据可信度

- 数据库行存在与数值为 `0` 必须分开；没有目标日行情行时属于事实不足。
- 个股与上证涨幅只在目标日开盘价、收盘价均有效且同日重复事实不冲突时计算；交易日存在与收益事实完整必须分开判断。
- 最近 25 条应公开实际样本数和执行日期范围，不把短样本包装成完整 25 条。

### 兼容性

- 保持现有 Bear HTML、账户日序时间轴、附录 Mermaid 流程图和 Markdown 原文不变。
- 没有数据库服务或没有历史记录时，HTML 仍可生成，但日历显示数据库事实不足，不扫描历史 Markdown 回补。
- 所有 Python 命令使用 `.generated/venv-py314/bin/python3.14`。

### 可访问性与响应式

- 日历使用语义化表格或等价可访问结构，含明确标题和汇总标签。
- 正负收益不只依赖颜色，还保留 `+/-` 符号与文字。
- 桌面与 390px 窄屏均无文字重叠或页面级横向滚动。

## Acceptance Criteria

- [x] AC-R1-1: 给定数据库有 30 条截止报告日的记录，当生成 Bear HTML 时，只展示按报告日选出的最近 25 条，并按执行日从旧到新排列在 `.position-timeline-shell` 之前。
- [x] AC-R1-2: 给定数据库只有 8 条记录，日历显示 8 条及真实日期范围，不补造 17 条。
- [x] AC-R2-1: 给定历史 Markdown 与 PostgreSQL 标的不一致，日历使用 PostgreSQL 标的。
- [x] AC-R2-2: 给定 PostgreSQL 无记录，日历显示数据库事实不足，且测试证明未调用 Markdown/JSON 历史回退。
- [x] AC-R3-1: 给定周五报告日，下一条上证日线为周一，操作归属周一单元格。
- [x] AC-R3-2: 给定法定休市前报告日，操作归属数据库中下一条上证交易日线，而不是下一自然日。
- [x] AC-R4-1: 给定同日两腿，甲第 2 日开收 `101→103`、乙第 1 日开收 `200→204`，账户当日涨幅为 `0.5×1.98% + 0.5×2.00% = +1.99%`；若上证开收跌 `-1.00%`，单元格显示跑赢上证 `+2.99%`。
- [x] AC-R4-2: 给定同股连续两份计划重叠，单元格合并显示该股 `2x/100% · 第1+2日`，收益仍按两条 `0.5` 权重腿相加。
- [x] AC-R4-3: 给定明确空仓且上证开收到收跌 `-1.20%`，单元格显示当日涨幅 `0.00%`、跑赢上证 `+1.20%`。
- [x] AC-R5-1: 给定无明日标的但没有明确账户归零事实，上一份标的仍在第二日时，单元格显示该标的 `1x/50% · 第2日` 及 `本日计划：不新增`，不显示 `空仓`。
- [x] AC-R5-2: 给定明确明日账户归零事实，或当日没有任何活跃持仓腿，单元格显示 `空仓`；其计划字段仍可显示 `不新增`，但不应把账户结果写成 `不新增`。
- [x] AC-R5-3: 给定日历周内的已知法定休市日，显示日期、星期和节日名称（例如 `2026-06-19 端午休假`），不占用报告记录数、不进入收益汇总；样本范围外工作日显示 `样本外`，不留无解释空格。
- [x] AC-R6-1: 给定执行日在报告日之后，单元格显示 `待发生`，不进入有效天数。
- [x] AC-R6-2: 给定标的或上证行情缺失，单元格显示 `事实不足`，汇总事实不足数增加且均值分母不变。
- [x] AC-R7-1: 给定两个有效日的账户收益均为 `+1%`、上证收益依次为 `+1%/-1%`，汇总显示累计账户收益 `+2.01%`、累计上证收益 `-0.01%`、累计跑赢上证 `+2.02%`；不得把每日超额百分点直接求和代替复利比较。
- [x] AC-R8-1: 1440px 与 390px 预览中，日历位于账户日序时间轴上方，文字不重叠，页面 `scrollWidth == clientWidth`，窄屏滚动限制在日历容器内。
- [x] AC-R9-1: 接入前后 `selection_workflow`、`final_target_resolution`、明日执行对象、仓位、执行性质、B1/B2 和退出动作逐字段一致。
- [x] AC-R10-1: 正式模式只读取正式台账，replay 模式只读取 replay 台账；两者缺失时分别显示自身事实不足。
