# Design: 板块先行选股淘汰赛HTML与日报同步生成

## Scope And Boundaries

This task adds a companion elimination-bracket artifact to the daily report flow. The report remains governed by `final_target_resolution`; the new artifact explains the decision path and does not create new execution targets.

The core boundary is:

- One final source of truth for the user-facing current action.
- Many candidates may appear as process evidence, eliminated candidates, or sector references.
- Only the final layer may render the final action.

The implementation should reuse existing structured artifacts where possible:

- `selection_workflow` nodes and candidate lifecycle evidence.
- `candidate-traces` style per-candidate paths.
- `decision-ledger` risk and planned participation fields.
- `final_target_resolution` for the final displayed target/action.

## Contracts / Data Flow

The intended data flow:

1. Report runtime builds the existing report context and `final_target_resolution`.
2. A structured elimination payload is built from existing workflow/candidate/ledger context.
3. The payload is rendered into a static HTML companion.
4. The report generation step writes the HTML beside the dated report artifact.
5. The acceptance audit can verify that the Markdown report and companion HTML agree on the final object/action.

Suggested payload shape:

```python
{
    "trade_date": "2026-06-12",
    "variant": "replay",
    "final_action": {
        "label": "0%不参与",
        "target": {},
        "source": "final_target_resolution",
    },
    "layers": [
        {
            "id": "sector",
            "title": "板块层",
            "input_count": 46,
            "eliminated_count": 43,
            "survivor_count": 3,
            "entries": [
                {
                    "stock_code": "002971",
                    "stock_name": "和远气体",
                    "sector": "化工原料",
                    "status": "survived",
                    "reason": "化工原料板块锚进入下一层",
                    "next_basis": "进入板块内角色层",
                }
            ],
        }
    ],
}
```

Layer status vocabulary should stay user-facing and trading-oriented:

- `survived`
- `eliminated`
- `final_action`
- `process_only`
- `sector_reference`

Avoid user-visible implementation language prohibited by `AGENTS.md`.

## Compatibility / Migration

- Existing report generation outputs remain valid.
- New HTML output is additive.
- For missing structured data, renderer should emit an explicit “数据不足，无法展示本层淘汰细节” row rather than invent reasons.
- Replay generation should write to `reports/replay/`.
- Official generation should write beside the official report path only when that path is being generated by the normal report command.

## Tradeoffs

Using existing evidence may initially produce imperfect layer attribution for older dates. That is acceptable if the artifact is honest about missing layer detail. The priority is to prevent hidden multi-target drift and make future optimization possible.

The HTML should be clear and dense rather than decorative. It is an audit artifact for decision quality.

## Rollback / Roll-forward

Rollback:

- Disable the generation hook or remove the companion renderer call.
- Existing Markdown report generation should remain unaffected.

Roll-forward:

- Extend layer detail once upstream evidence becomes richer.
- Add historical comparison metrics later, outside this task.
