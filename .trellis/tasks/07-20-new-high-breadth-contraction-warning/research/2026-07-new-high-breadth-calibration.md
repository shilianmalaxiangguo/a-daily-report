# Research: 2026-07 创新高扩散与核心补跌

## Question

如何把 7 月创新高个位数样本转成日报可重复的结构证据，同时避免把不同数据源或多次运行的差异写成单一确定序列。

## Sources

- `scripts/domains/market_activity/new_high_runtime.py:143-312` — 快照字段、板块分布和近25行趋势行生成。
- `scripts/report/market_overview_nodes.py:831-856,1290-1346` — 当前热度分档和 Markdown 唯一渲染入口。
- `.generated/report-quality/2026-07-15_default.json` — 可见 25 日趋势行中的 7/13 `6 / 0.12%` 和相邻行。
- `snapshots/2026-07-17.json:17751-18120` — 冻结快照中的目标日创新高字段和历史行。
- `wiki/交易思想/创新高扩散、核心独强与补跌.md` — 已沉淀的交易判断、反证和日报边界。

## Findings

- 创新高数量和全 A 占比是结构证据，不是买卖指令。
- `2026-07-13` 的 `6 / 0.12%` 在可见近25交易日窗口内是首次个位数；6 只分属 6 个板块，没有形成新板块集群。
- 现有日志里 7/1、7/10、7/15、7/16、7/17 存在 Akshare/Tushare 混用、不同运行结果或分母差异；只能确认部分目标日事实，不应直接凭日志拼出唯一序列。
- 当前分析的可复用结构是：宽度生成率收缩 -> 后排掉队 -> 资金向核心集中 -> 核心补跌 -> 指数确认。这条路径是风险候选，不是必然时序。
- 日报只需将可计算字段和反证写出；无需把华天科技、半导体和上证的价格联动硬编入新高数据源。

## Recommendation

新增一个纯函数结构投影，仅消费现有 `new_high_feedback` 快照；由 Markdown 统一呈现，Bear HTML 沿用最终 Markdown。LLM Wiki 路由只记录说明证据，其实事条件用现有 `market.breadth` 路径，不新增未登记的路径。

## Impact

- PRD：增加结构字段、反证、数据不足和 Bear 一致性验收。
- Design：共享结构函数，报告渲染和 Wiki 事实路由均只读。
- Implementation：先补单测和反例，再接入报告文字和知识路由；回放只做结果对比，不覆盖正式历史报告。

## 1.2 绝对水位校准

### 旧口径问题

- ECharts 写成 `5%及以上极致 / 2%冰点 / 1%以下极冰`，Markdown 写成 `<2%偏冷 / 2%-5%震荡 / >5%偏热`，恰好 `5%` 时结论不一致。
- `<2%` 合并过宽，无法区分 `1%-2%` 的普通偏冷、`0.2%-1%` 的异常低位和 `<0.2%` 或个位数的断层。
- 只看当天绝对水位，会把 `2.3% -> 0.8%` 的收缩与 `0.4% -> 0.8%` 的修复混为一谈。

### 1.2 结论

| 范围 | 绝对水位 |
|------|----------|
| `>=5%` | 极致扩散 |
| `>=2%且<5%` | 有效扩散 |
| `>=1%且<2%` | 扩散偏冷 |
| `>=0.2%且<1%` | 极低扩散 |
| `<0.2%` 或新高数 `<10只` | 扩散断层 |

最终解释使用：`绝对水位 × 变化方向 × 板块成群度 × 核心板块同步性 × 来源质量`。这些阈值是经验分层，不是买卖动作；后续用更长同源历史校验基准率、误报率和持续时间。
