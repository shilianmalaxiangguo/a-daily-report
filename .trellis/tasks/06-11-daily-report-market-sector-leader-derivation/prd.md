# 日报市场板块龙头推导重构

状态：✅ 已完成

## Goal

重构日报选股推导口径，让最终对象从“市场氛围 -> 板块动向 -> 板块发酵 -> 板块情绪 -> 市场选出龙头 -> 价格行为确认 -> 账户执行资格”逐层推出，而不是从涨停、T字板、一字板或单只强势个股开始，再回头寻找热点板块理由。

## User Story

- **角色**：使用日报做次日计划和盘中问股继承的交易者。
- **场景**：市场出现题材发酵、板块轮动、高标活跃或热点龙头争夺时。
- **目标**：看懂资金先选择了哪个板块，板块如何发酵，谁被市场选成龙头，以及为什么当前能参与或只能观察。
- **成功标准**：日报能稳定回答“为什么是这个板块、为什么是这个龙头、为什么不是其他涨停或T字板、价格和量能是否支持、最终仓位为什么是0%/50%/100%”。

### 用户旅程

1. 用户打开日报 -> 系统先展示市场情绪和赚钱效应，而不是先展示个股强度。
2. 用户查看主线推导 -> 系统说明资金正在选择哪些板块，哪些只是噪音或轮动脉冲。
3. 用户查看板块推导 -> 系统说明板块是否发酵、是否有成交扩散、后排承接和二次确认。
4. 用户查看龙头推导 -> 系统说明龙头是如何被市场选出，以及它相对中军、弹性载体、后排和旧龙头的关系。
5. 用户查看执行计划 -> 系统用布鲁克斯价格行为和 A股量价本地化确认是否具备买入资格，并输出0%/50%/100%。

## What I Already Know

- 当前 `scripts/report/selection_workflow.py` 已有 `selection_workflow.v1`，节点名从 N0 到 N9 已存在。
- 当前 N1-N4 多数仍在传递 `market_state`、`mainline` 和是否存在板块快照，尚未把市场氛围、板块发酵、板块情绪和龙头形成过程落成稳定字段。
- 当前 N7 已有 Brooks 价格行为判断，并且测试已覆盖“成交量不能单独生成买入资格”。
- 当前测试已约束：只有涨停但缺少反推证据不能成为最终对象；显式候选不在候选池时不能绕过链路；仓位只允许0%、50%、100%。
- `wiki/板块补充/板块中枢与主线延续.md` 已记录“板块先铺再筛核心”：当前阶段更常见的是资金先铺出板块效应，再筛成交容量、辨识度和承接最好的核心样本。
- `wiki/交易思想/布鲁克斯价格行为趋势.md` 已记录：成交量是资金表态，价格接受才可能形成买入资格；龙头身份只提高排序，不直接给买入资格。
- 本任务需要用分形思想重排推导：市场是更大级别，板块是中间级别，龙头是更小级别表达；下一级必须证明它承接了上一级资金选择。

## Product Decisions

- [x] D1: 严格从板块推导个股。涨停、连板、T字板、一字板不作为新仓候选入口；只有板块已经推导出个股后，这些形态才作为可交易性、分歧日、风险或价格行为证据解释。
- [x] D2: 本任务全面落地，范围包括结构化推导、Mermaid、日报正文、首页一致性和 Bear 版 HTML，不只做内部字段。
- [x] D3: 持仓和用户手动问股对象允许进入风险处理/观察链路，但不得绕过板块推导获得新仓买入资格；若想变成新仓候选，仍必须回到市场、板块、龙头和价格行为确认。
- [x] D4: 市场总龙、高标抱团、情绪龙头不能再作为独立个股入口。特殊行情必须先证明“情绪抱团资金方向”已经形成，至少包含多个资金载体、成交容量、大众可参与性、分歧承接和竞争方向对照，再从这个方向推导个股。
- [x] D5: 普通行业板块与特殊情绪抱团不再各自维护候选线。二者先在资金方向层完成对照，胜出的方向或未分胜负的方向对照再进入同一个候选台账；未分胜负时不得给100%。
- [x] D6: 关键市场、板块发酵、市场情绪线、价格行为或账户执行数据缺失时，日报生成必须停止，并明确提示优先修复缺失数据；不得用涨停、连板、T字板、一字板、热榜或历史记忆回退生成新仓结论。
- [x] D8: `selection_workflow.candidate_pool` 是整份日报唯一候选台账。旧 `extreme_conviction_list`、`crossline_observation_stocks`、`watchlist`、`core_stocks`、`secondary_stocks`、Step2/Step3 和狙击手名单只能作为台账行的来源证据，不得在任何消费层重新创建候选。
- [x] D9: `selection_workflow.final` 是整份日报唯一最终对象。首页、狙击手、两层决策、淘汰赛、候选质量、附录、Markdown 和 Bear HTML 只能投影该结果，不能从旧名单或来源顺序回退出另一个对象。
- [x] D10: `final_target_resolution` 只解释账户动作。它可以说明新仓动作、旧仓处理、代理与仓位约束，但对象和新仓仓位必须逐字段等于 `selection_workflow.final`；不得生成独立 `watch_target`、`process_target`，也不得反向改写候选或当前核心。
- [x] D11: 持仓风险对象和手动问股对象仍可进入 `candidate_pool`，但必须标记为 `holding_risk` 或 `manual_observation`，默认只作过程证据；只有重新取得已证明资金方向的归属和完整价格确认后，才能成为新仓候选。

## Requirements

- [x] R1: 日报推导必须先输出市场层结论，字段至少包含市场氛围、赚钱效应、成交量质量、风险偏好、是否允许继续向板块诊断。
- [x] R2: 日报推导必须输出板块层结论，字段至少包含资金选择方向、板块动向、板块发酵、板块情绪、板块成交扩散、后排承接和竞争线状态。
- [x] R3: 日报推导必须输出“市场选龙头”结论，证明龙头来自板块发酵和资金反复选择，而不是来自单只涨停、T字板、一字板或孤立强势。
- [x] R4: 日报必须严格降权涨停、连板、T字板、一字板、热榜、旧龙头记忆、题材标签、单日放量；这些只能在板块已经推出个股后作为解释证据，不能作为新仓候选入口或买入资格来源。
- [x] R5: A股量能必须前置用于识别资金表态和板块发酵，但最终参与必须由价格接受确认，至少包含收盘质量、突破回踩、后续行情、二次确认或失败条件。
- [x] R6: Brooks 价格行为确认必须覆盖趋势/交易区间谱系、K线收盘质量、突破失败测试、二次入场、迟到入场风险和交易者等式。
- [x] R7: 最终输出必须继续保持单一最终对象或无最终对象，仓位表达只允许0%、50%、100%，所有章节消费同一个推导结果。
- [x] R8: Mermaid、候选流水账、日报正文、首页和 Bear 版 HTML 必须展示从市场到板块、从板块到龙头、从龙头到价格行为确认、再到账户执行资格的完整路径。
- [x] R9: 新增或更新测试必须覆盖至少一个旧错误样本和一个应保留样本，防止把新框架变成“所有条件都叠满”的巨型筛选器。
- [x] R10: 推导链必须区分新仓候选、持仓风险处理对象和手动问股观察对象；后两者可以进入风险/观察链路，但不能自动进入新仓候选池。
- [x] R11: 推导链必须支持“市场情绪线”，用于普跌抱团、市场总龙、高辨识度情绪龙头等非普通行业板块路径；该线路仍必须由市场氛围推导，而不是由个股涨停形态推导。
- [x] R12: 当市场情绪线和板块主线指向不同对象时，系统必须按市场环境给出优先级、冲突解释和最终动作，不能同时输出多个新仓对象。
- [x] R13: 任何参与市场、板块、市场情绪线、龙头、价格行为或账户执行判断的关键数据缺失、采集失败或载荷为空时，日报生成必须停止，并提示用户优先修复数据缺失问题；不能输出半份日报、观察版结论或用旧候选来源替代。
- [x] R14: `selection_workflow.candidate_pool` 必须登记所有当前候选、过程对象及淘汰理由；任何旧列表、Step2/Step3 或狙击手对象未登记在该台账时，不得出现在日报当前候选、观察对象或最终对象中。
- [x] R15: 新仓资格必须由已证明资金方向授予。普通板块和特殊情绪抱团都必须先形成方向证明，单只涨停、旧核心、热榜、来源顺序或显式 `selected_position_candidate` 不能直接获得新仓资格。
- [x] R16: `selection_workflow.final` 必须成为所有当前动作表面的唯一对象与仓位来源；旧字段只能作兼容输入或过程展示，不能覆盖或补齐空的最终对象。
- [x] R17: `final_target_resolution` 必须只从 `selection_workflow.final` 和账户上下文派生账户动作，不得从候选池、旧名单或前台观察对象再次选股，也不得把解析结果反向写回候选选择。
- [x] R18: 狙击手、Step2/Step3、候选质量、淘汰赛和附录在存在 `selection_workflow` 时必须只读取 `candidate_pool/final`；缺少工作流的旧兼容路径只能显示为历史或过程证据，不能形成当前新仓结论。

## Non-functional Requirements

### 性能

- 沿用现有日报生成性能约束，不新增外部实时服务调用作为必要条件。

### 安全

- 不引入新的密钥、外部账号或网络写入路径。

### 兼容性

- 所有 Python 命令、测试和日报生成必须使用 `.generated/venv-py314/bin/python3.14`。
- 保留现有0%/50%/100%仓位表达，不恢复旧多档仓位。

### 用户可见语言

- 遵守 `wiki/交易思想/日报术语契约.md`。
- 不把工程实现词搬进日报正文；用户可见输出使用交易语言表达条件、资格、参与、不参与和观察。

## Acceptance Criteria

- [x] AC-R1-1: 给定市场赚钱效应弱、上涨家数不足但指数上涨，当生成推导链时，N1 必须说明是否只是少数板块路径被资金选择，而不是把指数上涨扩展成全市场参与质量提高。
- [x] AC-R2-1: 给定某板块成交占比扩张、板块内多只股票同步放量或趋势新高、后排仍有承接，当生成推导链时，N2-N3 必须把该方向标为被资金选择的板块路径。
- [x] AC-R2-2: 给定单只个股涨停但板块无扩散、无二波创新高群、无后排承接，当生成推导链时，N3 必须保留为个股异动或轮动脉冲，不能升级为主线。
- [x] AC-R3-1: 给定一个 T字板或一字板个股属于热门板块但板块尚未被资金选择，当生成候选池时，该个股不得作为新仓候选入口；如果需要展示，只能进入噪音/风险解释或附录观察。
- [x] AC-R3-2: 给定板块先铺开、二波创新高群出现、成交容量核心横住或继续放量、弹性核心分歧后承接，当生成龙头推导时，系统必须说明龙头是市场选择结果。
- [x] AC-R4-1: 给定热榜、涨停、题材标签、历史龙头记忆中的任一单项证据，当没有板块和价格确认时，系统必须说明它不能作为候选入口或买入资格来源。
- [x] AC-R5-1: 给定放量上涨、强收盘、板块同步和回踩不破，当 Brooks 价格行为确认运行时，候选可进入最终对照，但仍需账户、时间窗口和认错线。
- [x] AC-R5-2: 给定放量冲高回落、长上影或弱收盘，当 Brooks 价格行为确认运行时，系统必须写成资金表态未被价格接受。
- [x] AC-R6-1: 给定强趋势中第一次逆势K线，当推导输出时，系统必须优先写成回调或观察，不能直接写成趋势反转。
- [x] AC-R6-2: 给定错过早期买点且价格远离失效线，当推导输出时，系统必须写成迟到入场风险，不允许补偿式追高。
- [x] AC-R7-1: 给定最终仓位小于50%的计算结果，当输出日报时，最终对象为空且仓位为0%不参与。
- [x] AC-R7-2: 给定持仓或用户手动问股对象不属于当前资金选择板块，当生成推导链时，该对象可以出现在风险处理/观察链路，但不能成为新仓买入对象。
- [x] AC-R7-3: 给定普跌或窄池子进攻环境下，市场总龙具备高辨识度、成交容量和分歧承接，当生成推导链时，系统可以把它归入市场情绪线，并继续接受价格行为确认。
- [x] AC-R7-4: 给定市场情绪线和板块主线同时强但指向不同对象，当生成推导链时，系统必须输出PK对照；若价格行为和账户条件未分胜负，最终仓位不得为100%。
- [x] AC-R7-5: 给定市场情绪线所需的成交容量、大众可参与性或分歧承接数据缺失，当生成日报时，系统必须停止生成并提示修复缺失数据，不能把该线路写成观察结论。
- [x] AC-R8-1: 给定生成的 `selection_workflow`，Mermaid 必须包含市场、资金、板块、龙头、价格行为、执行资格和最终结论节点。
- [x] AC-R8-2: 给定日报正文和 Bear 版 HTML，二者必须都能看到新版推导链，且不出现旧口径的“涨停/T字板优先候选”表达。
- [x] AC-R9-1: 运行新增测试时，旧错误样本“先选涨停/T字板再找热点板块理由”必须无法成为新仓候选入口；应保留样本“板块先铺后筛出承接核心”必须保留为可对照候选。
- [x] AC-R13-1: 给定板块发酵、板块成交扩散、后排承接、核心个股价格行为或账户执行字段任一关键数据缺失，当生成日报时，系统必须输出“关键数据不完整，停止生成”类提示，并列出缺失数据项。
- [x] AC-R13-2: 给定涨停池、热榜或历史龙头记忆仍有数据但板块推导关键数据缺失，当生成日报时，系统不得用这些旧来源回退生成新仓结论。
- [x] AC-R14-1: 给定 `selection_workflow.candidate_pool` 只有板块证明候选 A，而旧极致信念、跨线、Step2、Step3 和狙击手名单都指向 B，当生成整份日报时，当前候选和最终对象只能来自 A；B 只能作为带来源和淘汰理由的过程证据。
- [x] AC-R15-1: 给定明新旭腾只出现在涨停、T字板或狙击手旧名单，且没有通过资金方向证明，当生成 2026-07-29 replay 时，它必须在候选台账中标记为过程证据，不能成为观察对象、新仓对象或带未来价位的当前动作。
- [x] AC-R15-2: 给定特殊行情中的高辨识度个股，但没有多个资金载体、成交容量、大众可参与性和分歧承接形成的资金方向，当生成候选台账时，该个股不得获得新仓资格。
- [x] AC-R16-1: 给定 `selection_workflow.final` 为空且所有旧容器非空，首页、狙击手、两层决策、淘汰赛、候选质量、附录、Markdown 和 Bear HTML 都不得补出当前对象。
- [x] AC-R16-2: 给定 `selection_workflow.final` 为对象 A、旧容器和 `selected_position_candidate` 为对象 B，所有当前动作表面必须显示 A，且 `final_target_resolution` 的新仓对象和仓位逐字段等于工作流最终结果。
- [x] AC-R17-1: 给定账户已有旧仓 C、工作流最终新仓对象 A，`final_target_resolution` 可以同时解释 C 的处理和 A 的新仓动作，但不得把 C 或任何观察对象改写成新仓对象。

## Open Product Decisions

### D7: 上层环境对局部趋势板块的仓位上限

用户已指出，若把市场、市场趋势、趋势板块、板块生态和个股确认错误地写成“每一层都必须全面转强才能参与”，日报会过度收缩为几乎每天 `0%不参与`，这不符合既有 B1 参与权、B2 确认权与窄池子进攻口径。

已确认边界：

- 六层链是最终确认顺序，不是要求所有上层每天同步转强的全绿清单。
- 市场层与市场趋势层决定新参与的最大仓位和风险表达；它们不能被单股强势反向证明已经改善。
- 趋势板块仍须证明跨日持续、分歧承接、内部扩散和竞争方向对照；单日爆发、单只核心、热榜或涨停不足以取得新参与资格。
- 市场偏弱但局部板块先于市场修复时，只要趋势板块已证明跨日持续、分歧承接、内部扩散、竞争方向对照，且个股与该方向匹配，最多允许 `50%` 的 B1 参与权。
- 弱市中的 B1 只取得参与权，不自动取得 B2；B2 和 `100%` 仍要求市场趋势或更广泛赚钱效应进一步确认。
- 系统性风险、关键事实不足、板块持续性不足或个股与已证明方向不匹配时，保持 `0%不参与`。
- 个股强势可以作为发现线索，但不能反向证明市场、市场趋势或板块持续性已经成立。

决策结果：采用“弱市完整局部趋势最多 `50% B1`”方案，不采用“市场未全面修复一律 `0%不参与`”的替代方案。后者会系统性放弃窄池子和领先板块的早期样本，也不符合现有 B1 参与权、B2 确认权口径。

除 D7 外，本 PRD 当前按 D1-D6 与 D8-D11 执行；若实现时发现某个数据项是否属于关键判断因子无法从 `wiki/运行契约/日报数据源契约.md` 或现有代码判断，再补充决策。
