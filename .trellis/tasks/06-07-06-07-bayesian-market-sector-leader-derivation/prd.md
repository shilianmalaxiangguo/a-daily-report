# brainstorm: 贝叶斯式市场板块龙头推导

## Goal

把用户提出的医学诊断类比落成日报规格：像“基础发病率 + 检测结果 -> 真实患病概率”一样，日报应先给市场和板块层面的先验，再用资金、承接、辨识度、龙头资格、执行窗口等证据逐步更新，最后给出唯一明日对象及其仓位条件。目标不是把交易伪装成精确概率，而是让“为什么是这个标的、为什么不是另一个标的、为什么是0/50/100”变得可检查、可复盘、可纠偏。

## What I Already Know

* 用户认为炒股选龙头像医学诊断：基础发病率对应市场情绪和板块情绪，检测结果对应个股资金/承接/龙头证据，真实患病概率对应“明日真实可做对象”的后验概率。
* 用户要的不是泛泛评分，而是从市场、资金、板块关系出发，最后才到个股。
* 用户强调最终目的是选出一个对象，不能每个步骤各说各的。
* 现有日报已经有 `market_research_snapshot`、`mainline_turnover_summary`、`current_sector_turnover_snapshot`、`position_decision`、`final_target_resolution`、`sniper_target_derivation` 等链路。
* 现有 `final_target_resolution` 已经统一新开仓对象、旧仓处理对象、小账户替代对象、观察对象和最终显示对象。
* 现有 `sniper_target_derivation` 已经能记录“原始候选 -> 当前核心 -> 最终对象解析”的过程，但还没有明确表达“先验、证据似然、后验、行动阈值”。
* 现有仓位只有 0%、50%、100% 三档；不是连续小仓位模型。

## Assumptions

* 贝叶斯层优先作为解释和校准层，不先做复杂机器学习或真实概率校准。
* 初版使用分档概率区间，例如低/中/高，或 20%-40% / 40%-70% / 70%+，避免伪精确。
* “市场情绪”和“主线/板块情绪”应作为先验；个股证据不能越过先验直接给 50%/100%。
* 强个股反常走强可以上调后验，但必须说明它是在逆环境提高可信度，还是只是噪音。

## Requirements

* 日报新增一条“贝叶斯诊断链”或同等结构，解释市场先验、板块先验、个股证据、后验结论、行动阈值。
* 市场先验必须来自市场状态、赚钱效应、跌停/涨停扩散、成交额、主线周期阶段等。
* 板块先验必须来自主线强度、板块成交额占比、资金流、内部梯队、周期阶段、超车/失速/窗口判断。
* 个股证据必须区分高区分度证据和低区分度证据：涨停本身不是龙头，只有在板块锚、承接路径、相对强弱和执行窗口同时支持时才显著上调。
* 最终对象必须进入同一个候选池比较，不能每个模块各自给一个结论。
* 输出必须说明反证：哪些证据会让后验下调，哪些条件不满足会从 50%/100% 回到 0%。
* 输出必须保留三档仓位：0%、50%、100%，并说明触发阈值与错判代价。

## Acceptance Criteria

* [ ] 一份日报能看到“市场先验 -> 板块先验 -> 个股证据 -> 后验 -> 最终对象/仓位”的连续链条。
* [ ] 当市场或主线处于冰点时，强个股不能无解释地直接升级为 50%/100%。
* [ ] 当板块先验强但个股证据弱时，报告输出候选观察或等待条件，而不是硬给唯一买入对象。
* [ ] 当个股证据很强但板块先验弱时，报告必须说明这是逆环境例外，并列出次日确认条件。
* [ ] `final_target_resolution` 与 `sniper_target_derivation` 中能消费或展示贝叶斯诊断结果。
* [ ] 相关测试覆盖至少三种场景：强市场强板块强个股、弱市场强个股、强板块弱个股。

## Definition Of Done

* 使用 `.generated/venv-py314/bin/python3.14` 运行新增/相关单测。
* 用户可见文字遵守 `wiki/交易思想/日报术语契约.md`。
* 如果改动日报正文，重新生成一个目标日期 replay 报告并检查可读性。
* 不引入 sqlite / Cloudflare / snap-ui 旧路径。

## Out Of Scope

* 不做真实统计模型训练。
* 不把概率精确到小数点。
* 不增加 25%、30%、70% 等新仓位档。
* 不替代现有 `final_target_resolution`，而是在现有统一对象链路上补充诊断解释。
* 不接入实时盘中交易自动执行。

## Technical Notes

* `scripts/report/runtime.py`：当前生成并存储 `final_target_resolution` 与 `sniper_target_derivation`。
* `scripts/report/sniper_target_derivation.py`：已有候选到最终对象的 ASCII 过程，可扩展为先验/证据/后验解释。
* `scripts/selection/position_sizing_runtime.py`：当前决定 0/50/100 仓位，是行动阈值落点。
* `scripts/report/front_page_v2_renderer.py`：前台消费 `final_target_resolution`、`position_decision`，适合展示摘要。
* `scripts/domains/market_state/mainline_turnover_summary_runtime.py`：板块成交额占比和主线切换证据来源之一。
* 记忆提示：报告工作必须避免黑盒，过程表不是结论，最终对象链路必须可检查。

## Bayesian Mapping Draft

* `先验 P(明日可做)`：市场情绪和主线周期给的基础概率。市场冰点/主线冰点时，先验低；启动/发酵时，先验中高；高潮后退潮时，先验下降。
* `板块似然比`：板块资金净流入、成交额占比抬升、内部梯队完整、核心承接强，会把后验上调；板块高标深水、跌停扩散、占比回落，会下调。
* `个股似然比`：龙头辨识度、低开强承接、开盘主动进攻、分时大单净流入、市值适配后的资金量、固定交易窗口条件，会继续上调。
* `反证`：只是涨停但不是板块锚、资金不足以匹配市值、只在弱板块中孤立上涨、买点离失效价太远，不能显著上调。
* `行动阈值`：50%需要后验越过“值得试错”的阈值；100%需要市场/板块/个股三层都高一致且错判代价可控；0%用于后验不足或下行不可接受。
