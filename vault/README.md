# Daily Report Vault

这个目录是日报项目的长期工作记忆层，参考 OpenAI Codex 长程工作白皮书里的 vault 结构，但按本仓库的日报系统做了收敛。

它的目的不是替代 `wiki/`、`.trellis/`、`reports/` 或代码，而是把跨多次对话仍然需要继续使用的工作记忆放到一个可读、可改、可 diff 的位置。

## 分区

- `TODO.md`：当前仍未完成、需要回看的事项。
- `people/`：和日报系统相关的人、偏好、协作对象。默认只写必要上下文，不写隐私细节。
- `projects/`：长期项目主线、阶段目标、当前风险和下一步。
- `agent/`：AI 协作方式、常见失误、运行偏好和检查习惯。
- `notes/`：按日期记录的轻量笔记，适合暂存当天讨论、判断和后续线索。

## 和现有目录的边界

- `wiki/`：稳定交易知识和日报口径。已经确认、可反复使用、能进入日报判断链的内容，沉淀到 `wiki/`。
- `.trellis/`：任务执行、规格、检查记录和开发过程。需要形成工程任务或质量检查时，走 `.trellis/`。
- `reports/`、`snapshots/`：日报产物和回放事实。它们是证据和产物，不是长期工作记忆入口。
- `reports/memory/`：生成产物范围内的记忆抽取结果。它在 `.gitignore` 范围内，不作为可提交的长期 vault。
- `vault/`：跨会话的工作记忆索引。它可以链接到上述目录，但不复制大段正文。

## 写入规则

- 只写未来还会用到的内容。
- 记录来源、日期和状态，避免把临时判断写成稳定结论。
- 能归入 `wiki/` 的交易原则，不长期停留在 `vault/notes/`。
- 能归入 `.trellis/tasks/` 的开发任务，不长期停留在 `TODO.md`。
- 生成日报时不要直接把 vault 笔记写进报告正文；需要先经过事实、规则和反证检查。

## 使用流程

1. 开始长任务时，先看 `vault/projects/` 和 `vault/TODO.md`。
2. 涉及个人偏好或协作方式时，看 `vault/agent/`。
3. 需要追某次讨论背景时，看 `vault/notes/`。
4. 发现稳定交易规则时，升级到 `wiki/`，并在原笔记留下链接。
5. 发现明确开发任务时，升级到 `.trellis/tasks/` 或当前计划，并在 `TODO.md` 标记去向。
