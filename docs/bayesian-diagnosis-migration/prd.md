# Bayesian 路径诊断接入 PRD

## 1. 背景

`codex/bayesian-diagnosis-module` 是一条真实遗漏的功能分支。它提供了“市场、主线、资金、个股、反证”逐层诊断能力，也补了来源日期和专项检查。

但这条分支不能直接整支合并。原因是当前主线已经形成了更清楚的日报主链路：

- `selection_workflow.final` 是最终动作来源。
- `final_target_resolution` 负责把旧仓、新机会、观察对象和替代对象统一表达。
- 首页结构已经调整为先给最终动作，再给推导和证据。
- 历史 replay 已经强调目标日期事实，不能让无日期或当前数据混入历史判断。

Bayesian 分支的精华应该被接入；会扰乱主链路的部分必须舍弃。

## 2. 产品目标

接入后，日报不只是告诉你“明天做不做、做谁、几成”，还要告诉你：

1. 这个结论是从哪几层推出来的。
2. 哪些层支持继续参与，哪些层只能观察。
3. 有哪些反证让参与资格下降。
4. 每一层证据属于哪一天。
5. Bayesian 路径和当前最终动作是否一致。

换句话说，它的价值不是替你重新选一个标的，而是让最终动作更可复盘、更可审计、更容易被 AI 和人读懂。

## 3. 范围

### 3.1 In Scope

- 新增或迁移 `bayesian_diagnosis.v1` 路径诊断包。
- 使用 `path_conclusion` 表达路径状态。
- 保留来源日期检查：来源日期缺失时必须显式保留“来源日期缺失”。
- 在运行期写入 `bayesian_diagnosis`，供首页、附录和接受检查读取。
- 首页展示简版路径解释，但不能压过最终动作。
- 附录展示完整路径，包括市场、主线、资金、个股、反证。
- 接受检查增加 Bayesian 专项检查。
- 补充聚焦测试，覆盖一致、冲突、来源日期缺失、反证、旧仓优先、0%不参与、50%条件执行、100%核心进攻。

### 3.2 Out of Scope

- 不整支合并 `codex/bayesian-diagnosis-module`。
- 不整文件覆盖当前主线 renderer/runtime。
- 不把 Bayesian 诊断设为最终动作来源。
- 不迁移会回退目标日期处理的 `market_analysis_builder.py` 改动。
- 不新增新的候选池排序体系。
- 不改数据库、环境配置、CI 或外部数据源。

### 3.3 Non-goals

- 不用 Bayesian 诊断替代现有选股逻辑。
- 不让它静默覆盖 `selection_workflow.final`。
- 不展示粗胜率、粗可信标签、粗区间判断。
- 不把观察对象包装成参与资格。
- 不把旧仓处理对象、新机会对象、替代对象混成一个对象。

## 4. 取其精华，去其糟粕

| 分类 | 保留 | 舍弃 |
|---|---|---|
| 诊断包 | `bayesian_diagnosis.v1` 的路径分层、候选证据、反证、来源日期。 | 让诊断结论直接覆盖最终动作。 |
| 用户表达 | `path_conclusion`：路径一致、条件执行、存在反证、路径不完整、无执行对象。 | `diagnosis_label`、粗胜率、粗可信区间。 |
| 运行期 | 把诊断结果存入 `data`、`execution_stage_context`、`market_research_snapshot`。 | 改写现有最终动作来源顺序。 |
| 首页 | 最终动作下方展示简版路径解释。 | 把 Bayesian 诊断做成比最终动作更显眼的新结论。 |
| 附录 | 展示完整路径和每层来源日期。 | 用无日期数据补历史判断。 |
| 接受检查 | 检查路径摘要、来源日期、对象一致性和不合适表达。 | 削弱当前主线已有的一致性检查。 |
| 测试 | 迁移分支里有价值的样本，并改成当前主线契约。 | 保留“Bayesian 覆盖旧最终对象”的测试预期。 |

## 5. 接入后的用户效果

### 5.1 首页效果

当前首页会先显示最终动作。接入后仍然保持这个顺序：

1. 明日最终动作：0%不参与 / 50%条件执行 / 100%核心进攻。
2. 重点对象：执行对象、观察对象或暂无。
3. Bayesian 路径解释：为什么是这个动作。
4. 关键反证：什么条件不满足会回到不参与。

建议展示成一张小表：

| 项目 | 展示 |
|---|---|
| 路径结论 | 条件执行 |
| 对象一致性 | 与最终动作一致 |
| 关键支持 | 主线仍在、资金未否定、个股具备回踩观察基础 |
| 关键反证 | 板块分歧仍在，固定交易窗口未确认 |
| 来源日期 | 2026-06-04 |

### 5.2 附录效果

附录会多一段“路径诊断”，用于复盘：

- 市场层：市场是否允许继续找机会。
- 主线层：周期主线和当天主攻线是否同向。
- 资金层：资金是否支持继续传递。
- 个股层：对象是否具备参与资格。
- 反证层：哪些证据要求降低动作。

每层必须带来源日期，不能默认用目标日期冒充来源日期。

### 5.3 AI 理解提升

接入后，后续 AI 不需要从散乱文本里猜“为什么选这个对象”。它能直接读取：

- `path_conclusion`
- `path[]`
- `source_date`
- `cannot_conclude`
- `conflicts`
- `execution_object`
- `final_action_alignment`

这样后续复盘、测试、修 bug 都更容易定位问题。

## 6. 和现有逻辑的冲突点

| 冲突点 | 原有逻辑 | Bayesian 分支风险 | PRD 处理 |
|---|---|---|---|
| 最终动作来源 | `selection_workflow.final` 给最终动作。 | Bayesian 结论可能覆盖最终动作。 | Bayesian 只能解释和复核，不能改最终动作。 |
| 对象身份 | 旧仓、新机会、观察对象、替代对象各自有身份。 | 诊断包可能只给一个 execution_object。 | 诊断包必须继承当前对象身份，不得把观察对象写成参与对象。 |
| 0/50/100 | 当前只允许三种动作表达。 | 分支里曾出现粗可信标签和旧仓位话术。 | 只允许 0%不参与、50%条件执行、100%核心进攻。 |
| 历史 replay | 必须使用目标日期事实。 | 来源日期缺失时容易被默认成目标日期。 | 来源日期缺失必须显式保留，接受检查要能发现。 |
| 首页层级 | 最终动作先出现，推导后出现。 | Bayesian 诊断可能抢主结论位置。 | 只放最终动作下方做短解释。 |
| 接受检查 | 当前已有对象一致性和结构检查。 | 新检查可能重复或误报。 | 只加 Bayesian 专项检查，不削弱原检查。 |
| 分支未提交改动 | 有些改动是修正，有些会回退主线。 | 整体迁移会混入不该要的内容。 | 按文件和函数小块迁移。 |

## 7. 功能需求

### 7.1 数据契约

`bayesian_diagnosis` 至少包含：

```python
{
    "schema_version": "bayesian_diagnosis.v1",
    "target_date": "2026-06-04",
    "conclusion": {
        "path_conclusion": "条件执行",
        "execution_object": {"name": "示例股份", "code": "000000"},
        "position_pct": 50,
        "action_text": "条件满足才50%条件执行；不满足回到0%",
        "final_action_alignment": "一致"
    },
    "path": [
        {
            "layer": "market",
            "source_date": "2026-06-04",
            "input_summary": "市场修复但分歧仍在",
            "judgement": "允许继续诊断",
            "passes_forward": "进入主线层",
            "cannot_conclude": ["市场层不能直接推出个股"]
        }
    ],
    "counter_evidence": ["固定交易窗口未确认"],
    "conflicts": []
}
```

### 7.2 最终动作保护

- Bayesian 可以读最终动作。
- Bayesian 可以报告“与最终动作一致 / 不一致 / 无法判断”。
- Bayesian 不可以写最终动作。
- 如果 Bayesian 对象和最终动作对象不一致，日报应展示不一致并停止把它当成执行依据。

### 7.3 首页渲染

- 最终动作仍然是首要信息。
- Bayesian 简版解释最多占一个小节。
- 没有路径摘要时不渲染空标题。
- 有反证时必须显示反证，不得只显示支持证据。

### 7.4 附录渲染

- 附录展示完整路径。
- 每层显示：层级、来源日期、输入摘要、判断、传递、不能推出什么。
- 来源日期缺失时显示“来源日期缺失”。

### 7.5 接受检查

至少检查：

- 首页有最终动作时，Bayesian 不得给另一个执行对象。
- Bayesian 路径缺来源日期时报告问题。
- Bayesian 使用粗胜率或粗可信标签时报告问题。
- `path_conclusion=路径一致` 时，反证层不能同时存在强反证。
- 0%不参与时，Bayesian 不能把观察对象写成参与对象。
- 50%条件执行时，必须保留固定交易窗口失败后的处理。

## 8. 验收定义

完成接入后，必须满足：

1. 当前主线最终动作来源不变。
2. 首页新增路径解释，但最终动作仍在首位。
3. 附录新增完整路径诊断。
4. 来源日期缺失不会被静默替换。
5. 不出现粗胜率、粗可信标签。
6. Bayesian 和最终动作不一致时可被看见，不会静默二选一。
7. 聚焦测试通过。
8. `git diff --check` 通过。
