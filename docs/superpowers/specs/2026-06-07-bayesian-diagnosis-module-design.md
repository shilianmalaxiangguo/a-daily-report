# 日报贝叶斯诊断模块设计

日期：2026-06-07

## 目标

新增一个统一的 `贝叶斯诊断模块`，让日报从市场、主线/板块、资金、龙头个股和反证，连续推出唯一的明日执行结论。

这个模块的目标不是计算真实概率，也不是把旧评分换成新的概率标签。它要解决三个问题：

1. 日报各段不能各自给最终对象。
2. 旧评分不能绕过市场和板块路径，直接推出仓位结论。
3. 用户必须能看懂“结合什么数据，得出什么判断，最后为什么是这个对象和这个仓位”。

最终日报应能稳定回答：

```text
明日是否参与？
如果参与，唯一执行对象是谁？
为什么是它，不是其他候选？
仓位是0%、50%、还是100%？
什么条件失败后必须回到0%？
```

## 设计定位

`贝叶斯诊断模块` 是路径一致性诊断模块，不是概率计算器。

它借鉴贝叶斯思维里的四件事：

- 先看基础环境。
- 再看证据如何上调或下调判断。
- 必须列出反证。
- 最后把判断落到行动阈值。

但它不输出概率区间，不写粗概率标签，也不把旧分数换算成所谓后验概率。

用户可见输出只保留交易诊断标签：

| 诊断标签 | 行动含义 |
|---|---|
| 低可信 | 0%，不参与 |
| 中高可信 | 条件满足才50%，失败回到0% |
| 高可信 | 只有三层共振才允许100%准备 |

这些标签不是概率换皮，而是路径证据支持后的行动分档。

## 论文整理

参考论文：`Strong Stochastic Flow Maps`，arXiv:2606.01086。

这篇论文研究的是生成模型里的随机微分方程采样效率问题，不是金融预测论文。它的核心问题是：扩散模型和流模型质量高，但推理时需要很多步数；如果直接学习微分方程的解映射，就能减少步数。已有随机流映射方法大多学习转移分布，只能恢复每个时间点的边际分布，不能恢复同一条随机路径上的解。

论文提出 `Strong Stochastic Flow Maps`。它不是只学习 `X_s -> X_t` 的转移分布，而是学习 Itô map：

```text
Ψ_{s,t}: (X_s, W_[s,t]) -> X_t
```

也就是：给定初始状态和同一段 Brownian 路径，模型要输出同一条路径上的结果，而不是只在每个时点各自抽一个看起来分布正确的结果。

论文里对我们有用的关键点有四个：

1. `弱式转移分布` 不够。只匹配每个时点的边际分布，可能看起来结果合理，但无法估计路径相关的量。
2. `强路径解` 必须吃到驱动路径。模型输入不只有起点，还要有驱动这段变化的随机路径。
3. `局部一致性` 和 `分段组合一致性` 同时需要。短步要贴近真实局部行为；从 `s` 到 `t` 的整体映射，要等于 `s -> u` 再 `u -> t` 的组合结果。
4. 路径可以压缩，但压缩有误差。论文用 Brownian 多项式系数压缩路径，并依赖 Chen relations 保证子区间信息能组合成整段信息。

论文实验不是证明金融可预测，而是验证 SSFM 在固定初始条件和同一随机路径下，跨不同步数能保持路径一致；在图像生成和分子采样里，少步数表现优于弱式随机流映射。

论文也有边界：它主要展示 additive-noise SDE；路径压缩阶数需要调参；对路径一致性的更细实验研究仍是未来工作。因此日报设计只能借用它的结构思想，不能把它当成交易胜率模型。

## 论文对日报设计的约束

日报不直接使用论文里的数学模型，但采用它的四个结构约束。

### 1. 不能只匹配最终结论

如果日报只在最后输出一个看似合理的标的和仓位，但市场、板块、资金、个股各段无法串起来，这相当于只看边际结果。它可能读起来像对，但不能解释路径，也不能复盘错误。

日报必须保留同一条市场路径上的连续推导，让分段判断和整体结论一致。

映射到日报：

```text
弱式日报：
市场给一个分，板块给一个分，个股给一个分，最后拼出仓位。
这种方式看起来量化，但仍然可能是假精确。

路径式日报：
市场路径 -> 主线/板块路径 -> 资金校准 -> 龙头个股 -> 反证 -> 仓位。
每一步都必须说明传给下一步什么，不能推出什么，是否和最终对象一致。
```

### 2. 诊断输入必须包含“驱动路径”

论文里的强路径解不只看起点，还看 Brownian path。日报里对应的不是随机数学路径，而是当天真实驱动路径：

- 市场从开盘到收盘的情绪变化。
- 主线/板块从启动、发酵、高潮、退潮到冰点的阶段位置。
- 资金从总量到板块再到个股的传导。
- 龙头和后排之间的强弱变化。
- 反证出现的时间和位置。

因此，贝叶斯诊断模块不能只吃静态快照。它至少要保留“路径摘要”，说明为什么今天这条市场路径会推到这个明日结论。

### 3. 需要局部一致性

论文要求短步行为贴近真实局部行为。日报对应的是：每个局部判断都必须能由本层数据推出。

示例：

- 市场层只能推出是否允许继续诊断，不能直接推出个股。
- 主线/板块层只能推出方向资格，不能因为板块强就指定任意涨停股。
- 个股层必须证明龙头资格、承接、资金和买点，不能只靠旧评分。
- 反证层必须能下调或停止结论，不能成为装饰段。

如果某层局部判断不成立，后面不能靠最终结论倒推补强。

### 4. 需要分段组合一致性

论文里的整体映射必须等于分段映射组合。日报对应的是：

```text
市场 -> 主线/板块 -> 个股 -> 仓位
```

的整体结论，必须等于各层依次传递后的结果。不能出现：

```text
市场层偏防守
板块层说另一个方向更强
个股层写上海石化更像对象
首页最后给豫能控股50%
```

如果分段组合和首页结论不一致，日报无效。正确做法是显式记录冲突，并让路径诊断停止或降到更低行动档位。

### 5. 路径摘要可以压缩，但必须可合成

论文用多项式系数压缩 Brownian path，并要求子区间信息能组合成整段信息。日报对应的是：可以把复杂市场数据压缩成路径摘要，但摘要必须保留可合成字段。

第一版路径摘要至少应保留：

- `source_date` / `target_date`：证明事实属于目标日期。
- `layer`：市场、主线/板块、资金、个股、反证。
- `input_summary`：本层使用的数据。
- `judgement`：本层判断。
- `passes_forward`：传给下一层的内容。
- `cannot_conclude`：本层不能推出什么。
- `conflicts`：与旧评分或其他候选的冲突。

如果摘要压缩后无法解释最终结论，它就是有损压缩过度，不能用于首页结论。

因此，本设计不追求精确概率，而追求路径可解释、局部判断成立、分段组合一致、压缩摘要可复盘。

## 当前设计偏差纠正

上一版设计对论文使用过于粗略，只抽取了“弱结论 vs 强路径结论”的表层类比，容易遗漏三件更重要的东西：

1. 强路径结论必须包含驱动路径输入，而不是只保留起点和终点。
2. 局部短步判断和长步分段组合必须同时一致。
3. 路径摘要可以压缩，但压缩后的摘要必须能重组出最终结论。

因此，本版修正为：

- 不把论文当成交易预测模型。
- 不把“路径一致性”写成空泛口号。
- 把局部一致性、分段组合一致性、路径摘要可合成写入模块输出、验收规则和测试计划。

## 范围

范围内：

- 设计 `贝叶斯诊断模块` 的职责、输入、输出和展示规则。
- 规定旧评分、旧分数、旧候选表如何降级为证据输入。
- 规定首页简版和推导层详版如何消费同一份诊断结果。
- 规定 0%、50%、100% 的诊断落点。
- 规定冲突、数据缺失和历史 replay 的处理原则。

范围外：

- 不训练统计模型。
- 不建立精确概率校准系统。
- 不增加 25%、30%、70% 等新仓位。
- 不重写全部数据采集器。
- 不接入自动交易。
- 不删除仍有证据价值的旧评分代码。

不做：

- 不把概率区间写进日报正文。
- 不把涨停本身当成龙头资格。
- 不让任一旧评分模块单独决定最终对象或仓位。
- 不用当前实时数据回填历史 replay。
- 不恢复 sqlite、Cloudflare、snap-ui 旧路径。

## 核心原则

### 1. 先路径，后对象

日报必须先说明市场和主线/板块发生了什么，再进入个股。

正确顺序：

```text
市场路径
  -> 主线/板块路径
  -> 资金证据校准
  -> 候选池收缩
  -> 龙头个股诊断
  -> 反证复核
  -> 唯一执行对象和仓位
```

个股不能绕开市场和板块，直接因为涨停、热度或单个高分成为明日执行对象。

### 2. 资金是证据，不是平行结论源

资金分析贯穿三层：

- 市场层：总成交、缩量/放量、赚钱效应、涨跌扩散。
- 主线/板块层：成交额占比、资金流向、梯队完整度、高标表现。
- 个股层：大单净流入、主动买盘连续性、VWAP/0轴保持、市值匹配。

资金不能单独输出一个最终对象。它只能上调、下调或否定路径诊断。

### 3. 所有候选进入同一个诊断池

热榜、涨停池、异动、主线核心、历史龙头记忆、旧评分高分候选，都必须进入同一候选池比较。

候选身份只允许这些类型：

- `明日执行对象`：最终唯一对象。
- `条件执行对象`：同一个对象，强调必须等待条件成立。
- `过程候选`：参与比较，但不能写成最终动作。
- `被淘汰候选`：明确说明淘汰原因。
- `无明日执行对象`：没有任何候选通过路径诊断。

默认不允许多个最终对象并列。

### 4. 旧评分只保留证据权

旧评分、旧分数、旧置信度相关模块不能直接给最终动作。

它们的身份调整为：

| 旧模块或旧结果 | 新身份 |
|---|---|
| 候选质量评分 | 个股层证据 |
| 板块扩散分 | 主线/板块层证据 |
| 风险分 | 反证和仓位下限证据 |
| 反馈成熟度 | 个股承接证据 |
| 大单净流入 | 个股资金确认 |
| 市值和成交额分层 | 资金阈值解释 |

如果旧评分和路径诊断冲突，以路径诊断为准，并在推导层说明冲突。

## 模块输入

### 市场路径输入

- 指数涨跌和结构。
- 涨跌家数。
- 两市成交额和成交趋势。
- 涨停/跌停扩散。
- 赚钱效应。
- 市场周期：启动、发酵、高潮、退潮、冰点。
- 是否存在全市场冰点，例如指数大跌、跌停扩散、全市场缩量失去参与意愿。

输出只能是环境判断，不能选股。

### 主线/板块路径输入

- 当前最强主线。
- 主线周期：启动、发酵、高潮、退潮、冰点。
- 板块成交额占比。
- 板块资金流向。
- 内部梯队完整度。
- 高标和核心股表现。
- `超车、失速、窗口` 判断：
  - 哪些方向比预期更强。
  - 哪些方向比预期更弱。
  - 哪些方向比预期更值得做。

输出是方向资格和板块支持度，不直接给个股仓位。

### 个股路径输入

- 是否是真龙头，而不是只看涨停。
- 是否是板块锚、情绪锚或容量核心。
- 相对强弱。
- MA5、MA10、VWAP、0轴位置。
- 低开承接路径。
- 主动进攻路径。
- 分时大单净流入与市值匹配。
- 买点和失效位距离。
- 是否在固定交易窗口内满足条件：
  - `09:30-09:35`
  - `09:50-10:10`
  - `14:30-14:55`

输出是个股是否具备执行资格。

### 反证输入

- 市场冰点。
- 主线/板块冰点。
- 板块高标深水或跌停。
- 板块普遍深水。
- 只有个股强，板块不跟。
- 只有涨停，没有龙头证据。
- 资金确认不足。
- 大市值对象使用了小中盘资金阈值。
- 买点离失效位太远。
- 历史 replay 数据来源无法证明属于目标日期。

反证必须优先展示，不能被一堆弱支持证据淹没。

## 路径层级

### 第一层：市场路径

目的：判断大环境是否允许继续寻找明日执行对象。

输出只能是：

- `不参与`
- `可等待50%条件`
- `允许继续诊断`

这一层不能选股。

### 第二层：主线/板块路径

目的：判断资金和情绪是否集中在可参与方向。

输出：

- 主线处于哪个周期阶段。
- 哪些板块比预期更强。
- 哪些板块失速。
- 哪个方向存在明日窗口。
- 传给候选池的方向范围。

这一层不能把板块内任意涨停股升级为执行对象。

### 第三层：资金校准

目的：用资金证据校准市场、板块和个股路径。

它不是独立步骤，而是贯穿校准：

- 市场资金确认环境。
- 板块资金确认方向。
- 个股资金确认执行资格。

个股大单净流入阈值必须结合市值或成交额体量：

| 对象体量 | 默认资金确认 |
|---|---|
| 小中盘活跃股 | 3000w-5000w |
| 大市值或高成交核心 | 1亿+ |
| 超大容量核心 | 1亿+，并结合成交额占比、VWAP保持和主动买盘连续性 |

### 第四层：龙头个股诊断

目的：判断候选是否是真正值得准备的执行对象。

必须回答：

- 它是不是板块龙头。
- 它是不是资金和情绪的实际承载对象。
- 它和同板块其他候选相比为什么胜出。
- 它的买点是否贴近失效位。
- 它是否有固定交易窗口内的条件路径。

涨停只是证据之一，不是龙头资格。

### 第五层：反证与行动落点

目的：把路径诊断翻译成 0%、50%、100%。

行动规则：

| 诊断标签 | 仓位 | 必须满足 |
|---|---:|---|
| 低可信 | 0% | 任一关键路径不足，或反证压倒支持证据 |
| 中高可信 | 50% | 市场和板块未否定，个股具备条件路径 |
| 高可信 | 100% | 市场不差、主线/板块强、个股是真龙头、买点贴近失效位 |

100% 不是“最看好”就够了。它必须来自三层共振，并且错判代价可控。

## 首页展示

首页只展示简版诊断结论，服务盘前快速决策。

建议结构：

```text
## 明日诊断结论

| 项目 | 结论 |
|---|---|
| 明日是否参与 | 条件满足才参与 |
| 明日执行对象 | 豫能控股(001896) |
| 诊断标签 | 中高可信 |
| 仓位 | 条件满足50%，失败0% |
| 失败处理 | 不参与 |

### 关键证据
- 市场：...
- 主线/板块：...
- 个股：...

### 关键反证
- ...
- ...
```

首页禁止展示概率区间。

## 推导审计层展示

推导层解释完整路径。

每一层固定使用：

```text
### <层级名称>
#### 输入数据
#### 本层判断
#### 传给下一层
#### 本层不能推出什么
#### 反证
```

如果某层不能继续支持执行对象，必须明确写出：

```text
路径诊断到此停止：无明日执行对象。
```

如果某个过程候选被淘汰，必须写明淘汰原因，而不是从后文消失。

## 与现有链路的关系

### `sniper_target_derivation`

继续承担最终对象推导的可见路径，但需要接入 `贝叶斯诊断模块` 的路径结果。

它应展示：

- 原始候选来自哪里。
- 哪些候选进入同一诊断池。
- 哪些被保留。
- 哪些被淘汰。
- 最终对象如何从诊断路径产生。

### `final_target_resolution`

它仍是最终对象身份的下游承载，但不应绕过诊断模块重新选对象。

最终对象应来自：

```text
贝叶斯诊断模块结论 -> final_target_resolution -> 首页和行动展示
```

### `position_sizing_runtime`

它继续承担 0%、50%、100% 的仓位落点，但需要消费诊断标签和路径结论。

旧仓位条件可以保留，但不能和诊断路径冲突。

### `candidate_quality_scorecard`

它降级为候选证据面板。

它可以展示过程候选、证据和淘汰原因，但不能独立渲染一个看起来像最终对象的股票。

### `front_page_v2_renderer`

它负责渲染首页简版诊断结论。

首页不得从旧候选字段直接取最终对象。

## 冲突处理

如果旧评分和诊断路径冲突，日报必须显示冲突，而不是静默修正。

示例：

```text
候选质量评分显示上海石化靠前，但贝叶斯诊断路径未保留为明日执行对象。
原因：它没有成为当前主线的龙头承载对象，且资金确认不足。
处理：仅作为过程候选展示。
```

如果首页、最终对象、仓位、推导层出现不同对象，日报应判为无效输出。

## 数据缺失处理

关键数据缺失时不能补出结论。

规则：

- 市场路径缺失：不能给 50% 或 100%。
- 主线/板块路径缺失：不能给 100%，50% 也必须说明只剩条件等待。
- 个股资金确认缺失：主动进攻路径不能成立。
- 失效位缺失：不能给 100%。
- replay 数据无法证明属于目标日期：不得混入当前事实。

关键数据不完整时，输出：

```text
关键数据不完整，停止生成
```

或：

```text
关键数据不完整，当前只能0%不参与
```

## 验收规则

以下情况判为日报无效：

- 日报出现概率区间或粗概率标签。
- 首页和推导层不是同一个执行对象。
- 只有最终结论，没有市场、主线/板块、资金、个股和反证的路径摘要。
- 任一层越过本层数据能力，直接推出后面层级的结论。
- 分段推导组合结果和首页结论不一致。
- 路径摘要缺少目标日期或事实来源日期，无法证明事实属于当前报告日期。
- 旧评分模块单独给出最终对象或仓位。
- 市场或主线处于冰点，却无解释给出 100%。
- 个股只是涨停，但没有龙头证据，却被写成明日执行对象。
- 板块强但个股不是龙头，仍给出最终执行对象。
- 个股强但板块弱，却没有写逆环境确认条件。
- 100% 缺少三层共振、失效位或错判代价说明。
- 过程候选在后文变成最终动作。
- replay 把当前实时事实混入历史日期。

## 测试计划

聚焦测试：

- 首页不渲染概率区间。
- 首页、最终对象、仓位、推导层消费同一份诊断结果。
- 诊断结果必须包含可复盘路径摘要，且每层包含输入数据、本层判断、传给下一层、本层不能推出什么。
- 市场层不能直接选股，主线/板块层不能直接指定任意涨停股，个股层不能只靠旧评分给执行资格。
- 分段推导组合结果必须和首页结论一致；不一致时输出无效。
- replay 路径摘要必须保留目标日期和事实来源日期。
- 市场冰点时不能直接给 50% 或 100%。
- 主线/板块冰点时不能直接给高仓位。
- 板块强、个股弱时，输出过程候选或等待条件。
- 个股强、板块弱时，只能输出逆环境确认条件，不能无条件参与。
- 涨停但非龙头时，不得升级为明日执行对象。
- 旧评分与诊断路径冲突时，诊断路径优先，并渲染冲突解释。
- 大市值对象不能使用小中盘 3000w-5000w 资金阈值。
- 100% 必须同时满足市场、主线/板块、个股和失效位条件。

Replay 验证：

```bash
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-06-04 --replay
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-06-05 --replay
```

随后检查：

- 首页是否清楚给出明日结论。
- 推导层是否能解释唯一对象。
- 旧候选是否只作为过程证据出现。
- 华电辽能做T亏损复盘相关纪律是否仍能约束冲动买入。

## 第一版实现边界

第一版优先做最小可验证闭环：

1. 增加 `bayesian_diagnosis.v1` 结构化诊断结果。
2. 把旧评分、旧候选、市场、主线/板块和资金证据收编为诊断输入。
3. 让 `final_target_resolution`、`sniper_target_derivation`、首页和仓位展示消费同一份诊断结论。
4. 首页渲染简版诊断结论。
5. 推导层渲染完整路径。
6. 增加一致性检查和聚焦测试。
7. 重新生成 replay 样例并人工检查可读性。

第一版不做：

- 不训练概率模型。
- 不校准真实胜率。
- 不用小数或概率区间表达后验。
- 不改动与当前日报主链路无关的数据源。
- 不扩大仓位体系。

## 未来校准方向

未来如果有足够历史样本，可以做预测校准，但必须另起规格：

- 记录每次诊断标签、执行条件和次日结果。
- 检查 `低可信 / 中高可信 / 高可信` 的历史命中率。
- 校准行动阈值，而不是回头把标签伪装成当日精确概率。

在没有足够样本之前，诊断标签只能表示路径强弱和行动资格，不能表示真实概率。
