# HTML 图表驾驶舱日报设计

日期：2026-06-09

## 背景

现有 HTML 日报已经能把 Markdown 长文变成阅读器式页面，但它仍主要是在展示表格和文字。用户指出 HTML 的真正优势不是“更漂亮”，而是能用图表、悬停、点击、高亮和维度切换改变阅读方式。

本设计把 HTML 日报的第一屏从“长文阅读”升级为“市场与主线图表驾驶舱”。第一屏先回答：

- 今天市场容量是否支持继续诊断。
- 资金是否集中到主线。
- 主线攻击证据是否成立。
- 哪些板块在强化、掉队或只是注意力候选。
- 热榜前 100 的 tag 注意力是否支持板块拆解。

Markdown 继续保留。HTML 首版只增强阅读产物，不改写交易判断逻辑。

## 目标

第一版目标是让每日 HTML 第一屏稳定回答一个主问题：

> 今天的市场与主线证据，是否支持继续寻找明日参与对象？

为此新增五类图表：

1. 市场容量趋势。
2. 主线成交占比趋势。
3. 板块热力矩阵。
4. 主线攻击证据散点。
5. 热榜 Tag 构成图。

另保留板块周视图 / 周期日历作为下钻图表，用于解释时间脉络，不放入首屏五图，也不参与当天热力重复计算。

## In Scope

- 扩展 `DailyReportView`，新增 `charts` 字段。
- 在 `scripts/report/html_report_view.py` 中组装五类图表 payload。
- 在 `scripts/report/html_report_renderer.py` 中安全注入图表数据。
- 在 `scripts/templates/daily_report_reader.html` 中加入 ECharts 容器、解释面板和基础交互。
- 复用上证缠论 HTML 的 ECharts 加载策略：优先本地 `.generated/vendor/echarts/echarts.min.js`，本地缺失时才使用 CDN。
- 明确图表之间的数据职责，避免热榜 tag 被重复当成板块强度确认。
- 保留现有明日动作、参与对象、数据来源、运行诊断等章节。
- 增加相关单测和视觉检查要求。

## Out of Scope

- 不做独立前端应用。
- 不引入构建系统。
- 不一次性废掉 Markdown 输出。
- 不改写交易判断逻辑。
- 不改变日报入口的采集顺序。
- 不从当前实时数据回补历史 replay。
- 不把候选分层阶梯放进第一屏。
- 不把指数结构缩略图放进第一屏。
- 不把板块周视图合并进当天板块热力分数。

## Non-goals

- HTML 不重新判断买入资格。
- HTML 不把图表缺失伪装成完整证据。
- HTML 不把热榜注意力直接等同于主线确认。
- HTML 不把当天截面和周内节奏合成一个混合分数。
- HTML 不为了交互效果新增每日完整大 JSON 附属文件。

## 完成定义

实现完成后应满足：

- 每日 HTML 第一屏以五类图表为主，文字解释为辅。
- 图 1、图 2 缺关键数据时，HTML 驾驶舱按“关键数据不完整，停止生成”处理。
- 图 3、图 4、图 5 缺数据时，页面可生成，但对应图位显示缺失原因。
- 板块周视图作为下钻区域展示时间脉络，不参与当天热力重复计算。
- 点击日期、板块或 tag 只更新解释面板和关联高亮，不重新计算交易结论。
- 所有文本进入 HTML 前继续转义。
- 图表数据通过安全 JSON 嵌入，不允许 raw HTML 注入。
- 相关测试和至少一次视觉检查通过。

## 总体架构

沿用现有 HTML 日报架构，不另起前端项目：

```text
PSQL 事实 / replay 快照
  -> DailyReportView
  -> charts payload
  -> ECharts HTML 模板
  -> 每日 HTML 图表驾驶舱
```

### `html_report_view.py`

职责：

- 从已有事实组装 `DailyReportView`。
- 新增 `charts` 字段。
- 只整理图表数据，不生成 HTML。
- 不重新推理交易结论。
- 不读取实时源补历史。

建议输出：

```text
view["charts"] = {
  "market_capacity": {...},
  "mainline_turnover_share": {...},
  "sector_heatmap": {...},
  "mainline_attack_scatter": {...},
  "hot_tag_composition": {...},
  "cycle_week_view": {...}
}
```

### `html_report_renderer.py`

职责：

- 渲染 HTML。
- 加载 ECharts。
- 安全序列化图表数据。
- 注入图表容器、解释面板和降级提示。
- 保存 `.html` 文件。

不得做：

- 不查询 PSQL。
- 不重新判断交易结论。
- 不写每日完整大 JSON。

### `daily_report_reader.html`

职责：

- 展示驾驶舱布局。
- 初始化 ECharts。
- 处理悬停、图例开关、点击联动解释面板。
- 在数据缺失时显示缺失提示。
- 保持移动端可读。

## 图表设计

### 1. 市场容量趋势

定位：核心图。

回答：

- 今天市场容量是否支持继续诊断？
- 成交额是否处在可参与区间？
- Top50 成交额占比是否说明资金过度集中或扩散不足？
- 上涨 / 下跌家数是否支持市场继续向前看？

数据来源：

- `total_turnover`
- `top50_turnover_share_series`
- `market_stats.up_count`
- `market_stats.down_count`

图形：

- 柱线组合。
- 成交额用柱。
- Top50 成交额占比用线。
- 上涨 / 下跌家数可作为图例切换线。

交互：

- 悬停显示日期、成交额、Top50 占比、上涨家数、下跌家数。
- 点击日期更新解释面板。

缺失处理：

- 缺少成交额或 Top50 占比序列时，关键数据不完整，停止生成 HTML 驾驶舱。

### 2. 主线成交占比趋势

定位：核心图。

回答：

- 资金是否仍集中在主线？
- 主线成交占比是抬升、回落，还是横向震荡？
- 当前主线和当天主攻线是否一致？

数据来源：

- `turnover_share_trend_rows`
- `mainline_turnover_summary`
- `current_mainline_history_record`

图形：

- 折线图或面积图。
- 按主线名称区分颜色。
- 最近若干交易日按日期排列。

交互：

- 悬停显示日期、周期主线、当天主攻线、主线成交额、两市成交额、占比、占比变化。
- 点击日期或主线更新解释面板。

缺失处理：

- 缺少可用趋势行时，关键数据不完整，停止生成 HTML 驾驶舱。

### 3. 板块热力矩阵

定位：解释图。

回答：

- 今天哪些板块强？
- 强在资金、扩散、涨停、高标还是持续性？
- 哪些板块只是注意力候选？

数据来源：

- 板块资金流。
- 涨停扩散。
- 高标高度。
- 主线攻击证据。
- 板块历史记录。
- 热榜注意力只可作为辅助字段。

图形：

- 行是板块。
- 列建议为：资金、扩散、涨停、高标、持续性、注意力。
- 色阶表达强弱。

交互：

- 点击板块，高亮相关主线攻击证据和热榜 tag 构成。
- 解释面板显示它是主攻线、背景线、掉队线，还是只观察。

重复计算约束：

- 热榜 tag 可以作为“注意力”列。
- 如果板块强度总分已经使用热榜权重，图表必须标注该列只是注意力入口。
- 不允许把同一份热榜数据既计入强度总分，又在页面上当成独立确认。

缺失处理：

- 数据不足时显示缺失原因，不阻止 HTML 生成。

### 4. 主线攻击证据散点

定位：解释图。

回答：

- 为什么这条线是主线？
- 哪些板块具备资金、扩散和强度共振？
- 哪些只是单点活跃？

数据来源：

- `mainline_attack_evidence_summary`
- evidence rows
- 板块净流入
- 涨停数
- 高标高度
- 成交占比变化

图形：

- 横轴：成交占比变化或主线聚焦度。
- 纵轴：资金强度或综合强度。
- 气泡大小：涨停数或高标高度。
- 颜色：主攻线、候选线、背景线、观察线。

交互：

- 悬停显示完整证据。
- 点击气泡联动板块热力矩阵和解释面板。

缺失处理：

- 数据不足时显示缺失原因，不阻止 HTML 生成。

### 5. 热榜 Tag 构成图

定位：解释图。

回答：

- 同花顺热榜前 100 的注意力集中在哪些 tag？
- 哪些 tag 是主叙事？
- 哪些只是辅助、噪音或反证？
- 热榜注意力是否支持板块拆解？

数据来源：

- `tag_distribution`
- `integrated_hot_list`
- `realtime_tag_evidence_snapshot`

图形：

- 首选 treemap 或横向条形图。
- 可表达：

```text
热榜股票 -> tag -> 主 tag / 辅助 tag / 噪音 tag / 反证 tag
```

交互：

- 点击 tag，高亮关联板块和样本股票。
- 点击板块热力矩阵中的板块，显示对应 tag 构成。

计算约束：

- 该图只回答“市场在讲什么”。
- 该图不直接给买入资格。
- 该图不能替代价格、成交、资金和扩散证据。

缺失处理：

- 数据不足时显示缺失原因，不阻止 HTML 生成。

## 板块周视图 / 周期日历

板块周视图不合并进首屏五图。

职责：

- 展示周内主线、当天主攻线、阶段变化和动作演变。
- 解释当前板块处于启动、强化、分歧、退潮还是切换。
- 作为当天热力矩阵的时间脉络下钻。

与板块热力矩阵的关系：

- 板块热力矩阵是当天截面图。
- 周视图是时间演变图。
- 两者可以高亮联动。
- 周视图不反向改写当天热力分数。
- 当天热力矩阵也不把周视图趋势直接当作今日强度。

缺失处理：

- 周视图缺失不影响第一屏。
- 下钻区域显示周期数据不足。

## 页面结构

第一屏：

- 顶部信息条：日期、运行模式、数据来源、生成时间。
- 核心摘要：市场容量、主线成交占比、当前主线、是否继续诊断。
- 主图区域：市场容量趋势、主线成交占比趋势。
- 解释图区域：板块热力矩阵、主线攻击证据散点、热榜 Tag 构成图。
- 解释面板：随点击更新。

下钻区域：

- 板块周视图 / 周期日历。
- 明日动作。
- 参与对象。
- 参与预演复盘。
- 数据来源。
- 运行诊断。

移动端：

- 第一屏先显示核心摘要和两张核心图。
- 解释图按单列纵向排列。
- 图表容器固定高度，避免布局跳动。
- 表格区域保留横向滚动。

## 交互规则

首版采用中交互设计、最小可验证实施：

- 必须支持悬停查看精确数值。
- 必须支持图例显示 / 隐藏。
- 必须支持点击日期、板块或 tag 更新解释面板。
- 点击只做高亮和说明，不重新计算交易结论。
- 移动端可通过点击替代悬停。

暂不做：

- 日期区间筛选。
- 指标自由切换。
- 原始事实表展开。
- 导出 PNG。

这些能力可作为后续增强。

## 数据完整性规则

核心图：

- 市场容量趋势。
- 主线成交占比趋势。

核心图缺关键字段时：

- HTML 驾驶舱停止生成。
- 报告缺失字段。
- 不写半成品 HTML。

解释图：

- 板块热力矩阵。
- 主线攻击证据散点。
- 热榜 Tag 构成图。

解释图缺关键字段时：

- HTML 可生成。
- 对应图位显示缺失原因。
- 数据来源和运行诊断记录缺失项。

历史 replay：

- 只使用目标日期已有事实、官方快照、replay 快照或明确支持目标日期的数据。
- 不使用当前实时数据补历史。
- 如果目标日期缺少核心图事实，按关键数据不完整处理。

## 安全规则

- 所有用户可见文本进入 HTML 前必须 escape。
- 图表 payload 使用 JSON 序列化后放入 `<script type="application/json">`。
- 前端脚本只读取安全 JSON，不拼接 raw HTML。
- 图表 tooltip 文本也必须从安全字段生成。
- URL 展示为链接时，只允许 `http`、`https` 或本地相对路径。

## 实施顺序

1. 扩展 `DailyReportView.charts` 数据契约。
2. 先做两张核心图：市场容量趋势、主线成交占比趋势。
3. 再做三张解释图：板块热力矩阵、主线攻击证据散点、热榜 Tag 构成图。
4. 接入 ECharts 加载、JSON 注入和解释面板。
5. 添加周视图下钻区域，只做高亮联动。
6. 补齐单测和视觉检查。

每一步都要能单独验证。任何一步如果需要新增每日完整大 JSON，必须停止并重新讨论。

## 风险与处理

### 风险 1：图表数据字段暂时不完整

处理：

- 核心图缺失时停止生成。
- 解释图缺失时显示缺失原因。
- 不用实时数据补历史。

### 风险 2：热榜 tag 与板块热力重复计算

处理：

- 热榜 tag 只作为注意力入口。
- 板块热力要区分资金、扩散、涨停、高标、持续性和注意力。
- 页面文案明确：注意力不等于参与资格。

### 风险 3：第一屏过度拥挤

处理：

- 两张核心图占主区域。
- 三张解释图采用紧凑布局。
- 周视图放到下钻区域。
- 移动端单列排列。

### 风险 4：交互扩大范围

处理：

- 首版只做悬停、图例开关、点击解释面板。
- 不做筛选器、原始事实展开或导出。

## 规格自检清单

- 已明确五张首屏图。
- 已明确周视图只做下钻。
- 已明确 ECharts 复用现有加载策略。
- 已明确核心图和解释图的缺失处理差异。
- 已明确热榜 tag 不直接给参与资格。
- 已明确不改交易判断逻辑。
- 已明确不新增每日完整大 JSON。
- 已明确 replay 不使用当前实时数据补历史。
