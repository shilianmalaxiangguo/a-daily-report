# 狙击手视角龙头战法重构设计

## 背景

2026-06-05 日报的“狙击手视角”已经包含 `涨停只是证据，不能替代板块锚和承接路径` 这类规则，但呈现顺序和叙述方式仍然有明显问题：它先展示涨停池、连板、明日预期强度排序，再解释板块锚和龙头资格，读起来像是在涨停股里找龙头。

更大的问题是 Step 本身太像节点流水账。现在的写法按“输入、输出、字段”堆信息，容易把真正的交易判断淹没掉。狙击手视角应该像一条动作链：先判断今天值不值得出手，再确认主线和龙头身份，再复核证据是否撑得住，最后只给明天动作。

用户当前交易口径是龙头战法，但“龙头”不是涨幅最高、涨停最多或连板最多的股票。龙头必须经过主线、板块锚、承接、相对强弱、容量、固定交易窗口和风险边界共同反推。涨停、T 字板、连板只能作为资金表态证据。

最新交易思想还补充了两条会影响最终动作的约束：

1. 短线交易的执行只落在当下。未来大机会、远期价值兑现、新股首日暴涨、题材后续发酵，只能提高观察或研究优先级，不能替代当下价格、量能、板块、资金、辨识度、承接、时间窗口和失效线。
2. 连续盈利后先收紧，不加速。盈利不能自动提高仓位资格，也不能放宽时间窗口、认错线、仓位上限和禁止清单；两笔不符合预演或触发失效后，直接停止新增参与，只观察股池和处理旧仓风险。

## 目标

把“狙击手视角 / 统一执行链 / 推导审计层”从 7 段清单重构为 4 段动作链：

1. 市场是否值得出手。
2. 主线与龙头身份是否清楚。
3. 承接和证据是否撑得住。
4. 明天只做什么。

重构后的日报要满足：

- 龙头资格反推先于涨停、连板和明日预期强度排序。
- 每个 Step 只回答一个交易问题，先给结论，再给证据。
- 主链不铺长表，不列满所有候选，只展示会影响最终动作的事实。
- 未来叙事只提高观察或研究优先级，不直接生成参与动作。
- 连续盈利后的顺境收紧、两笔不符合预演、股池强者接连走弱，必须影响最终动作。

## 范围

### In Scope

- 重构“狙击手视角 / 统一执行链 / 推导审计层”的 Step 结构。
- 把旧的 Step 0-6 压缩为新的 Step 1-4。
- 调整 Markdown 输出顺序和用户可见标题。
- 限制每个 Step 的叙述长度和候选数量。
- 保留现有交易规则，只改变呈现主次和判断落点。
- 对 2026-06-05 replay 日报重新生成 HTML，用真实样例验证读感。
- 增加回归测试，防止涨停强度和明日预期排序再次前置。

### Out of Scope

- 不重构 HTML 阅读器样式。
- 不改变 PostgreSQL-first 存储路径。
- 不生成日报附属大体积数据文件。
- 不新增任何日报附属数据导出物。
- 不改变用户已有交易规则本身。
- 不重新采集历史行情数据。

### Non-goals

- 不把所有涨停股都降级为无意义样本。涨停仍是重要证据，但只能在龙头资格反推之后使用。
- 不取消 T+1 混合龙头。它仍然适用于强核心，但不能扩展到普通后排。
- 不把“板块锚”机械等同于唯一可参与对象。分支龙头、大容量中军可以保留比较资格，但必须说明为什么不做锚。

## 现有问题

当前日报里，“Step 1 - 明天观察池”先展示主线趋势密度、明日预期强度排序、异动后观察池和龙头记忆；“Step 2 - 明日核心标的”才展示跨线观察候选、重点观察名单和板块锚反推细节。

这个顺序有三层问题：

1. 先看涨停和预期强度，再看板块锚，读者会被速度和涨幅牵着走。
2. 每个 Step 都像把节点结果摊开，不像给交易动作做收缩。
3. 候选越列越多，最后反而看不清“明天到底做不做、做谁、什么条件作废”。

## 新 Step 结构

### Step 1：市场是否值得出手

回答的问题：今天的市场环境，是否允许继续向下找参与对象？

用户可见输出只保留三类信息：

- `结论`：不做新仓、只观察、可继续筛选、可等窗口参与。
- `理由`：最多三条，只写涨跌家数、成交额、主线强度、亏钱效应中最关键的事实。
- `影响`：如果市场不支持出手，后续个股全部先降为观察对象或旧仓处理。

叙述要求：

- 不铺指数、涨跌家数、涨跌停、成交额的长段解释。
- 不把市场底色写成宏观复盘。
- 如果结论是不做新仓，后面 Step 只能解释“为什么观察”，不能再把候选包装成执行对象。

### Step 2：主线与龙头身份是否清楚

回答的问题：资金主战场在哪里，谁是板块锚、总龙或容量中军？

用户可见输出只保留四类信息：

- `主线`：主攻线、竞争线、轮动脉冲、无主线。
- `锚点`：板块锚、总龙、趋势比价链锚点、容量中军。
- `候选关系`：就是锚、分支龙头、容量中军、低位补涨、跟风样本、观察样本。
- `不做锚原因`：候选不是锚时，用一句话说明为什么不能替代锚。

叙述要求：

- 主链最多展示 3 个候选，其余进入附录或不展示。
- 没有确认主攻线时，不列满所有活跃题材，只写最强竞争线和失败原因。
- 个股统一用代码样式，例如 `大有能源(600403)`，避免正文和股票名称混在一起。
- 明日预期强度排序不得出现在本 Step 之前。

### Step 3：承接和证据是否撑得住

回答的问题：候选的价格行为，是否支撑 Step 2 给出的身份？

用户可见输出只保留四类信息：

- `承接`：分歧后是否有人接，是否收回关键线。
- `强弱`：相对指数、相对板块、相对同池候选是否占优。
- `容量`：成交额、换手和资金承载是否匹配龙头身份。
- `速度证据`：涨停、连板、T 字板、一字板、光头大阳线。

叙述要求：

- 涨停、连板、T 字板只能作为最后一类证据，不直接生成龙头身份。
- 每个候选只输出一个结果：强化、保留观察、降级、剔除。
- 每个候选最多写两条关键证据，避免长篇解释。
- 如果候选没有通过板块锚反推，速度证据只能提高观察优先级。

### Step 4：明天只做什么

回答的问题：明天到底参与、不参与、观察，还是只处理旧仓？

用户可见输出只保留四类信息：

- `动作`：参与、不参与、观察对象、旧仓处理、空仓等待。
- `触发`：固定交易窗口内，当下价格、量能、板块、资金、辨识度、承接和失效线同时成立。
- `作废`：跌破哪条线、哪个承接失败、哪个时间窗口失效。
- `纪律`：未来叙事与顺境收紧如何影响动作。

叙述要求：

- 只给明日唯一主动作；备用动作最多一条。
- 未来大机会、远期价值、新股暴涨想象、题材后续发酵，只能写成观察或研究理由。
- 连续盈利后先复核仓位、窗口、失效线和禁止清单，不因手感放宽条件。
- 两笔不符合预演或触发失效后，新候选只观察；股池强者接连走弱时，只处理旧仓风险。

## 报告结构建议

新的“狙击手视角”主结构：

```text
### 附录：十三、统一执行链（狙击手视角）

#### Step 1 - 市场是否值得出手
结论：...
理由：...
影响：...

#### Step 2 - 主线与龙头身份是否清楚
主线：...
锚点：...
候选关系：...
不做锚原因：...

#### Step 3 - 承接和证据是否撑得住
候选：...
结果：强化 / 保留观察 / 降级 / 剔除
证据：...

#### Step 4 - 明天只做什么
动作：...
触发：...
作废：...
纪律：...
```

旧标题收敛方式：

| 旧内容 | 新位置 |
|---|---|
| 市场底色、指数、涨跌家数、成交额 | Step 1 |
| 主线趋势密度、主线竞争、龙头记忆 | Step 2 |
| 板块锚反推、为什么不做锚、角色分层 | Step 2 |
| 重点观察名单、跨线观察候选中的身份关系 | Step 2 |
| 重点观察名单、跨线观察候选中的承接证据 | Step 3 |
| 分歧后承接、相对强弱、成交容量 | Step 3 |
| 涨停池、连板、T 字板、明日预期强度排序 | Step 3 |
| 固定交易窗口、账户状态、失败仓处理 | Step 4 |
| 当下执行、未来叙事、顺境收紧 | Step 4 |

## 叙述压缩规则

- 每个 Step 必须先有结论，再有证据。
- 每个 Step 主体最多 3 条证据，超过则进附录。
- 主链最多出现 3 个个股候选；超过说明已经不适合放在狙击手视角主链。
- 不再使用“输入 / 输出”作为日报用户可见结构。
- 不写“可能、也许、如果很多条件都满足”式长句；条件不清楚就写观察。
- 不把明日预期、涨停速度、题材想象写在板块锚之前。
- 失败原因比热闹事实更重要；如果不参与，要先写不参与的原因。
- 2026-06-05 这类市场收缩日，主链应更短，而不是因为候选很多就写得更长。
- 附录只保留事实来源、回归验证和必要明细，不能把主链压缩掉的长候选清单恢复到附录。

## 主链判定口径

这不是要求加字段。实现应优先复用现有内部字段，只在无法表达四段动作链时补最少字段。用户可见主链只围绕以下判定口径组织：

| 字段 | 含义 |
|---|---|
| `market_action_status` | 不做新仓、只观察、可继续筛选、可等窗口参与 |
| `mainline_status` | 主攻线、竞争线、轮动脉冲、无主线 |
| `sector_anchor` | 板块锚、总龙、趋势比价链锚点或容量中军 |
| `candidate_role` | 候选与锚点的关系 |
| `anchor_gap_reason` | 候选不能替代锚的原因 |
| `acceptance_verdict` | 承接是否成立 |
| `evidence_verdict` | 速度证据对候选是强化、保留观察、降级还是剔除 |
| `future_projection_role` | 未来叙事只能是观察或研究理由 |
| `discipline_status` | 顺境收紧、两笔不符合预演、股池强者走弱等纪律状态 |
| `action_window` | 固定交易窗口 |
| `invalid_line` | 作废条件 |
| `final_action` | 参与、不参与、观察对象、旧仓处理、空仓等待 |

字段约束：

- `future_projection_role` 不能直接把候选升级为 `参与`。
- `market_action_status` 为不做新仓时，`final_action` 不能输出新增参与。
- `candidate_role` 未通过板块锚反推时，速度证据只能影响观察优先级。
- `discipline_status` 为收紧、停止新增参与或股池强者走弱时，`final_action` 只能是观察、旧仓处理或空仓等待。

## 2026-06-05 样例期望

重构后，2026-06-05 的狙击手视角应读成更短的动作链：

1. Step 1：市场收缩防守，赚钱效应不足，结论是不做新仓。
2. Step 2：无确认主攻线，多方向局部活跃但资金未明显胜出；先找板块锚，不先看涨停强度。
3. Step 3：`大有能源(600403)`、`泰坦股份(003036)`、`凤凰航运(000520)` 等涨停/连板样本只能作为证据池和观察样本；若无法说明为什么比 `兆易创新(603986)` 等板块锚更值得参与，就不能进入执行对象。
4. Step 4：`宇环数控(002903)` 只保留观察对象身份；即使有明日加速想象，也要等第二天当下承接、固定窗口和失效线；最终仍是 0% 不参与。

## 风险

- 这是主链路改动，不应混入 HTML 样式调整。
- 现有测试可能断言旧标题，需要同步更新。
- 压缩主链后，部分细节需要保留在附录或内部字段中，不能直接丢掉事实来源。
- 旧日报 replay 不应按实时数据重采，只能用已有 replay、Markdown 或 PostgreSQL 事实验证。

- 中文 spec 通过自检，无占位符、无矛盾要求。

- 新日报输出中，未来预期只能作为观察或研究理由，当下事实未成立时不得生成参与动作。
