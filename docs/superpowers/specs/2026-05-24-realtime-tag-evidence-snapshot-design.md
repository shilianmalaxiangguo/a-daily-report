# Realtime Tag Evidence Snapshot Design

## Summary

日报里的行业、概念、板块和 tag 不能各自独立判断。第一版要新增一层共享的 `实时tag证据快照`：所有热榜、行业、概念、资金流、雪球 AI 解释、东方财富 label、公告和问董秘反证，先进入同一张证据网，再由主线判断、板块资金流、DeepSeek 分析、候选股质量和日报文案共同消费。

目标不是多加一个展示区，而是让日报前后使用同一套交易口径。比如同一天出现 `半导体`、`芯片`、`元器件`、`国产芯片替代`、`PCB电子材料` 时，系统必须先判断它们是父子关系、同义关系、细分分支，还是互相冲突，然后再决定日报采用哪个名称、哪些名称只作为表层行业或辅助解释。

## In Scope

- 新增一个共享的 `实时tag证据快照` 运行时产物。
- 统一归并行业、概念、板块、热榜 tag 和个股 label。
- 把 `半导体 / 芯片 / 元器件 / PCB / CPO / MLCC / 国产芯片替代` 等电子链标签拆成大方向、细分分支和表层名称。
- 让主线判断、板块资金流、DeepSeek 板块分析、候选股质量和日报渲染优先消费同一份 tag 快照。
- 在日报里输出中文字段化结论，说明采用名称、未采用名称及原因、资金证据、注意力证据、扩散证据和反证信息。
- 保留现有 `sector_narrative_alias.py` 的有效能力，但把它升级为共享 tag 证据快照的一部分，而不是孤立别名工具。
- 修正旧逻辑里把 `元件/电子元件` 直接等同于 `半导体` 的路径；只有出现分支证据时，才允许归入 `泛半导体/硬科技电子`。

## Out Of Scope

- 不做 snap-ui 页面或交互改动。
- 不在第一版实现 SQLite 或 Postgres 历史 tag 池。
- 不重写完整候选股评分、仓位、止损和买卖点策略。
- 不重写全部 DeepSeek 调用框架。
- 不把 tag 热度直接变成买点。
- 不让雪球 AI 解释覆盖公告、问董秘和互动易反证。

## Non-goals

- 不追求把所有概念一次性归入完整行业图谱。
- 不用单一热榜、单一资金流、单一 LLM 结论确认主线。
- 不把行业大词当真实交易分支。
- 不把一个股票的所有概念平均加分。
- 不把报告写成一堆英文内部字段。
- 不让新 tag 层产生第二套与主线系统并行的判断口径。

## Done Definition

- 存在一个可测试的 tag 证据快照构建函数，输入现有日报数据，输出统一的中文字段化结果。
- `半导体 / 芯片 / 元器件` 的关系能够被解释为大方向、细分分支、表层行业或冲突项。
- `元器件/元件/电子元件/电子元器件` 在缺少 PCB、CPO、MLCC、芯片、先进封装等分支证据时，不被强行归入半导体。
- 主线判断和 DeepSeek 板块分析至少消费同一份 tag 快照，不再分别拿原始散标签自由判断。
- 日报可见文案使用中文字段：`周期主线`、`当日主攻分支`、`表层行业名`、`采用名称`、`未采用名称及原因`、`资金证据`、`注意力证据`、`扩散证据`、`反证信息`。
- 测试覆盖电子链归并、元器件保守归因、消费电子独立分支、资金流与主线名称统一、DeepSeek 上下文包含 tag 快照。

## Problem

当前日报已经有正确的 wiki 口径，也有 `sector_narrative_alias.py` 这样的局部归并能力，但它还不是全链路共享的证据层。因此不同模块可能出现以下割裂：

- 主线写 `半导体`，资金流写 `芯片`，候选股理由写 `元器件`。
- 同一个方向在热榜、资金流、雪球解释和日报正文里被写成不同名字。
- `元件/电子元件` 旧逻辑直接归成 `半导体`，但真实交易可能是 PCB、MLCC、CPO、消费电子或普通电子制造。
- DeepSeek 拿到的是散标签，容易按语言相似度归类，而不是按当日资金选择和反证证据归类。
- 候选股带有很多概念时，评分容易把主 tag、辅助 tag、噪音 tag 和反证 tag 混在一起。

所以第一版要先解决“同一份证据、同一套命名、同一条交易解释链”。

## Data Sources

`实时tag证据快照` 第一版读取已经进入日报数据包的来源，不新增重型外部抓取：

| 来源 | 用途 |
|---|---|
| 同花顺/淘股吧热榜 | 注意力入口，识别市场正在看的股票和初步概念 |
| 雪球 A 股热榜 | 社区注意力补充，判断是否与热榜共振 |
| 雪球 AI 解释 | 当前炒作理由候选，识别资金正在讲什么故事 |
| 东方财富 label | 细分标签补全，例如 CPO、PCB、MLCC、数据中心、液冷、AI眼镜 |
| 行业资金流 | 大行业资金方向 |
| 概念资金流 | CPO、PCB、芯片替代等细分概念资金方向 |
| 涨停池/强势股/成交额 | 扩散、核心承接和价格反馈 |
| 公告/问董秘/互动易/风险事件 | 判断炒作理由是否被事实压缩 |

任一注册因子失败时，日报仍按现有规则停止生成，不能用缺失数据继续输出看似完整的 tag 结论。

## Snapshot Structure

每个 tag 组输出一条中文字段化记录：

| 字段 | 含义 |
|---|---|
| `采用名称` | 日报最终使用的方向名 |
| `大方向` | 更高层级，例如 `泛半导体/硬科技电子`、`AI算力基础设施`、`AI终端/消费电子` |
| `当日主攻分支` | 当日真正被资金选择的细分分支，例如 `国产芯片替代`、`PCB电子材料`、`光通信/CPO` |
| `表层行业名` | 原始行业或概念名，例如 `元器件`、`半导体`、`芯片` |
| `辅助名称` | 能帮助理解但不是发动机的标签 |
| `噪音名称` | 历史挂靠、静态概念或当日资金没有选择的标签 |
| `反证信息` | 公告、问董秘、互动易或风险事件对当前炒作理由的压缩 |
| `资金证据` | 净流入、成交占比、概念资金聚合等 |
| `注意力证据` | 热榜、雪球热榜、雪球 AI 解释 |
| `扩散证据` | 涨停扩散、核心票承接、强势股数量 |
| `关系判断` | 同义、父子、分支、冲突、证据不足 |
| `未采用名称及原因` | 为什么不在日报主文采用某些表层名 |

内部实现可以继续使用英文变量名，但日报、日志摘要和用户可见文案必须渲染为中文字段。

## Tag Relationship Rules

### 电子链

`泛半导体/硬科技电子` 是大方向，不直接等于所有电子类标签。

允许进入该大方向的分支证据包括：

- `国产芯片替代`
- `存储/芯片`
- `先进封装`
- `半导体设备/材料`
- `PCB/电子材料`
- `光通信/CPO`
- `被动元件/MLCC`

`元器件/元件/电子元件/电子元器件` 是表层行业名。只有同时出现上述细分分支证据，才允许提升到 `泛半导体/硬科技电子`。否则保留为表层行业，不强行讲成半导体。

### AI 算力与电子链

`数据中心/液冷服务器/英伟达概念` 优先归入 `AI算力基础设施`，但如果同一天出现 PCB、CPO、先进封装、芯片等证据，要保留多分支：

- 大方向可以是 `AI算力基础设施`
- 细分供应链可以是 `PCB电子材料`、`光通信/CPO`、`先进封装`
- 日报要说明谁是当日发动机，谁只是供应链辅助

### 消费电子

`消费电子/苹果概念/AI眼镜/AI PC/智能穿戴` 默认归入 `AI终端/消费电子`，不自动塞进半导体。只有存在 CPO、PCB、芯片等硬科技分支证据时，才作为多分支保留。

### 冲突处理

如果热榜、资金流和雪球解释指向不同方向，不强行合并。输出：

- `关系判断：冲突`
- `采用名称：证据最强的方向，或暂无确认主攻分支`
- `未采用名称及原因：资金不足、扩散不足、只属于表层行业、被公告反证`

## Report Integration

第一版至少接入四个消费点：

### 主线判断

主线判断不直接读取散标签，而是读取 tag 快照里的：

- `采用名称`
- `当日主攻分支`
- `资金证据`
- `扩散证据`
- `关系判断`
- `反证信息`

如果 tag 快照显示只是表层行业活跃，不能直接写成周期主线。只有资金、扩散、核心承接和反证共同支持，才写成主攻分支或周期主线。

### 板块资金流

板块净流入和概念净流入要先经过 tag 快照归并。

示例：

- 行业净流入：`元器件`
- 概念净流入：`芯片替代`、`PCB`
- 热榜解释：`国产替代`

日报应输出：

- `采用名称：国产芯片替代`
- `大方向：泛半导体/硬科技电子`
- `表层行业名：元器件 / 芯片 / 半导体`
- `资金证据：行业资金和概念资金共同指向电子链分支`

### DeepSeek 分析

DeepSeek 输入不再只给散标签列表，而是给 tag 快照摘要，让它回答：

- 这些名称是同义、父子、分支还是冲突。
- 当前采用名称是否合理。
- 是否存在需要保留的未采用名称。
- 是否有反证命中当前主 tag。

DeepSeek 只能做归纳和解释，不覆盖资金、扩散和公告事实。

### 候选股质量

候选股不再因为“有很多概念”加分，而是先判断：

- 它是否属于当日主攻分支。
- 主 tag 是否被资金选择。
- 辅助 tag 是否增强逻辑。
- 噪音 tag 是否只是历史挂靠。
- 反证信息是否命中当前上涨发动机。

日报里的 `明日极度看好` 必须说明候选股依赖哪个主 tag，以及该 tag 明日继续成立需要什么证据。

## Example Output

当日原始标签出现：

- `半导体`
- `芯片`
- `元器件`
- `PCB`
- `国产芯片替代`
- `AI算力`

tag 快照可输出：

| 字段 | 内容 |
|---|---|
| 周期主线 | 泛半导体/硬科技电子 |
| 当日主攻分支 | 国产芯片替代 |
| 表层行业名 | 半导体 / 芯片 / 元器件 |
| 采用名称 | 国产芯片替代 |
| 未采用名称及原因 | 元器件只是表层行业；AI算力只作为供应链辅助，资金主攻未完全指向算力基础设施 |
| 资金证据 | 芯片和 PCB 概念资金强于表层行业名 |
| 注意力证据 | 热榜和雪球解释共同指向国产替代 |
| 扩散证据 | 同分支多只核心票上涨，非单票孤立 |
| 反证信息 | 暂无命中主 tag 的公告或问董秘反证 |

日报正文采用：

`今日电子链不是简单的元器件行业上涨，资金和注意力更集中在国产芯片替代分支；元器件只作为表层行业名保留，主攻分支仍需看芯片/PCB核心票明日承接。`

## Implementation Notes

建议新增或扩展一个纯函数模块，例如：

```text
scripts/knowledge/realtime_tag_evidence_snapshot.py
```

核心函数：

```text
build_realtime_tag_evidence_snapshot(data) -> dict
```

它可以复用：

- `build_sector_driver_tag_profile`
- `resolve_sector_narrative_label`
- `merge_sector_evidence_rows_by_narrative`

但输出要比别名归并更完整：不仅返回名称，还返回证据、关系、采用原因和未采用原因。

第一版不需要写入数据库，只把结果挂到日报数据包，例如：

```text
data["realtime_tag_evidence_snapshot"]
```

后续 SQLite 版本再补充 `date`、`source`、`stock_code`、`tag`、`tag_layer`、`driver_role`、`evidence_text`、`evidence_score`、`contradiction_level`、`updated_at`。

## Test Plan

新增或扩展测试：

| 测试 | 目标 |
|---|---|
| `test_realtime_tag_evidence_snapshot.py` | 验证 tag 快照构建、字段输出和关系判断 |
| `test_sector_narrative_alias.py` | 修正元件直接归半导体的旧路径 |
| `test_market_activity_infer.py` | 验证 market activity 消费 tag 快照 |
| `test_mainline_turnover_summary_runtime.py` | 验证主线判断名称来自 tag 快照 |
| `test_llm_service.py` 或相关板块分析测试 | 验证 DeepSeek 上下文包含 tag 快照摘要 |
| `test_report_runtime.py` | 验证日报可见字段为中文，且主线、资金流、候选理由名称一致 |

关键样本：

- `半导体 + 芯片 + 国产替代` 应归为 `泛半导体/硬科技电子` 下的 `国产芯片替代`。
- `元器件` 单独出现时保留为表层行业，不强行归半导体。
- `元器件 + PCB + 电子布` 应归为 `PCB/电子材料` 分支。
- `消费电子 + AI眼镜` 应归为 `AI终端/消费电子`，不自动归半导体。
- `数据中心 + 液冷 + PCB` 应保留 `AI算力基础设施` 与 `PCB电子材料` 的多分支关系。
- 公告或问董秘否认当前炒作理由时，候选质量下降，不能作为盘中加仓理由。

## Acceptance Checks

- 报告不能同一天一处写 `半导体`、一处写 `芯片`、一处写 `元器件`，却没有解释它们的关系。
- 不能把 `元器件` 这种表层行业直接写成主攻分支。
- 不能让 DeepSeek 自由改写资金和公告事实。
- 不能让雪球 AI 解释替代公司事实。
- 不能把概念数量当成候选股质量。
- 不能因为缺少某个数据源，就继续生成完整 tag 判断。
- 日报可见字段必须是中文。
