# 超车窗口判断设计

## Summary

日报已经能识别主线攻击证据：资金净流入、涨停扩散、高标强度、成交占比扩张等。但这些证据主要回答“谁在进攻”，还缺少一个更贴近实战的判断：什么时候从观察切到主动寻找参与资格。

本设计新增 `超车窗口判断`。它的核心不是“我方最强”，而是“对手开始失速，我方仍能保持节奏”。对应短线和超短线，就是旧主线、竞争线或昨日强方向出现承接变差、冲高回落、扩散断掉时，当前方向仍有资金扩散、核心承接和强度反馈。此时才是从观察进入参与候选的窗口。

## In Scope

- 定义 `overtake_window_summary` 的结构化字段。
- 在 `主线攻击证据` 之后、`明日动作` 之前新增一张很小的前台表。
- 用已有数据判断对手是否失速、我方是否稳住、失速差是否拉开。
- 将输出收束到方向资格：`超车窗口打开`、`等待二次确认`、`仅观察`、`不参与`。
- 保持现有主线攻击证据、主线容量与格局判断、候选质量评分不被重写。

## Out Of Scope

- 不新增外部数据源。
- 不重写个股评分、仓位、止损和执行链。
- 不把趋势容量、短线接力、量化轮动、机构抱团扩成多套策略。
- 不把超车窗口直接等同于新增参与动作。
- 不新增 snap-ui 页面。

## Non-goals

- 不预测明天一定延续。
- 不用单一净流入、单一涨停、单一高标或单一创新高确认超车窗口。
- 不为了制造动作而强行找对手失速。
- 不把一次成功样本写成固定公式。

## Done Definition

- `market_research_snapshot` 或 `mainline_turnover_summary` 中出现 `overtake_window_summary`。
- 前台在 `主线攻击证据` 下方展示 `超车窗口判断` 小表。
- 表格能够解释四类样本：超车窗口打开、等待二次确认、仅观察、不参与。
- `超车窗口打开` 只给方向内寻找参与资格，不直接生成主买或补位。
- 相关单测覆盖确认主攻线、候选线、混沌轮动、无主线四类输入。

## Problem

当前日报容易做到“看到强”，但还缺少“什么时候该主动”的最后一扣。

主线攻击证据能说：

`半导体资金净流入靠前，涨停和高标更集中，成交占比扩张。`

但它没有明确回答：

- 旧方向是否开始掉队？
- 竞争方向是否已经冲不动？
- 当前方向是在大家一起弱里相对少跌，还是在分歧中仍能扩散？
- 这个差值是否足够让明日动作从观察升到方向内找参与资格？

所以新增判断顺序：

1. 先看对手是否失速。
2. 再看我方是否稳住。
3. 再看失速差是否拉开。
4. 最后决定明日动作落点。

## Glossary

| 术语 | 含义 |
|---|---|
| 对手失速 | 旧主线、竞争线、昨日强方向或多头候选方向出现承接变差、扩散断掉、冲高回落、资金撤离 |
| 我方稳住 | 当前方向仍有资金扩散、核心承接、涨停/高标/创新高反馈或成交占比扩张 |
| 失速差 | 不是大家一起弱，而是其他方向开始掉队，当前方向仍保持节奏 |
| 超车窗口 | 失速差拉开后，允许只在当前方向核心里寻找参与资格 |

## Data Shape

新增摘要：

```python
{
    "window_state": "open",
    "primary_line": "半导体",
    "rival_slowdown": "旧主线承接转弱，竞争线冲高回落",
    "own_stability": "半导体资金扩散，核心承接稳定",
    "speed_gap": "失速差拉开",
    "action": "只在半导体核心里找参与资格",
    "evidence_labels": ["对手失速", "我方稳住", "失速差拉开"],
    "evidence_gaps": [],
}
```

允许的 `window_state`：

| 状态 | 条件含义 | 动作 |
|---|---|---|
| `open` | 对手失速 + 我方稳住 + 当前方向已有主线攻击证据 | 只在当前方向核心里找参与资格 |
| `confirm_next` | 对手失速或我方稳住只完成一侧，另一侧待次日确认 | 等竞价、开盘承接、回封或60分钟确认 |
| `observe` | 只有局部迹象，没有形成失速差 | 仅观察，不给新增参与资格 |
| `no_trade` | 对手失速但我方也失速，或全市场同步走弱 | 不参与，先防风险 |

## Evidence Rules

### 对手失速

可由以下已有证据归纳：

- 旧主线不再是 `confirmed_attack`。
- 竞争线只剩候选证据或资金确认不足。
- 多方向局部活跃但资金未明显胜出。
- 旧方向成交占比回落、净流入转弱、涨停扩散断掉。
- 市场出现放量杀跌、冲高回落、跌停扩散时，除非当前方向有明显逆势承接，否则不算超车。

### 我方稳住

必须至少满足资金侧和强度侧各一项：

- 资金侧：资金净流入靠前、资金净流入明显领先、成交占比扩张。
- 强度侧：批量涨停、高标强度突出、板块普涨、高涨幅集群、创新高方向反馈。
- 承接侧：核心票分歧后仍有承接，后排没有全部掉队。

### 失速差拉开

只有在“对手失速”和“我方稳住”同时成立时才写 `失速差拉开`。如果只是我方单日强，但旧方向没有退，写 `等待二次确认`。如果只是旧方向弱，但新方向也没有扩散，写 `不参与`。

## Front-Surface Output

位置：`### 4. 主线容量与格局判断` 里的 `主线攻击证据` 表后面。

示例：

```markdown
#### 超车窗口判断
| 对手失速 | 我方稳住 | 失速差 | 明日动作 |
|---|---|---|---|
| 旧主线承接转弱，竞争线冲高回落 | 半导体资金扩散，核心承接稳定 | 失速差拉开 | 只在半导体核心里找参与资格 |
```

无窗口示例：

```markdown
#### 超车窗口判断
| 对手失速 | 我方稳住 | 失速差 | 明日动作 |
|---|---|---|---|
| 多方向都有局部热度 | 当前方向强度不足 | 未拉开 | 仅观察，不给新增参与资格 |
```

## Integration Points

### Runtime

优先在 `scripts/domains/market_state/mainline_turnover_summary_runtime.py` 增加：

- `build_overtake_window_summary(...)`
- 从 `mainline_attack_evidence_summary`、`mainline_capacity_regime_summary`、`turnover_share_trend_rows`、`current_mainline_history_record` 读取已有证据。

不要直接从渲染层拼判断，避免前台和执行链不一致。

### Rendering

在 `scripts/report/market_research_snapshot_nodes.py` 增加：

- `_build_overtake_window_table_lines(context)`
- 在 `_build_mainline_attack_evidence_table_lines(context)` 后追加表格。

### Decision Board And Execution Chain

第一版不改主买、补位、仓位。只允许已有文案读取 `overtake_window_summary.action`，把“主攻线领涨”修成更精确的方向资格语言：

- `超车窗口打开：只在半导体核心里找参与资格`
- `超车窗口未打开：候选只观察`

### Decision Ledger

第一版不强制写账本字段。后续可以扩展：

- `signal_chain`
- `rival_slowdown`
- `own_stability`
- `overtake_window_state`
- `day_1_window_result`
- `day_3_window_result`
- `day_5_window_result`

## Acceptance Samples

| 样本 | 输入特征 | 期望状态 |
|---|---|---|
| 超车窗口打开 | 一个方向 confirmed_attack，旧方向资金和强度回落，竞争线冲高回落 | `open` |
| 等待二次确认 | 新方向 confirmed_attack，但旧方向仍有回流或背景线未退 | `confirm_next` |
| 仅观察 | 多方向都有局部证据，没有明显胜出 | `observe` |
| 不参与 | 旧方向失速，新方向没有资金和强度扩散，全市场同步走弱 | `no_trade` |

## Acceptance Checks

- 不能只因为当前方向强就写超车窗口打开。
- 不能只因为旧方向弱就写超车窗口打开。
- `open` 必须同时有对手失速、我方稳住、失速差拉开。
- 放量杀跌日的局部强方向默认先按 `confirm_next` 或 `observe`，除非核心承接和扩散连续成立。
- 前台动作只写方向资格，不写直接参与。
