# 日报反推龙头选股工作流设计

日期：2026-06-08

## 背景

当前日报已经有板块锚反推、候选追踪、贝叶斯诊断、双层日报和狙击手视角等模块，但它们更像多个分散节点各自给结论。结果是：日报能写出很多事实，却不能稳定回答“这只股票从哪来、经过哪些筛选、为什么最后是它”。

用户要的不是在涨停池里挑最强股票，也不是给候选补一段解释。真正需要的是一条类似 Dify 的工作流链条：每个节点只消费上一节点结论，输出下一节点能继续使用的结构化结果。最终标的必须从市场、资金、板块关系、板块内角色、反推龙头和执行条件依次推出，而不是从已有候选池里事后挑一个再解释。

本设计把旧的分散模块收束为内部 `selection_workflow.v1`。它不引入外部 Dify 系统，只在日报内部建立固定节点、固定输入输出和固定候选生命周期。

## 目标

第一版目标是让日报稳定回答五个问题：

1. 这只股票最早从哪个数据或节点进入？
2. 它为什么进入同一个诊断池？
3. 它经过市场、资金、板块、角色、反推和执行条件时分别发生了什么？
4. 为什么不是其他候选？
5. 最后为什么是唯一执行对象，或为什么没有执行对象？

日报最终只能输出：

- `0%不参与`
- `50%条件执行`
- `100%核心进攻`

不得恢复旧多档仓位或其他仓位表达。

## 范围

### In Scope

- 定义 `selection_workflow.v1` 的节点顺序、输入、输出和候选生命周期。
- 把现有市场分析、资金分析、板块分析、超车/失速/窗口、板块锚反推、候选追踪和最终对象解析收束到同一条链。
- 保留已有数据结论，但统一进入工作流节点证据，不再让多个模块各自生成最终对象。
- 规定 `final_target_resolution`、首页、推导层、候选追踪和流程图只能消费工作流最终结果。
- 规定涨停池、连板、T 字板、热榜、历史记忆只能作为候选来源或后置证据。
- 设计候选流水账表，解释每只股票从哪里来、在哪一步保留或淘汰、为什么最后胜出或出局。
- 设计 replay 验证，优先覆盖 2026-06-04 和 2026-06-05。

### Out of Scope

- 不接入外部 Dify、n8n 或其他工作流平台。
- 不重写全部数据采集器。
- 不恢复废弃前端发布、旧本地库或旧外部分发路径。
- 不改 HTML 阅读器样式。
- 不新增仓位层级。
- 不把旧评分全部删除；旧评分只降级为证据输入。
- 不使用当前实时数据回填历史 replay。

### Non-goals

- 不做“涨停强度排序换皮”。
- 不把板块强直接等同于个股可参与。
- 不让任一旧候选字段绕过工作流生成最终对象。
- 不为了主链变短而删除现有重要数据结论；详细事实可以进入节点证据和候选流水账。
- 不输出多个最终执行对象。

## 设计原则

### 1. 先主线，后个股

个股只能在市场、资金和板块关系明确之后出现。日报不能先给股票，再回头找理由。

正确顺序是：

```text
市场情况
  -> 资金方向
  -> 板块关系
  -> 板块内角色
  -> 反推龙头
  -> 候选对照
  -> 仓位与执行对象
```

### 2. 每个节点只传递自己能证明的东西

- 市场节点只能说明今天是否允许继续诊断。
- 资金节点只能说明资金集中、分散或撤退。
- 板块节点只能说明哪条线更强、哪条线失速、哪里有窗口。
- 角色节点只能说明板块内谁是总龙、板块锚、容量中军、弹性先锋或补涨。
- 反推节点才能把角色映射到具体股票。
- 执行节点才能给出 0%、50% 或 100%。

### 3. 涨停只是证据，不是入口结论

涨停池可以让股票进入候选池，但不能直接决定它是龙头。涨停、连板、T 字板、一字板、光头大阳线只说明资金有表态，不能替代板块锚、容量、承接、主线地位和执行窗口。

### 4. 候选必须有生命周期

每只股票必须能追踪：

```text
首次来源 -> 进入理由 -> 所属主线 -> 板块角色 -> 反推结论 -> 对照结果 -> 最终动作
```

如果股票中途消失，日报必须说明它在哪一步被淘汰，不能让它从正文里静默消失。

### 5. 一个最终结论

首页、最终对象、行动计划、推导层、候选追踪和流程图必须使用同一个工作流最终结果。任何章节不得重新选股。

## 工作流节点

### N0：数据封装

目的：证明日报使用的是同一天、同一批事实。

输入：

- `target_date`
- PostgreSQL 事实、官方快照或 replay 快照。
- 市场、资金、板块、个股、风险、账户相关事实。

输出：

- `source_date`
- `target_date`
- `data_completeness`
- `available_fact_groups`
- `missing_fact_groups`

不能推出：

- 不能选股。
- 不能给仓位。

### N1：市场周期判断

目的：判断当天市场是否允许继续寻找执行对象。

输入：

- 指数涨跌。
- 涨跌家数。
- 两市成交额。
- 涨停和跌停扩散。
- 赚钱效应。
- 市场周期：启动、发酵、高潮、退潮、冰点。

输出：

- `market_cycle`
- `market_participation_bias`
- `allowed_position_ceiling`
- `passes_forward`

输出只能是：

- `停止诊断，0%不参与`
- `只允许观察或旧仓处理`
- `允许继续向主线和板块诊断`

不能推出：

- 不能指定个股。
- 不能因为指数强就直接给 100%。

### N2：资金方向判断

目的：判断资金是在集中进攻、分散轮动，还是撤退。

输入：

- 市场成交额和成交趋势。
- 主线成交额占比。
- 板块资金流向。
- 高成交核心股反馈。
- 热榜和异动只作为注意力来源。

输出：

- `fund_flow_state`
- `primary_fund_direction`
- `secondary_fund_directions`
- `fund_conflicts`
- `passes_forward`

不能推出：

- 不能把资金净流入最大的个股直接当最终对象。
- 不能用小中盘资金阈值解释超大容量核心。

### N3：板块关系拆解

目的：回答市场上正在发生什么，以及板块之间谁超车、谁失速、哪里有窗口。

输入：

- N1 市场结论。
- N2 资金方向。
- 板块涨跌、成交额占比、涨停扩散、高标反馈、后排承接。
- 历史主线记录。

输出：

- `mainline_map`
- `primary_mainline`
- `competing_lines`
- `slowing_lines`
- `window_lines`
- `sector_cycle_by_line`

板块周期只允许：

- `启动`
- `发酵`
- `高潮`
- `退潮`
- `冰点`

不能推出：

- 不能把板块内任意涨停股升级为龙头。
- 不能把多个方向并列成多个最终标的。

### N4：板块内角色识别

目的：在主线或窗口板块内部拆角色，而不是直接看涨停强度。

输入：

- N3 给出的主线和窗口板块。
- 板块内成交额、辨识度、相对强弱、趋势承接、梯队关系。
- 高标、容量中军、弹性先锋、低位补涨和后排反馈。

输出：

- `sector_roles`
- `total_leader`
- `sector_anchor`
- `capacity_core`
- `elastic_frontline`
- `rear_feedback`
- `role_conflicts`

不能推出：

- 不能因为低位补涨涨停就替代板块锚。
- 不能因为总龙涨停就忽略板块内部失速。

### N5：候选池归一

目的：把所有股票放进同一个诊断池，并记录来源。

输入来源：

- 主线核心。
- 板块锚和容量中军。
- 热榜。
- 涨停池。
- 盘中异动。
- 历史龙头记忆。
- 旧评分高分候选。
- 用户持仓和旧仓处理对象。

输出：

- `candidate_pool`
- 每只股票的 `first_seen_node`
- 每只股票的 `source_pools`
- 每只股票的 `entered_reason`
- 每只股票的初始 `candidate_status`

候选初始身份只允许：

- `进入诊断池`
- `过程候选`
- `旧仓处理对象`

不能推出：

- 不能在本节点生成明日执行对象。
- 不能因为来源多就自动提高仓位。

### N6：反推龙头

目的：先问“资金明天最应该回看的角色是谁”，再映射到具体股票。

输入：

- N3 板块关系。
- N4 板块内角色。
- N5 候选池。
- 板块锚反推结果。

每只候选必须回答：

- 它是不是当前资金路径里的核心角色？
- 它和板块锚是什么关系？
- 为什么是它，不是板块锚、总龙或容量中军？
- 如果它只是涨停样本，为什么不能升级？

输出：

- `leader_reversal_result`
- `candidate_role`
- `relationship_to_anchor`
- `why_not_anchor`
- `reversal_decision`

`reversal_decision` 只允许：

- `可作为主对象`
- `可作为补位`
- `降级观察`
- `不参与`

不能推出：

- 不能直接给仓位。
- 不能把“可作为补位”写成最终唯一对象，除非 N7 对照后证明主对象不可做且补位具备执行条件。

### N7：候选对照淘汰

目的：让用户看懂为什么不是其他股票。

输入：

- N6 反推结果。
- 个股承接、强弱、容量、风险和账户条件。

输出：

- `kept_candidates`
- `eliminated_candidates`
- `comparison_table`
- `winner_reason`
- `loser_reasons`

对照必须覆盖：

- 最终保留对象。
- 至少前 3 个最容易误导的过程候选。
- 用户持仓或当天被重点提及的对象。

不能推出：

- 不能新增 N5 之外的候选。
- 不能让被淘汰候选在后文重新变成执行对象。

### N8：仓位与执行条件

目的：把唯一对象或无对象翻译成明天动作。

输入：

- N1 市场上限。
- N3 主线周期。
- N6 反推结论。
- N7 对照结果。
- 分时买点、失效位、账户约束。

输出：

- `execution_object`
- `position_pct`
- `action_text`
- `trigger_paths`
- `failure_conditions`
- `fail_action`

仓位只允许：

- `0%不参与`
- `50%条件执行`
- `100%核心进攻`

50% 的触发路径至少覆盖：

- 低开承接型：靠近 MA5 或快速收回 MA5，固定窗口内收回 VWAP 或 0轴。
- 主动进攻型：开盘直接进攻，分时大单净流入达标，VWAP 上方保持。

资金阈值必须结合体量：

| 对象体量 | 默认资金确认 |
|---|---|
| 小中盘活跃股 | 3000w-5000w |
| 大市值或高成交核心 | 1亿+ |
| 超大容量核心 | 1亿+，并结合成交额占比、VWAP保持和主动买盘连续性 |

不能推出：

- 买点远离失效位时不能给 100%。
- 市场或主线冰点时不能无解释给 50% 或 100%。

### N9：输出一致性复核

目的：保证各处只消费同一个最终结果。

输入：

- N8 最终结果。
- 首页、推导层、行动计划、候选追踪和流程图准备渲染的对象。

输出：

- `front_decision_payload`
- `final_target_resolution`
- `sniper_target_derivation`
- `candidate_trace_artifact`
- `flowchart_payload`
- `consistency_findings`

要求：

- 首页对象必须等于 N8 对象。
- `final_target_resolution` 不能重新选股。
- `sniper_target_derivation` 只能解释 N5 到 N8 的候选去向。
- 流程图必须来自同一份工作流节点结果。
- 如果 N8 是 0%，不得渲染“最终标的解题过程”式新增参与路径，只能渲染无执行对象或观察流水。

## 报告展示

### 首页

首页只展示工作流最终结果：

```text
## 明日诊断结论

| 项目 | 结论 |
|---|---|
| 明日动作 | 50%条件执行 |
| 唯一对象 | 豫能控股(001896) |
| 来源路径 | 市场允许继续诊断 -> 电力成为窗口方向 -> 板块锚反推保留 -> 对照胜出 |
| 不满足条件 | 回到0%不参与 |
```

### 推导层

推导层用节点顺序展示：

```text
### N1 市场周期判断
结论：...
传给下一步：...
本节点不能推出：不能选股

### N2 资金方向判断
结论：...
传给下一步：...
本节点不能推出：不能指定个股
```

### 候选流水账

候选流水账必须出现：

| 股票 | 首次来源 | 进入理由 | 板块角色 | 反推结论 | 对照结果 | 最终动作 |
|---|---|---|---|---|---|---|
| 豫能控股(001896) | 主线核心/热榜 | ... | ... | 可作为主对象 | 胜出 | 50%条件执行 |
| 上海石化(600688) | 涨停池 | ... | 过程候选 | 降级观察 | 被淘汰：不是当前主线核心 | 不参与 |

### 流程图

Mermaid 流程图必须由 `selection_workflow.v1.nodes` 生成，不能手写另一套解释。每个节点显示：

- 节点结论。
- 传给下一步的对象或方向。
- 候选增减数量。
- 如果最终 0%，显示“无执行对象”，不画成某只股票的执行路径。

## 与现有模块关系

### `build_anchor_reversal_decision`

继续保留。它从候选后置校验升级为 N6 的核心判断来源之一。涨停样本若无法说明和板块锚关系，只能输出 `降级观察` 或 `不参与`。

### `build_extreme_conviction_list`

保留，但不能再作为最终对象入口。它产出的对象先进入 N5 候选池，再经过 N6 和 N7。

### `sniper_target_derivation`

从事后汇总改成工作流解释器。它只解释 N5 到 N8 的候选生命周期，不重新决定最终对象。

### `final_target_resolution`

成为 N8 结果的承载层。它不能绕过 `selection_workflow.v1` 重新从 `selected_position_candidate` 或旧候选字段里挑对象。

### `two_layer_decision_payload`

继续服务首页和推导层，但它的数据源必须来自工作流最终结果和节点摘要。

### `candidate_trace_artifact`

继续保留，并扩展为候选生命周期的持久化载体。它应能记录每只股票的首次来源、经过节点、淘汰节点和最终动作。

## 冲突处理

如果旧模块和工作流冲突，以工作流为准，并在推导层展示冲突。

示例：

```text
旧候选质量评分把上海石化排在前列，但工作流在 N6 将其降级。
原因：它来自涨停池，未证明比当前主线板块锚更值得回看。
处理：作为过程候选展示，不进入明日执行对象。
```

如果首页、最终对象、候选追踪和流程图不是同一对象，本次日报输出无效，应改为：

```text
关键数据不完整，停止生成
```

或：

```text
路径不一致，当前只能0%不参与
```

## 验收规则

以下情况必须失败：

- 最终对象没有候选生命周期记录。
- 最终对象不来自 N8。
- 任一章节从旧候选字段重新选股。
- 涨停股没有通过 N6，却被写成明日执行对象。
- 首页对象、推导层对象、流程图对象不一致。
- 0% 时仍渲染新增参与路径。
- 多个股票同时写成最终执行对象。
- 市场层或板块层直接推出个股。
- 板块强但候选不是龙头，仍无解释给执行动作。
- 旧评分高分候选绕过反推龙头。
- replay 混入非目标日期事实。
- 出现废弃前端发布、旧本地库或旧外部分发路径读取。

## 测试计划

聚焦测试：

- `selection_workflow.v1` 必须包含 N0 到 N9 的节点摘要。
- N1 不能输出股票。
- N3 不能输出最终对象。
- N5 每个候选必须有 `first_seen_node` 和 `entered_reason`。
- N6 中涨停但非板块锚的对象只能是 `降级观察` 或 `不参与`。
- N7 必须给出至少一个被淘汰候选原因。
- N8 仓位只能是 0、50、100。
- `final_target_resolution` 只能消费 N8 结果。
- `sniper_target_derivation` 必须展示候选从 N5 到 N8 的去向。
- 首页、推导层、候选流水账、流程图必须引用同一个对象。
- 0% 不参与时，不生成新增参与路径。
- 工作流扫描不得出现废弃前端发布、旧本地库或旧外部分发读取路径。

Replay 验证：

```bash
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-06-04 --replay
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-06-05 --replay
```

检查重点：

- 2026-06-04 能解释最终对象从市场、主线、板块角色和反推龙头如何得出。
- 2026-06-05 能解释为什么华电辽能做 T 亏损后，冲动买入不能被盘中理由包装成执行动作。
- 涨停/连板样本只能作为候选来源和后置证据。
- 最终日报能清楚展示“为什么是它，不是其他候选”。

## 第一版实施边界

第一版不直接重写所有模块，采用兼容层收束：

1. 新增 `selection_workflow.v1` 构建器。
2. 从现有运行数据中生成 N0 到 N9 节点摘要。
3. 把现有候选统一塞入 N5 候选池。
4. 让 N6 消费现有板块锚反推。
5. 让 N7 生成候选对照和淘汰原因。
6. 让 N8 生成唯一最终动作。
7. 让 `final_target_resolution`、`two_layer_decision_payload`、`sniper_target_derivation` 和流程图改为消费工作流结果。
8. 用 replay 验证 2026-06-04 和 2026-06-05。

## 风险

- 如果一次性重写所有日报章节，容易再次发散。第一版应先保证主链唯一，再逐步替换旧章节。
- 现有测试很多会断言旧标题和旧字段，需要只更新和主链相关的断言。
- 候选来源很多，第一版要优先保证“来源可追踪”，不追求把所有历史附录一次性整理完。
- 如果某些数据缺失，不能为了完整链条硬补结论，应输出 0% 或停止生成。

## 完成定义

- 中文 spec 无占位符、无自相矛盾。
- 工作流节点顺序、候选生命周期和最终消费关系明确。
- 后续实施计划能按 N0-N9 拆任务。
- 2026-06-04 和 2026-06-05 replay 可用于验收。
- 新日报能解释股票从哪里来、经过哪些筛选、为什么最终是它。
- 涨停池不能作为最终选股入口。
- 首页、推导层、候选流水账和流程图只消费同一个工作流最终结果。
