# 日报双层重写设计

日期：2026-06-05

## 目标

把日报重写成双层产品：

1. 服务次日交易准备的前台决策层。
2. 解释日报如何得到前台结论的推导审计层。

日报必须同时服务盘前快速决策和事后排错。第一层告诉用户明天怎么处理。第二层展示哪些数据产生了每一步结论、哪些对象被淘汰、哪些对象留下、哪些内容传给下一步。

## 问题

当前日报把最终动作、候选证据、历史复盘和中间 Step 输出混在一起，造成三个阅读问题：

- 报告可以一边写最终结果为空，一边又把某只股票写得像明日执行对象。
- Step 段列出很多事实，但没有稳定说明本 Step 传给下一步什么。
- 中间标签让过程证据看起来像最终对象，用户分不清日报到底是在说“条件出现就执行”，还是“只看不做”。

核心修复不是画一张更漂亮的流程图，而是日报本身需要更严格的信息架构和对象身份契约。

## 范围

范围内：

- 日报整体结构。
- 首页决策契约。
- Step 逐步推导契约。
- 最终对象身份表达。
- 50%执行条件。
- 候选和过程证据展示规则。
- 一致性检查和 replay 验证要求。

范围外：

- 替换整个交易判断引擎。
- 重建所有数据采集器。
- 改写与本次实现无关的历史交易思想文档。
- 优化 LLM 调用、数据刷新速度或无关日报章节。

不做：

- 不把日报改成纯研究摘要。
- 当真实含义是条件执行时，不要把股票写成旧被动称呼。
- 不允许大量候选表与最终决策争夺注意力。

## 读者契约

日报必须按顺序回答这些问题：

1. 明天有没有唯一执行对象？
2. 如果有，哪些具体条件允许 50%条件执行？
3. 条件失败时怎么处理？
4. 哪些数据推导出这个对象和这些条件？
5. 哪些候选被淘汰或降级，原因是什么？

用户应该可以读完第一层就完成盘前准备，也可以继续读第二层来排查日报逻辑。

## 新日报结构

### 第一层：前台决策层

这一层必须出现在详细市场段之前，短、直接、可执行。

必备章节：

1. `明日执行结论`
2. `明日执行对象`
3. `50%执行条件`
4. `不执行条件`
5. `关键证据摘要`
6. 有旧仓时展示 `旧仓优先处理`

示例结构：

```text
## 明日执行结论
| 项目 | 结论 |
|------|------|
| 明日仓位 | 条件满足才50%条件执行；不满足回到0% |
| 明日执行对象 | 豫能控股(001896) |
| 执行性质 | 50%条件执行，约50%仓位 |
| 不满足条件 | 不参与 |

## 50%执行条件
| 触发类型 | 必须满足 | 窗口 | 动作 |
|----------|----------|------|------|
| 低开承接型 | 靠近MA5或快速收回MA5；09:50-10:10收回VWAP/0轴 | 09:50-10:10 | 50%条件执行 |
| 主动进攻型 | 开盘直线进攻；分层大单净流入达标；VWAP上方保持 | 09:30-09:35或09:50-10:10 | 50%条件执行 |
```

第一层不能使用旧被动称呼。如果选出的股票在条件出现时应当执行，可见身份就是 `明日执行对象` 或 `条件执行对象`。

### 第二层：推导审计层

这一层解释结论来源。每个 Step 固定使用同一模板：

```text
### Step N - <title>
#### 输入数据
#### 本步判断
#### 保留与淘汰
#### 传给下一步
#### 本步不能推出什么
```

每个 Step 必须明确写出传给下一步的内容。如果没有执行对象传下去，必须直接说明。如果选中的股票继续保留为条件执行对象，必须说明还等待哪些条件确认。

## 对象身份契约

日报只有一套最终对象身份模型：

- `明日执行对象`: 条件出现时明天可以执行的唯一股票。
- `条件执行对象`: 同一个对象，强调执行必须等待预设条件。
- `备选对象`: 只有当日报明确允许第二执行对象时才展示；默认前台不允许。
- `过程候选`: 只作为证据，不能出现在前台动作里。
- `不参与对象`: 被拒绝或不产生动作的证据。

前台决策层禁止使用旧被动称呼。它会让对象听起来像只看不做，掩盖“条件出现就执行”的真实含义。

当任何条件都不能导向执行时，日报可以写 `无明日执行对象`。当某只股票在条件出现时可以执行，日报必须写 `明日执行对象`，即使计划是“先等条件，不满足回到0%”。

## 50%条件执行契约

`50%条件执行` 表示约 50% 仓位的条件执行。它不是无条件买入，也不是只看不做。

### 低开承接型触发

用于股票低开或早盘先回踩的情形。

必要条件：

- 日线结构：价格靠近 MA5，不有效跌破 MA5，或跌破后快速收回 MA5。
- 分时结构：`09:50-10:10` 窗口收回 VWAP 或 0轴，并能站住。
- 市场/方向支持：市场底色和相关方向不能同时明显走弱。
- 失败处理：MA5 未收回，或 VWAP/0轴未收回，都不执行。

日报不能把 MA5 单独当作充分条件；日线结构很差时，也不能只靠分时收回就追。

### 主动进攻型触发

用于股票开盘直接向上进攻的情形。

必要条件：

- 价格行为：开盘后直接进攻，不是快速冲高回落。
- 资金确认：分时大单净流入达到按体量分层的阈值。
- 分时保持：股价保持在 VWAP 上方，或短暂震荡后快速收回。
- 方向确认：相关方向不能和个股明显背离。

大单净流入阈值：

| 对象类型 | 默认资金确认 |
|-------------|---------------------------------|
| 小中盘活跃股 | 3000w-5000w |
| 大市值或高成交核心 | 1亿+ |
| 工业富联这类超大容量核心 | 1亿+，并结合成交额占比、VWAP保持和主动买盘连续性 |

第一版实现可以用市值、近期成交额或成交额排名分层。日报必须显示本次采用了哪个体量分层。

## Step 契约

### Step 0：市场底色

目的：判断次日环境是否允许考虑 50%条件执行。

输入数据：

- 指数涨跌。
- 涨跌家数。
- 成交额和成交额趋势。
- 涨停/跌停扩散。
- 主方向关系。

输出：

- `可等待50%执行条件`
- `只允许旧仓处理`
- `无执行条件`

本 Step 不能选股，只判断是否可以继续考虑执行条件。

### Step 1：候选池

目的：收集可能对象，并标明它们为什么进入候选池。

输入数据：

- 热榜。
- 涨停池。
- 盘中异动。
- 板块与 tag 证据。
- 近期龙头记忆。

输出：

- 过程候选列表。
- 候选来源理由。
- 候选角色，不是最终身份。

本 Step 不能把股票直接升级为最终执行对象。

### Step 2：主方向与候选收缩

目的：围绕最相关的方向和对象收缩候选池。

输入数据：

- 主方向证据。
- 板块核心或当前焦点。
- 候选质量字段。
- 跨方向证据。

输出：

- 当某只股票值得准备 50%条件执行时，输出一个 `条件执行对象`。
- 当没有股票值得条件执行时，输出 `无明日执行对象`。
- 输出被拒绝的过程候选及原因。

本 Step 必须解释为什么选中对象胜出。若跨方向股票留下，必须说明什么条件能证明它不是噪音。

### Step 3：风险复核

目的：在生成执行计划前，检查条件执行对象是否已经不安全。

输入数据：

- 烂板/炸板。
- 板块走弱。
- A杀或结构破坏证据。
- 跌停扩散。
- 关键数据缺失。

输出：

- `条件执行对象继续保留`
- `降为不参与`
- `只处理旧仓`

本 Step 不能引入新的执行对象，只能保留、拒绝或降级 Step 2 传来的对象。

### Step 4：50%条件执行计划

目的：把留下来的对象转成具体 50%执行条件。

输入数据：

- MA5 位置。
- VWAP / 0轴收回规则。
- 分时大单净流入分层。
- 市场和方向确认。
- 旧仓约束。

输出：

- 低开承接型触发条件。
- 主动进攻型触发条件。
- 失败条件。
- 50%仓位上限。

如果本 Step 不能生成任一触发路径，该对象降为 `无明日执行对象`。

### Step 5：最终一致性

目的：让前台决策层、行动计划、候选表和附录使用同一个最终身份。

输入数据：

- Step 4 给出的最终对象。
- 50%执行条件。
- 账户约束。
- 旧仓优先级。

输出：

- 最终前台决策载荷。
- 推导路径载荷。
- 一致性检查事实。

本 Step 不能重新打开候选选择。

## 数据载荷契约

重写应引入一个统一日报载荷。即使第一版仍从现有模块拼装，也必须先形成这一层结构：

```python
{
    "target_date": "YYYY-MM-DD",
    "front_decision": {
        "position_plan": "50%条件执行 | 0%不参与 | 旧仓优先",
        "position_pct": 50,
        "execution_object": {"code": "001896", "name": "豫能控股"},
        "execution_identity": "明日执行对象",
        "if_fail": "不参与",
    },
    "b_level_conditions": {
        "low_open_acceptance": {...},
        "active_attack": {...},
        "invalidations": ["..."],
    },
    "derivation_steps": [
        {
            "step": "Step 2",
            "input_summary": ["..."],
            "judgement": "...",
            "kept": ["001896"],
            "rejected": [{"code": "600688", "reason": "..."}],
            "passes_forward": {"execution_object": "001896", "pending_conditions": ["..."]},
            "cannot_conclude": ["..."],
        }
    ],
}
```

内部字段名可以保留英文；日报可见表头和正文必须使用中文交易语言。

## 渲染规则

- 第一页先展示最终决策，再展示过程证据。
- 最终执行对象只在前台决策层出现一次。
- 后续候选表必须标为过程证据。
- 被拒绝的候选不能在后文变成前台动作。
- Step 章节不能使用与前台决策层不同的最终对象身份。
- 日报必须区分“条件出现就执行”和“无执行对象”。
- 历史回测表永远不能生成明日动作。

## 验收规则

出现以下情况时，日报无效：

- 第一页没有 `明日执行对象`，后文却暗示有具体条件执行股票。
- 过程候选看起来像最终执行对象。
- 任一 Step 缺少 `传给下一步`。
- Step 3 或 Step 4 引入了前一步没有传来的新执行对象。
- 提到 50%条件执行却没有给出条件。
- 大市值股票使用小中盘 3000w-5000w 资金阈值，却没有解释体量分层。
- 低开承接型只使用 MA5 或只使用 VWAP/0轴，而不是同时要求日线与分时确认。

## Replay 示例：2026-06-04

前台预期含义：

```text
明日执行对象: 豫能控股(001896)
执行性质: 条件满足才50%条件执行；不满足回到0%
低开承接型: MA5承接 + 09:50-10:10收回VWAP/0轴
主动进攻型: 开盘直线进攻 + 分层大单净流入达标 + VWAP上方保持
不执行条件: 市场继续走弱、主线承接失败、个股不能收回关键分时位置、资金确认不足
```

审计层预期含义：

- Step 1 可以展示上海石化、豫能控股、XD红星发、瑞贝卡等过程候选。
- Step 2 必须解释为什么豫能控股成为条件执行对象，或为什么它是唯一值得准备 50%条件执行的对象。
- Step 3 可以拒绝或保留豫能控股，但不能引入新对象。
- Step 4 必须生成两条 50%条件执行触发路径，否则降为无明日执行对象。
- Step 5 必须同步前台、行动计划、候选质量、附录路径和一致性检查事实。

## 测试计划

聚焦测试：

- 前台决策渲染器展示 `明日执行对象`、`50%执行条件` 和 `不满足回到0%`。
- 前台决策渲染器不使用旧被动称呼。
- Step 渲染器要求 `输入数据`、`本步判断`、`保留与淘汰`、`传给下一步` 和 `本步不能推出什么`。
- Step 3 不能引入新的执行对象。
- Step 4 不能在缺少两类触发路径且没有明确降级时渲染 50%条件执行。
- 大市值主动进攻型使用更高资金确认分层。
- 低开承接型必须同时要求 MA5 和 VWAP/0轴确认。
- 当过程证据与前台执行对象冲突时，一致性检查失败。

Replay 验证：

```bash
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-06-04 --replay
```

随后对生成的完整版 replay 日报运行一致性检查，并人工抽查前台决策层和 Step 2-5。

## 实现边界

第一版实现优先采用兼容层，不直接重写整个交易判断引擎：

1. 从现有运行输出构建统一日报载荷。
2. 用该载荷渲染新的前台决策层。
3. 用现有阶段导出和明确的传递字段渲染 Step 审计层。
4. 更新一致性检查。
5. 重新生成 replay 并比较可读性。

除非无法生成统一载荷，否则第一版不重写数据采集器或评分内部逻辑。
