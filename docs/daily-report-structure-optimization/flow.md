# 日报结构优化流程

> 历史展示记录，不适用于当前日报入口。下文流程描述旧完整版及旧操作展示，不得为满足它而重新启用已废除的生成链。当前流程见[框架重建 PRD](../plans/2026-10-22-daily-report-framework-rebuild-prd.md)。

## 范围边界

本轮只处理日报结构和结构相关口径：

- 首屏阅读顺序。
- 板块资金证据在首屏的位置。
- Bear HTML 中动作段和证据段的视觉区分。
- 完整版、轻量版、附录的标题层级。
- 0%不参与时的对象表达。
- 历史 replay 中报价敏感事实的日期约束。
- 接受检查提示的用户可见表达。
- “明日操作”“明日策略”“出手时怎么做”等正向执行文案的 2B 表达。
- 市场语言研究证据在最终动作之后的只读展示、Bear HTML 分类和完整版/摘要版隔离。
- 附录主线推导链使用 Mermaid 主视图和中文节点表，不展示内部字典。
- 候选生命周期证据的来源中文化、四维明细和 Bear 默认折叠展示。
- Bear 中近期热点板块成交额与 25 日小周期方向合并为横向周期泳道，原始表默认收起；近期热点名单优先保留成交事实完整且有强势高标支撑的当日方向。
- Bear 在有效目标日三坐标存在时，把旧周期泳道升级为板块反馈区间；主图回答反馈从何时开始、何时结束、持续多久以及区间内出现过哪些响应，归一价格路径只作辅助记录。
- 板块资金扩散淘汰赛使用空间、时间、认知三坐标，补充反事实、优势来源和淘汰赛十问，并在各展示端复用同一目标日产物。
- 三坐标把阶段主线与当日主攻线分开；已确认阶段主线至少覆盖 10 个交易日，并同时具备冷却后回流、逐日板块指数相对强度、内部趋势股密度和适用的分歧修复，板块指数短期斜率只作有利证据。

未处理：

- 不重构日报生成主链路。
- 不新增数据源。
- 不覆盖正式历史 Markdown 和快照；Bear HTML 可从原 Markdown 单独重建。
- 不清理工作树里的无关修改和未跟踪产物。
- 不改变选股、评分、最终对象和仓位百分比，只改变可读执行口径。
- 不把三坐标变成综合分、第二套候选或账户动作。

## 生成链路

1. 读取 replay 快照或当日数据。
2. 在 preflight 前清理报价敏感派生结果，确保检查和渲染看到的是同一份刷新后事实。
3. 构建选股流程和最终对象解析。
   - `selection_workflow` 从目标日及以前的市场参与、局部趋势和价格事实构建一次 `sector_tournament_three_axis.v1`。
   - 三坐标依次记录空间位置、时间阶段、认知验证、反事实、优势来源、故事与价格关系、剩余传播证据和十问。
   - 阶段主线可同时有多个；每个方向分别记录启动日、确认日、截至日和最近确认日。候选期不写确认日，首次确认时两确认日期相等，续证只移动最近确认日，弱化或失效保留最后完整续证日。
   - 阶段跨度按交易所日历含首尾计算，少于 10 个交易日只能是候选或事实不足；达到 10 日仍需从活跃日、冷却后回流、逐日指数路径、完整比较范围与名次、内部趋势股密度和适用的分歧修复共同重算。
   - 当日主攻线、日内多次轮动、两个活跃日、短期向上斜率或单股强势都不能覆盖阶段身份，也不改变正式决定。
   - `cross_day_competition` 只冻结 T0 对未来一至两个交易日的板块竞争假设；事后结果进入独立复盘，不回写三坐标、两级哈希或正式决定投影。
   - 输入哈希与产物哈希随判断冻结；来源日期、目标日期或两级哈希不一致时，消费者整份拒绝该产物并显示事实不足。
   - 三坐标挂载前后，正式对象、仓位、执行性质、B1/B2、旧仓和退出动作逐字段不变。
4. 在入口从目标日可追溯事实构建一次 `market_language_translation.v1`，保留在局部变量；完整版和摘要版分别接收隔离副本。
5. 生成首屏：
   - H1。
   - 阅读地图。
   - 账户日序表。
   - 日报裁决总览。
   - 明日执行结论。
   - 满仓条件执行条件、50%条件执行条件、不执行条件。
   - 板块资金扩散淘汰赛、板块资金载体复核、T0推演；淘汰赛先显示三坐标摘要，再按同一产物列出十问。
   - 市场语言翻译研究证据；只能出现在明日动作之后。
   - 判断纠偏、市场、主线、个股、执行计划、最终结论。
   - 正向执行文案统一经过 `report.execution_wording`：B1先买参与权，B2只在确认后补；没有确认不补足。
   - 近期热点板块跟踪仍保留 8 个名额；成交额和占比有效、最高连板至少 3 板且同板块至少 2 只涨停的方向，优先替换仅有历史记录的方向，不挤掉已有当日成交事实。
6. 生成 Bear HTML：
   - 沿用 Markdown 最终顺序。
   - 给阅读地图、动作段、证据段加稳定样式标记。
   - 从最终 Markdown 同时读取逐板块成交额表和 25 日小周期方向表，生成 `sector_cycle_swimlane.v1`。
   - 入口传入目标日冻结且哈希有效的 `sector_tournament_three_axis.v1` 时，使用当前评估方向的 `relative_strength_window.trade_dates` 作为唯一共同窗口，升级为 `sector_relative_path_swimlane.v2`；无效产物保持 v1。
   - v2 以反馈区间为主几何：保留来源起止日和当前横轴内可见起止日，显示持续交易日、逐日证据数和证据覆盖率；阶段起点在轴外时从轴内首次可核实反馈开始显示。
   - 阶段主线弱化或失效后，区间结束于最近完整续证日；逐日价格路径缺口只让归一价格辅助线断开，不删除已有跨日反馈区间。
   - 区间内的节点分别显示价格响应、跨日反馈、轮动/回流、成交参与、主力净流入和机构净买。同日多类事实分别画节点；成交额与占比不能改写为资金净流入。
   - 机构净买只接受目标日机构表中同时具备股票、代码，并能由同一 Markdown 明确映射所属板块的记录；缺股票列、缺代码、目标日无效或无法映射时不生成机构节点。
   - 阶段主线、当日主攻和当前评估分别标识；同起点 100 的价格路径、真正转强、高质量修复、普通反弹、弱化/失效和价格吸收程度都只作解释，不产生买入资格。
   - ECharts 展示反馈区间、逐日证据节点和细价格辅助线；脚本不可用时保留同源 ASCII 泳道。
   - 全篇只在正式主章节展示一张板块周期泳道；主章节缺失的旧报告才使用首个兼容附录位置。
   - 主章节和详细附录中的三个原始板块事实组分别进入默认收起区，表内标题、T 编号和数据行不删除。
   - `## 八、详细附录` 下的每个三级标题形成独立的默认收起区，后续知识与原则章节保持在附录之外。
   - 桌面目录保留三级入口；移动目录把详细附录三级入口放入默认收起的“详细附录”原生折叠组，展开后仍指向同一摘要锚点。
   - 从 PostgreSQL `index_daily_bars` 读取 `sz399006` 截至报告日的最近 25 个有效收盘点，只在 Bear 图表载荷中按 Top50 日期同日对齐；缺失日保持空值。
   - Top50 占比和创业板指使用左右双轴，两条图例默认开启且可独立显隐；没有任何同日创业板事实时保持原 Top50 单线图。
   - 从目标日冻结的中金所持仓证据读取最多 60 日序列，分面显示中信代客名义净空、中信代客净空日变和前 20 榜单净空差；默认 20 日，可切换 60 日，缺失值不补 0。
   - 股指期货趋势图只解释结构，原目标日精确表继续负责数值复核；载荷变化进入 Bear 输入哈希，不进入候选、仓位或执行动作。
   - companion HTML 的三坐标面板和内嵌 JSON 复用工作流同一 `artifact_hash`，不自行判断时间阶段。
   - 不从 HTML 反推或改写明日对象。
7. 生成附录：
   - 推导审计层降为附录内标题。
   - 主线推导链先渲染 `selection_workflow.v1.nodes` 生成的 Mermaid，再渲染节点、结论、向下传递和尚未确认四列表。
   - `passes_forward` 只保留中文交易含义，原始嵌套字典继续留在快照，不进入 Markdown 或 Bear HTML。
   - 过程候选统一作为复盘证据。
   - 候选生命周期 Markdown 仍保留全部七列逐股证据，来源标题为“发现路径”且已知来源使用中文名。
   - Bear HTML 将该表收缩为“数量概览 / 重点候选 / 其余过程样本”，普通样本用原生 `details` 默认收起，但全部候选仍在 HTML DOM 中。
   - 空最终对象时清理旧的当前对象、主观察对象、明日观察池等误导表达。
8. 生成轻量版：
   - 先移除完整版已有阅读地图。
   - 再把轻量版阅读地图插到 H1 后。
   - 保留关键动作、市场底色、个股处理、明日三窗口和最终结论。
9. 比较接入前后的正式决定投影和研究产物哈希，运行日报一致性检查。
10. 正式入口在整日事实同步和磁盘正文复读均通过后写 fresh；replay 只写独立 replay 路径。
11. 写出 Markdown、HTML、运行日志和伴随文档。

## 关键判断

### 2B执行口径

50%或满仓结果仍是T0已经决定的条件执行计划，不是T+1盘中重新决定。升级后的表达只改变执行方式：

- B1买参与权，用来避免完全踏空唯一动作。
- B2买确认权，只在竞价/开盘前几分钟/回封/09:50-10:10等确认条件存活后补。
- 没有确认就没有补足义务，坏样本只亏B1，好样本才给B1+B2。
- 同股T时，已有1x旧仓先视为B1参与权，B2只在强表态存活后补；强表态失败先卖可卖旧仓。

这个口径只进入“明日操作”“明日策略”“真到盘中怎么做”“明天具体怎么做”等用户可见动作说明，不反向修改选股流程和最终对象解析。

### 最终动作优先

阅读地图把最终动作放在第一位，先回答明天做不做、做什么、什么条件不做。这样人工复盘不会被后文过程候选带偏，AI 解析也先拿到稳定结论。

### 过程证据不覆盖最终对象

过程候选可以进入附录，但不能在空最终对象时写成当前对象、主观察对象或明日执行对象。

### 0%仍可有前台观察对象

0%不参与表示不新增参与，不等于不能记录前台观察对象。合格前台观察对象可以进入 `watch_target`；过程观察样本仍会被过滤，不上升成当前对象。

### 历史事实必须能对齐日期

`selection_workflow_quote_rows`、`same_day_quote_rows`、`stock_daily_quotes_recent` 必须带目标日日期。热榜、成交排行、涨跌停池等旁路行情如果行内无日期，必须由外层数据包证明属于目标日，否则不参与价格状态判定。

### 轻量版只保留一张地图

完整版已经有阅读地图，轻量版不能再把地图放到 H1 前，也不能重复两张地图。轻量版固定为：H1、阅读地图、裁决和账户建议、执行图、市场和个股摘要、最终结论、证据入口。

### 市场语言只翻译，不发动作

市场语言产物只回答合力发生在哪一层、方向与阶段是什么、候选何时确认或失效，以及下一正式窗口该核对什么。它不能确认交易账户身份，也不能把前哨或全天事件记录改成窗口外买卖动作。全市场宽度必须由精确日期数据生产端携带自身交易日，翻译层不从外层报告日期猜测。
