# 日报结构优化说明

> 历史展示记录，不适用于当前日报入口。2026-10-22 起，默认日报独立生成板块阅读页；旧账户、固定分笔与时窗、唯一对象及操作日历不再生成。当前范围和验收以[框架重建 PRD](../plans/2026-10-22-daily-report-framework-rebuild-prd.md)与[验证约定](../../references/verification.md)为准。

本目录保留此前日报结构优化的改动范围、处理流程和验证证据，供历史复核。下文“本轮”“修改后”和“不变项”指各自当时的任务，不是当前交易或新阅读页的要求。

## 改动目标

- 让日报首屏先给最终动作，再给推导和证据。
- 让 Bear HTML 与 Markdown 使用同一套动作优先顺序。
- 让旧仓、新机会、观察对象、过程候选分开表达，避免把观察信号写成执行资格。
- 让生成的“明日操作”“明日策略”统一使用 2B 执行口径：B1先买参与权，B2只在确认后补；没有确认不补足。
- 让完整版、轻量版和附录有稳定层级，减少标题漂移和重复内容。
- 让历史 replay 使用目标日期事实，避免无日期行情旁路影响历史判断。
- 让市场语言研究证据在最终动作之后解释范围、方向与阶段，同时保持正式决定不变。
- 让附录主线推导链先显示 Mermaid，再用中文节点表承接审计信息，不暴露内部字典。
- 让 Bear 的 25 日板块周期记录先显示横向泳道，底部常显滑杆与左右按钮，完整原表保留为默认收起的核对入口。
- 让 Bear 在有效目标日三坐标存在时直接显示板块反馈起止区间：起始日、结束日、持续交易日和逐日响应一眼可见，归一价格路径降为辅助线。
- 让 Bear 全篇只显示一张板块周期泳道，并把“八、详细附录”按三级标题分组收起，避免同一套周期、资金和执行依据连续重复展示。
- 让 Bear 的 Top50 成交占比趋势按同一交易日叠加创业板指数，使用左右双轴和可独立显隐的图例；缺失日保留断点。
- 让 Bear 用 20/60 日三分面图展示股指期货净空结构，同时保留目标日精确表复核数值。
- 让板块资金扩散淘汰赛同时回答空间传到哪里、时间处于什么阶段、主观假设获得哪些量化与价格验证，以及当前主要赚哪一种阶段差。
- 让阶段主线与当日主攻线分开显示：已确认阶段主线至少覆盖 10 个交易日，并同时证明冷却后回流、逐日板块指数相对强度和内部趋势股密度；日内活跃、两个轮动日、短期斜率或单股强势都只提供候选线索。

## 主要文件

- `scripts/report/runtime.py`：完整版阅读地图、账户日序表位置、板块资金证据后置、附录标题降级、空对象附录清理、0%场景前台观察对象保留。
- `scripts/report/execution_wording.py`：统一“明日操作”“明日策略”使用的 B1/B2 执行文案。
- `scripts/report/markdown_report_html.py`：Bear HTML 标题分类、v1 周期泳道、v2 反馈区间与逐日证据载荷、资金事实映射、ASCII 降级和原始记录分组。
- `scripts/templates/daily_report_markdown_reader.html`：Bear HTML 动作/证据样式、ECharts 甘特式反馈区间、分离证据节点、价格辅助线、附录摘要和窄屏局部滚动。
- `scripts/daily_report_render.py`：轻量版阅读地图去重，报告伴随文档路径，preflight 前刷新报价敏感派生结果。
- `scripts/report/selection_workflow.py`：同日行情日期匹配；规范化阶段轮动、板块指数路径和当日主攻线事实，过滤未来日期且不污染目标日判断。
- `scripts/report/candidate_decision_evidence.py`：构建版本化、目标日冻结的 `sector_tournament_three_axis.v1`，负责规范输入、反事实、十问和稳定哈希。
- `scripts/report/elimination_tournament.py`：核对三坐标目标日期与两级哈希，供淘汰赛、生成前复核和 companion HTML 同源展示；量化痕迹缺失时保留事实不足。
- `scripts/report/two_layer_decision_payload.py`：主线推导链的 Mermaid 主视图、中文节点表和向下传递摘要。
- `scripts/report/report_acceptance_audit.py`：接受检查提示改成中文交易口径，减少英文工程化提示。
- `scripts/daily_report_entry_demo.py`：账户日序表插入到标题和阅读地图之后；把三坐标纳入 Bear 输入哈希和两次渲染入口，并从 PostgreSQL 构造 Bear 专用的创业板最近 25 日收盘序列。
- `scripts/report/front_page_v2_renderer.py`：首屏结论和前台观察表达配合结构调整。
- `scripts/domains/market_state/market_language_translation.py`：目标日来源投影、事件时钟、范围/方向/阶段和 replay 事后验收。
- `scripts/report/market_language_translation_artifacts.py`：fresh/replay 独立准备、加载与保存。
- `scripts/report/final_conclusion_nodes.py`、`scripts/report/action_plan_nodes.py`、`scripts/domains/execution_chain/pk_decision_nodes/action_plan_context.py`：把最终结论、操作计划和 PK 执行上下文同步到 2B 口径。

## 修改后对比

| 项目 | 修改前 | 修改后 | 不变项 |
|------|--------|--------|--------|
| Markdown 顺序 | 板块资金扩散淘汰赛可能压在明日执行结论前面。 | 明日执行结论、执行条件、不执行条件先出现，板块资金证据随后解释。 | 明日对象、仓位和执行性质仍取自原结构化结果。 |
| Bear HTML | 只按普通标题渲染，动作段和证据段不区分。 | 动作段和证据段有不同样式标记，顺序跟随 Markdown。 | HTML 不参与候选、评分、淘汰或最终对象解析。 |

| 明日操作/明日策略 | 容易读成开盘一次性买够，或把第二笔当成任务仓。 | 正向执行统一写明：B1先买参与权，B2只在确认后补；没有确认不补足。同股T时，已有1x先视为B1参与权。 | `selection_workflow`、`final_target_resolution`、仓位百分比和最终对象不因文案升级而改变。 |
| 市场语言研究证据 | 公式、弧形和量化压力只在独立研究报告中解释。 | 完整版和摘要版在明日动作之后增加只读证据区；缺少一分钟事实时明确降级，未来表现只进入 replay。 | 正式候选、最终对象、仓位、执行性质、B1/B2 和退出动作不变。 |
| 板块周期记录 | 逐板块成交额表和 25 日小周期表连续展开，主文和两个附录又各显示一张同源泳道。 | Bear 只在正式主章节显示一张横向泳道；三个原始事实组分别保留，附录副本随所属三级附录默认收起。 | 泳道载荷、板块名、个股候选、正式决定和仓位不变。 |

| Top50 成交占比趋势 | 只显示 Top50 占比单线。 | Bear 按 Top50 的 25 个日期同日叠加创业板指，Top50 使用左轴、创业板使用右轴；图例可独立显隐，缺失点显示事实不足。 | Markdown 原表、正式快照和交易决定不变。 |

## 当前验证结论

本轮展示层改动已通过新增窄路径测试、相关文件级测试、格式检查、稳定结构单测和临时 Bear HTML 渲染检查。

2B 执行口径补充验证：

- `tests.test_front_page_v2_renderer` 覆盖账户页“明日动作”和同股T表达。
- `tests.test_report_runtime` 覆盖正文、附录、满仓归一化和历史旧文案升级。
- `tests.test_final_conclusion_renderer` 覆盖“明日策略”。
- `tests.test_action_plan_renderer` 覆盖“明日操作计划”。
- `tests.test_two_layer_decision_payload` 覆盖明日执行结论。
- `tests.test_pk_decision_stage` 覆盖 PK 阶段执行上下文。

市场语言研究证据补充验证：

- 相关 12 模块 766 项整套回归覆盖来源日期、真实市场宽度生产形状、事件顺序、正式决定隔离、fresh/replay 保存、前台和 Bear HTML；1 项真实 PostgreSQL 用例在常规模式按条件跳过后已单独开启并通过。
- 真实 PostgreSQL 同库重存测试证明整日事实再次保存后仍能按目标日读回研究产物。
- 真实 Runtime 比较接入前后正式决定投影，确认动作先于研究证据且共享输入不残留研究产物。
- Revision 4 论文通过 23 项研究测试、逐字一致、HTML 解析和桌面/`390px` Playwright 复核。

三坐标淘汰赛补充验证范围：

- 校准单日假启动、局部秩序形成且市场混沌、强势轮动、单主线聚焦、首次主动分歧承接/失败、市场响应和成熟趋势继续上修。
- 比较重复构建的输入哈希与产物哈希，确认输入只读；目标日之后的趋势、价格或分歧事实不能进入产物。
- 已确认阶段主线至少需要 10 个交易日的含首尾跨度；达到时长后仍须同时具备冷却后回流、完整逐日指数路径和相对强度比较、内部趋势股密度及适用的分歧修复。两个活跃日或日内多次轮动只能保持候选或事实不足。
- 启动日、确认日、截至日和最近确认日分别记录，后来确认不能倒写到启动日；阶段主线与当日主攻线分别显示，同一阶段允许多个方向并存。
- T0 只保存未来一至两个交易日的板块竞争假设；T+1/T+2 实际结果只进入复盘，不改变目标日产物、哈希或正式决定投影。
- 核对工作流、淘汰赛、生成前复核、Markdown、companion HTML 和内嵌 JSON 使用同一 `artifact_hash`。
- 无真实量价事实时只显示事实不足；接入前后正式对象、仓位、执行性质、B1/B2、旧仓和退出动作逐字段一致。

板块相对路径泳道补充验证范围：

- Bear 入口、输入哈希和两次渲染都传递同一三坐标产物；目标日、输入哈希或产物哈希无效时回退 `sector_cycle_swimlane.v1`。
- 当前评估方向的比较日期是唯一共同横轴；主图保留来源起止日、可见起止日、持续交易日、证据日期数和覆盖率，完整价格路径缺日时仍显示可核实反馈区间。
- 阶段起点在轴外时回退到轴内首次可核实反馈；阶段主线弱化或失效时结束于最近完整续证日。
- 同日价格响应、跨日反馈、轮动/回流、成交参与、主力净流入和机构净买分别绘制；成交额不改写为净流入，机构记录缺股票、代码或板块映射时不生成机构节点。
- 阶段主线、当日主攻和当前评估分别显示；同起点 100 的价格辅助线缺日保持 `null` 断点，解释标签不产生买入资格。
