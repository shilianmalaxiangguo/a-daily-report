# 候选质量评分与动作分层 V1

## 文档定位

本 spec 是后续实现候选质量评分的主文档。它只定义第一版该做什么、字段怎么命名、日报怎么展示、盘中问股怎么继承、复盘怎么校准，不在本文档阶段修改运行代码、测试或 wiki。

第一版目标不是把交易判断变成精密公式，而是让日报先稳定回答五个问题：

1. 今天市场是否支持新增参与。
2. 账户里有没有必须先处理的持仓问题。
3. 哪些候选是选股质量高，哪些只是买点看起来便宜。
4. 每只候选最多能做到什么动作。
5. 明天盘中如果问股，能否继承前一晚结论，而不是重新讲一套故事。

## In Scope

- 日报固定前置步骤：先输出市场情绪、账户后台任务负担、持仓优先动作、今日新增上限，再进入候选评分和单票解释。
- 盘中问股继承日报：盘中只补充新事实，并以最新日报的动作上限、恢复条件、取关条件和今日新增上限为基础。
- 候选主表：固定日报可见中文字段，展示候选、持仓、可卖数量、仓位性质、选股质量、买点质量、风险项、成本项、动作上限、持仓动作、新开仓动作、恢复条件、取关条件和最晚复核。
- 单票展开：每只关键候选必须解释当前上涨发动机、市场辨识度、趋势审美、买点质量、风险项、成本项、持仓动作、新开仓动作、最坏情境和一句话纪律。
- 复盘校准：保留当时判断、实际走势、买点是否出现、用户是否偏离、错误归因和样本保护结果，防止后续实现漂移。
- 给出可实施字段名建议：后台可以使用英文结构化字段，但日报和盘中回答的可见字段必须是中文。
- 区分三组概念：选股质量 vs 买点质量；持仓动作 vs 新开仓动作；风险项 vs 成本项。

## Out of Scope

- 不改运行评分逻辑。
- 不改日报渲染器。
- 不改测试。
- 不改 wiki。
- 不生成真实候选评分。
- 不自动调整权重。
- 不新增独立交易体系。
- 不把普通观察池全部补齐为完整评分对象。
- 不为未来 UI、数据库或多账户管理预留新子系统。

## Non-goals

- 不追求一次性做出完美权重。
- 不让分数替代买卖计划。
- 不让低成本替代选股质量。
- 不让行业大逻辑替代买点确认。
- 不让盘中问股绕过前一晚日报。
- 不把可见中文写成工程实现口径。
- 不增加无法改变动作的解释项。

## Done Definition

第一版实现完成时，必须满足：

- 日报生成前有固定前置步骤，且顺序为：市场情绪 -> 账户后台任务负担 -> 持仓优先动作 -> 今日新增上限 -> 候选评分。
- 日报候选主表只展示中文字段，且至少包含本文档定义的主表字段。
- 单票展开能同时给出选股质量、买点质量、风险项、成本项、持仓动作和新开仓动作。
- 盘中问股能读取或接收最新日报里的动作上限、恢复条件、取关条件、今日新增上限，并说明新事实是否改变原结论。
- 复盘校准表能记录当时判断、实际走势、偏离动作、错误归因和样本保护结果。
- 样本校准不能只修复一个小问题，却破坏核心样本、强主线样本或差票拦截样本。
- 用户可见中文不出现工程实现口径，统一使用交易语言。
- 后续实现任务可以拆给 subagent，并按本文档的工作包独立验收。

## 1.0 第一版判断顺序

候选质量系统的核心不是算出一个看似精确的总分，而是减少三类错误：

- 把真正核心票因为普通分歧误杀。
- 把差票因为便宜位置、MA、VWAP 或周 K 支撑误当成买点。
- 把未处理风险仓变成后台任务，持续占用注意力。

稳定顺序：

1. 市场情绪先行。
2. 账户约束先行。
3. 先挣分，再扣分。
4. 选股质量和买点质量拆开。
5. 持仓动作和新开仓动作拆开。
6. 风险项和成本项拆开。
7. 分数服务排序，动作上限决定最多能做到什么。

## 2.0 日报固定前置步骤

日报在进入候选表之前，必须先输出账户层面的总决策。这个前置步骤不是装饰，而是限制盘中临时冲动的交易合同。

### 2.1 前置步骤顺序

| 顺序 | 日报可见字段 | 后台字段建议 | 说明 |
|------|------|------|------|
| 1 | 市场情绪状态 | `market_emotion_label` | 主线扩张 / 分歧轮动 / 退潮踩踏 / 恐慌误杀 |
| 2 | 账户后台任务负担 | `account_attention_load` | 低 / 中 / 高 |
| 3 | 持仓优先动作 | `holding_priority_action` | 先处理哪只、按什么失效线处理、是否受可卖数量限制 |
| 4 | 今日新增上限 | `daily_new_entry_limit` | 0 / 1 / 2，受市场情绪和账户负担共同约束 |
| 5 | 主买对象 | `primary_buy_candidate` | 只能一只，没有就写暂无 |
| 6 | 补位对象 | `backup_candidate` | 只能一只，没有就写暂无 |
| 7 | 禁止动作 | `forbidden_actions` | 例如亏损后补仓、计划外追高、差票低吸 |
| 8 | 忽略清单 | `ignored_noise_items` | 对动作没有影响的信息噪音 |

### 2.2 前置步骤规则

- 市场情绪不支持进攻时，今日新增上限优先收缩。
- 账户后台任务负担为高时，先处理持仓风险，再看新增机会。
- 当前可卖数量不足时，持仓动作必须标注不可卖约束，不能把不可卖仓当作可立即处理仓。
- 主买对象和补位对象都必须来自候选主表，不能在日报末尾临时新增。
- 没有主买对象时，写 `暂无`，不能用后排干净票填空。
- 禁止动作必须是盘中能执行的短句，不能写成泛泛提醒。

## 3.0 三组必须拆开的概念

### 3.1 选股质量 vs 买点质量

选股质量回答：这只票是否值得排进视野。

买点质量回答：现在或明天是否适合参与。

| 项目 | 选股质量 | 买点质量 |
|------|------|------|
| 核心问题 | 它是不是市场正在选择的东西 | 现在做是否舒服 |
| 主要证据 | 当前上涨发动机、主线地位、市场辨识度、趋势审美、承接 | MA3/MA5/MA7/MA10、VWAP、开盘价、前高前低、成交密集区、盈亏比 |
| 典型错误 | 因普通噪音误杀核心票 | 因位置便宜误买差票 |
| 高质量低买点 | 保护选股资格，等待确认 | 不追高，最多补位或核心观察 |
| 低质量好买点 | 不新增参与 | 均线和 VWAP 只用于已有仓处理参考 |

第一版必须保护两个判断：

- 好票高成本：保留视野，不追高。
- 差票低成本：不因为靠近 MA、VWAP 或周 K 支撑就新增参与。

### 3.2 持仓动作 vs 新开仓动作

持仓动作回答：已经在手里的仓位怎么处理。

新开仓动作回答：没有仓或想新增时，是否还有参与资格。

| 项目 | 持仓动作 | 新开仓动作 |
|------|------|------|
| 主要输入 | 当前持仓、可卖数量、不可卖数量、成本、失效线、反抽位置 | 选股质量、买点质量、今日新增上限、动作上限 |
| 常见动作 | 持有、降仓、反抽减亏、按失效线处理、继续观察 | 主买、补位、核心观察、修复观察、不参与 |
| 不能混用 | 不能因为已有仓就给新增资格 | 不能因为不适合新开仓就忽略已有仓处理 |
| 输出要求 | 必须写可卖数量和不可卖约束 | 必须写触发条件和不满足怎么办 |

已有风险仓未处理时，日报先输出持仓优先动作，再决定今日是否允许新增。

### 3.3 风险项 vs 成本项

风险项回答：交易理由是否被伤到。

成本项回答：交易理由还在，但参与方式是否要收缩。

| 类型 | 典型情况 | 对分数影响 | 对动作影响 |
|------|------|------|------|
| A类风险 | 重大负面、当前上涨发动机被证伪、结构破坏、关键风险源缺失 | 不看总分 | 不参与；已有仓只按失效和反抽处理 |
| B类风险 | 发动机被澄清但核心地位还在、连续上影未修复、高位分歧但未破 | -15 到 -30 | 强核心最多核心观察，非核心最多修复观察 |
| C类成本 | 买点太高、远离 MA/VWAP、盈亏比差、当日追高成本不舒服 | -5 到 -15 | 最多补位或观察 |
| 信息不完整 | 公告、互动问答、当前上涨发动机、持仓可卖数量缺失 | -5 到 -20 | 关键数据不完整，停止生成主买结论 |
| 注意力成本 | 解释复杂、需要持续刷消息、会影响工作生活 | -5 到 -30 | 高负担时不新增参与 |

风险项不能被行业大逻辑抵消。成本项也不能把差票变成好票；它只能改变参与方式。

## 4.0 正向挣分

第一版满分 100。分数只服务排序和盘后校准，日报前台优先展示动作、原因、条件和失效。

| 维度 | 分值 | 后台字段建议 | 说明 |
|------|------|------|------|
| 市场情绪匹配 | 15 | `market_fit_score` | 指数、涨跌家数、跌停扩散、成交额、主线核心承接、昨日强票反馈 |
| 当前上涨发动机 | 15 | `upside_engine_score` | 候选上涨的真实发动机是否仍成立 |
| 市场辨识度 | 20 | `recognition_score` | 板块地位 10 分，个股辨识度 10 分 |
| 趋势审美 | 15 | `trend_aesthetic_score` | 120 日日 K 结构、呼吸感、重心、平台、缩量回踩、破坏形态 |
| 价格行为与承接 | 15 | `support_behavior_score` | 放量进攻、回踩承接、VWAP/均线收回、分时抗跌 |
| 风险干净程度 | 10 | `risk_cleanliness_score` | 公告、互动问答、监管、减持、澄清、质押等 |
| 盈亏比 | 5 | `risk_reward_score` | 离失效线和目标空间是否合理 |
| 低噪音程度 | 5 | `low_noise_score` | 是否低解释负担、低盯盘依赖、低后台任务 |

后排干净票不能靠“没缺点”超过真正核心票。评分必须先看正向挣分，风险少只是加分项，不是主买理由。

## 5.0 扣分和动作上限

扣分必须落到动作上限。只扣分但不改变动作的字段，第一版不新增。

| 项目 | 扣分 | 动作上限 |
|------|------|------|
| A类风险 | 不看总分 | 不参与 |
| B类风险 | -15 到 -30 | 强核心最多核心观察，非核心最多修复观察 |
| C类成本 | -5 到 -15 | 最多补位或观察 |
| 信息不完整 | -5 到 -20 | 关键风险源缺失时不主买 |
| 注意力占用 | -5 到 -30 | 高负担时不新增参与 |
| 解释负担 | -5 到 -30 | 解释越复杂，动作越保守 |
| 盯盘依赖 | -5 到 -20 | 无法按窗口执行时不参与 |

动作上限不是最终动作。最终动作还要看持仓状态、今日新增上限、买点质量和盘中触发条件。

## 6.0 动作映射

第一版动作只保留五层，避免日报出现多个相近词。

| 动作 | 条件 | 必须附带 |
|------|------|------|
| 主买 | 85 分以上，风险干净，买点舒服，市场情绪支持 | 触发条件、仓位上限、失效条件、不满足怎么办 |
| 补位 | 75-84 分，或高分但不是唯一核心，或成本限制不适合主买 | 触发条件、替代关系、失效条件 |
| 核心观察 | 选股质量高，但 B 类风险或买点成本不舒服 | 恢复条件、最晚复核 |
| 修复观察 | 历史价值仍在，但当前承接、结构或主线选择需要修复 | 修复路径、取关条件 |
| 不参与 | A 类风险、差票低成本、关键风险源缺失、注意力负担过高 | 不参与原因、是否取关 |

动作必须同时给恢复条件和取关条件。没有恢复条件的扣分容易变成永久偏见；没有取关条件的观察会变成后台任务。

## 7.0 字段建议

后台字段可以使用英文，便于实现和测试；日报、盘中问股、复盘表的可见字段必须使用中文。

### 7.1 总决策字段

| 日报可见字段 | 后台字段建议 | 类型建议 | 说明 |
|------|------|------|------|
| 市场情绪状态 | `market_emotion_label` | string | 主线扩张 / 分歧轮动 / 退潮踩踏 / 恐慌误杀 |
| 账户后台任务负担 | `account_attention_load` | enum | low / medium / high |
| 今日新增上限 | `daily_new_entry_limit` | int | 0 / 1 / 2 |
| 持仓优先动作 | `holding_priority_action` | string | 优先处理对象和失效线 |
| 主买对象 | `primary_buy_candidate` | object or null | 只能一个 |
| 补位对象 | `backup_candidate` | object or null | 只能一个 |
| 禁止动作 | `forbidden_actions` | list[string] | 盘中禁止做什么 |
| 忽略清单 | `ignored_noise_items` | list[string] | 不改变动作的信息 |

### 7.2 候选字段

| 日报可见字段 | 后台字段建议 | 类型建议 | 说明 |
|------|------|------|------|
| 候选 | `symbol_name` | string | 名称 + 代码 |
| 当前持仓 | `current_position_shares` | number | 无仓写 0 |
| 可卖数量 | `sellable_shares` | number | T+1 约束必须体现 |
| 不可卖数量 | `locked_shares` | number | 当天买入或其他不可卖部分 |
| 仓位性质 | `position_nature` | enum | 无仓 / 底仓 / 观察仓 / 趋势仓 / 风险仓 |
| 周期身份 | `cycle_identity` | enum | 超短参与 / 短线参与 / 短中结合观察 |
| 选股质量 | `selection_quality_label` | string | 高 / 中 / 低，并可附 `selection_quality_score` |
| 买点质量 | `entry_quality_label` | string | 舒服 / 等确认 / 不舒服，并可附 `entry_quality_score` |
| 风险项 | `risk_items` | list[object] | 风险分类、证据、恢复条件 |
| 成本项 | `cost_items` | list[object] | 价格成本、盈亏比、注意力成本 |
| 总分 | `candidate_total_score` | number | 后台排序使用，日报可按需要隐藏 |
| 动作上限 | `action_ceiling` | enum | 主买 / 补位 / 核心观察 / 修复观察 / 不参与 |
| 持仓动作 | `holding_action` | string | 已有仓怎么处理 |
| 新开仓动作 | `new_entry_action` | string | 无仓或新增时怎么处理 |
| 恢复条件 | `recovery_conditions` | list[string] | 什么事实出现后重新评估 |
| 取关条件 | `removal_conditions` | list[string] | 什么事实出现后移出观察 |
| 最晚复核 | `latest_review_at` | string | 日期或盘中时间窗口 |
| 最坏情境 | `worst_case_plan` | object | 最坏情境、触发条件、应对动作 |
| 一句话纪律 | `one_sentence_discipline` | string | 盘中只执行这一句话 |

### 7.3 与既有字段兼容

如后续实现需要兼容既有执行链字段，建议采用以下对齐关系：

| 既有字段 | V1 对齐含义 |
|------|------|
| `strength_score` | 选股质量里的市场强度部分 |
| `strength_role` | 候选在主线中的身份 |
| `tradability_score` | 买点质量和动作可做程度 |
| `execution_path` | 新开仓动作路径 |
| `sniper_grade` | 买点质量等级 |
| `fire_condition` | 触发条件 |
| `no_fire_condition` | 不满足怎么办 |

兼容字段可以保留在后台，但日报可见字段必须按本文档中文展示。

## 8.0 日报中文展示模板

### 8.1 今日总决策面板

| 字段 | 内容 |
|------|------|
| 市场情绪状态 | 主线扩张 / 分歧轮动 / 退潮踩踏 / 恐慌误杀 |
| 账户后台任务负担 | 低 / 中 / 高 |
| 今日新增上限 | 0 / 1 / 2 |
| 持仓优先动作 | 先处理哪只、按什么失效线处理 |
| 主买对象 | 只有一只，没有就写暂无 |
| 补位对象 | 只有一只，没有就写暂无 |
| 禁止动作 | 例如亏损后补仓、计划外追高、差票低吸 |
| 忽略清单 | 对动作没有影响的信息噪音 |

### 8.2 候选主表

| 候选 | 当前持仓 | 可卖数量 | 不可卖数量 | 仓位性质 | 周期身份 | 选股质量 | 买点质量 | 风险项 | 成本项 | 动作上限 | 持仓动作 | 新开仓动作 | 恢复条件 | 取关条件 | 最晚复核 |
|------|------|------|------|------|------|------|------|------|------|------|------|------|------|------|------|

主表规则：

- 主表只展示影响动作的字段。
- `风险项` 和 `成本项` 必须分列。
- `持仓动作` 和 `新开仓动作` 必须分列。
- 同一只票允许选股质量高、买点质量低；这不是矛盾。
- 无仓票的持仓动作写 `无仓`，不能空着。
- 不参与对象仍可保留一行，但必须写清取关条件或最晚复核。

## 9.0 盘中问股继承规则

盘中问股不是重新生成一份日报，而是在前一晚日报基础上更新事实。

### 9.1 必须继承

盘中问股必须继承：

- 市场情绪状态。
- 今日新增上限。
- 账户后台任务负担。
- 持仓优先动作。
- 候选动作上限。
- 恢复条件。
- 取关条件。
- 一句话纪律。

### 9.2 允许更新

盘中只允许因为新事实更新：

- 指数和涨跌家数明显改变。
- 主线资金明显回流或撤退。
- 候选竞价、开盘承接、回封质量、强弱线收回或跌破。
- 重大公告、澄清或监管信息出现。
- 预设确认窗口命中或失败。
- 持仓触发失效条件或恢复条件。

### 9.3 不允许更新

盘中不能因为以下原因改写计划：

- 论坛突然很多人看空或看多。
- 自己害怕亏损。
- 看到别的票涨了，想临时换。
- 持仓亏了，想找理由补仓。
- 原计划没触发，但觉得可能要启动。

### 9.4 升级和降级规则

- 不参与不能直接升为主买或补位。
- 修复观察只能在重新站回强弱线、板块回流、风险项修复后升为核心观察。
- 核心观察只能在风险干净、板块同步、VWAP/MA 收回、量能健康且恢复条件命中后升为补位。
- 补位只能在主买失格、该票成为同主线最强替代、且买点仍舒服时升为主买。
- 任一对象触发取关条件，盘中回答必须先承认原观察失败，再给处理动作。

## 10.0 复盘校准

复盘校准的目标不是追求事后完美，而是找出当时错误属于选股、买点、执行、市场、信息还是情绪。

### 10.1 复盘字段

| 字段 | 后台字段建议 | 说明 |
|------|------|------|
| 样本日期 | `sample_date` | 当时日报日期 |
| 样本 | `sample_symbol_name` | 名称 + 代码 |
| 当时市场情绪 | `market_emotion_label` | 当时总决策面板结论 |
| 当时选股质量 | `selection_quality_snapshot` | 分数、等级、主要理由 |
| 当时买点质量 | `entry_quality_snapshot` | 分数、等级、主要理由 |
| 当时风险项 | `risk_items_snapshot` | 风险分类和证据 |
| 当时成本项 | `cost_items_snapshot` | 价格成本、注意力成本、盈亏比 |
| 当时动作上限 | `action_ceiling_snapshot` | 当时最多允许做到什么 |
| 当时持仓动作 | `holding_action_snapshot` | 已有仓怎么处理 |
| 当时新开仓动作 | `new_entry_action_snapshot` | 新增参与怎么处理 |
| 实际走势 | `actual_outcome` | 次日、3 日、5 日、10 日表现 |
| 买点是否出现 | `entry_window_result` | 计划买点是否真实出现 |
| 用户是否偏离 | `user_deviation` | 是否追高、补亏、临时换票 |
| 错误原因 | `error_category` | 选股问题 / 买点问题 / 执行问题 / 市场问题 / 信息问题 / 情绪问题 |
| 改进归因 | `improvement_owner` | 系统问题 / 用户执行问题 / 市场问题 / 信息源问题 / 共同问题 |
| 样本保护结果 | `sample_protection_result` | 是否破坏保护样本 |

### 10.2 复盘判断口径

- 如果选股质量判断正确，但买点没有出现，不下单不是错误。
- 如果买点出现但用户追高偏离计划，优先归为执行问题。
- 如果风险项当时不可知，不能把事后信息全部归咎于系统。
- 如果差票低成本被拦住但后来反弹，只要反弹不是计划买点，也不算系统错杀。
- 如果核心票被普通噪音拦住，且后续主线继续选择它，要归为过度防守样本。
- 如果高分票因为成本太高没有主买，但后续给出回踩确认，系统应允许重新评估，而不是永久降级。

## 11.0 避免捡芝麻丢西瓜

校准时最容易出现的错误，是为了修复一个小样本，把核心规则改坏。第一版必须有“避免捡芝麻丢西瓜”的校准原则。

### 11.1 原则

- 先保护大机会：主线核心、辨识度高、趋势审美好、承接未坏的样本，不能被普通噪音轻易降到不参与。
- 再拦住差机会：低质量票不能因为价格便宜、靠近均线或短线反抽就获得新增参与资格。
- 小风险不直接改写大判断：论坛情绪、单次分时跳水、长期研究担忧，只能进入最坏情境或注意力成本，不能单独取消核心票资格。
- 大风险不能被小优点抵消：重大负面、上涨发动机被证伪、结构破坏，不能被便宜位置或行业故事抵消。
- 成本收缩动作，不抹掉选股：好票高成本应该降动作，不应该从视野里删除。
- 只有改变动作的字段才进入第一版：如果一个字段不会改变主买、补位、观察或不参与，就不进入 V1。

### 11.2 校准变更规则

每次调整权重、扣分或动作映射前，必须同时检查三类样本：

1. 必须保护样本：核心机会不能被普通噪音误杀。
2. 必须拦截样本：差票低成本不能被误判为可新增参与。
3. 成本约束样本：好票高成本不能被追高主买，也不能被永久取关。

如果一次调整只修复一个边角样本，却破坏以上任一保护样本，该调整不能进入第一版实现。

## 12.0 样本保护规则

### 12.1 基础保护样本

| 样本 | 类型 | 应有判断 | 保护点 |
|------|------|------|------|
| 晶方科技 | 好票高成本 | 保护选股资格，不追高；一字或远离 MA/VWAP 时核心观察或补位等待 | 不能因为成本高就删除核心视野 |
| 汇源通信 | 差票低成本 | 弱反抽、风险信息缺失、非核心高波动时不新增参与；MA/VWAP/周 K MA5 只作已有仓处理参考 | 不能因为位置便宜获得新增资格 |
| 圣阳股份 | 发动机澄清 | 如果当前发动机是 AIDC、数据中心、美国客户合作，互动问答澄清未达成合作后最多核心观察；非核心不进主买补位 | 当前上涨发动机被伤到时必须收缩动作 |
| 上峰水泥 | 持仓节奏 | 必须结合趋势、MA/VWAP、可卖数量给持仓动作；不能给无来源点位区间 | 持仓动作和新开仓动作必须分开 |

### 12.2 新增样本要求

新增校准样本必须包含：

- 样本日期。
- 当时日报原文或结构化快照。
- 当时市场情绪。
- 当时动作上限。
- 选股质量判断。
- 买点质量判断。
- 风险项和成本项。
- 次日、3 日、5 日、10 日结果。
- 结论：保护、拦截、修正或仅记录。

### 12.3 样本保护验收

- 任何规则变更都要说明修复了哪个样本。
- 任何规则变更都要说明是否破坏基础保护样本。
- 基础保护样本不能只看总分，必须看最终动作。
- 同一个样本不能既当作修复证据，又忽略它对其他动作层的伤害。
- 复盘允许承认“判断正确但收益一般”，不能因为收益一般就强行改规则。

## 13.0 后续实现拆分建议

后续可以拆给 subagent，但每个 subagent 只负责一个纵向切片，避免扩大架构。

| 工作包 | 负责内容 | 不做什么 | 验收 |
|------|------|------|------|
| A. 字段合同 | 定义总决策字段、候选字段、复盘字段的数据结构 | 不改渲染样式 | 能从样例数据生成完整结构 |
| B. 评分与动作映射 | 实现正向挣分、扣分、动作上限和三组概念拆分 | 不接入完整日报 | 样本能得到预期动作上限 |
| C. 日报展示 | 在日报固定位置展示总决策面板、候选主表、单票展开 | 不新增顶层大章节 | 可见字段全为中文 |
| D. 盘中继承 | 盘中问股读取最新日报结论，并只按新事实更新 | 不重新生成完整日报 | 不参与对象不能直接升为主买或补位 |
| E. 复盘校准 | 记录复盘字段、样本保护结果和 3/5/10 日验证 | 不自动调权重 | 能判断规则变更是否破坏保护样本 |
| F. Wiki 与测试同步 | 将稳定规则同步到知识入口，并补充最小测试 | 不新增平行交易体系 | 文档、测试、replay 口径一致 |

当前 V1 字段合同落点：`scripts/selection/candidate_quality_contracts.py`。它只提供总决策面板、候选主表、单票展开的结构化字段和中文可见字段，不负责真实评分、排序、日报渲染或盘中问股执行。

当前 V1 字段输入口径：面板里的禁止动作、忽略清单，以及候选合同里的风险项、成本项、恢复条件、取关条件等列表型文本字段必须兼容单个字符串输入；字符串按一条处理，不能被当作字符序列拆成单字。列表归一化时过滤 `None` 和空字符串，避免结构化数据里出现空风险、空条件或空噪音项。

当前 V1 仓位字段口径：候选显式提供仓位性质时优先使用原值；未提供但当前持仓大于 0 时显示“已有仓”；当前持仓为 0 时显示“无仓”。当前持仓、可卖数量和不可卖数量可以是数字或数字字符串，判断、持仓动作生成和候选主表展示前必须转成数值，避免字符串 `"0"` 被误判为已有仓，也避免表格里同一类数量一会儿像数字、一会儿像文本。不能让持仓样本在候选主表里被默认写成无仓，也不能让空仓样本生成已有仓处理动作。

当前 V1 样本动作映射落点也在 `scripts/selection/candidate_quality_contracts.py`。它只覆盖基础保护样本的动作上限校准：好票高成本、差票低成本、发动机澄清、持仓节奏。它不代表完整评分模型，不负责真实候选排名。

当前 V1 独立渲染落点：`scripts/report/candidate_quality_renderer.py`。它只消费总决策面板和候选质量合同，渲染“今日总决策面板、候选主表、单票展开”的 Markdown 片段，不接入完整日报大结构。

当前 V1 日报挂载方式：先作为 `action_plan` 的可开关节点 `candidate_quality` 接入。只有 `enabled_node_keys` 显式包含 `candidate_quality` 时才渲染，不抢主结论和既有候选表位置。节点可直接消费已经构造好的 `candidate_quality_panel` / `candidate_quality_contracts`，也可从 `candidate_quality_panel_fields` / `candidate_quality_samples` 生成第一版样例片段。嵌入明日操作计划且同时渲染 overview 时，候选质量标题使用子层级，不高过“明日操作计划”；单独诊断渲染 `candidate_quality` 时使用正常标题层级。标题最大只到 6 级，单票名在极深层级改用加粗行，避免生成无效标题。独立渲染保留完整候选主表；嵌入明日操作计划时使用精简主表，完整风险、成本、持仓和恢复信息放在单票展开里。候选主表保留“风险项：证据 / 成本项：证据”，单票展开因字段名已显示，不重复输出同名标签。

当前 V1 运行时输入落点：`scripts/domains/execution_chain/pk_decision_nodes/action_plan_context.py` 会从 PK 决策上下文派生 `candidate_quality_panel_fields` 和 `candidate_quality_samples`，`scripts/domains/execution_chain/pk_decision_nodes/render_sections.py` 负责透传给 `render_action_plan_section`。PK 已选出的主买对象进入候选质量样本时默认标为高质量核心、买点确认中；补位对象默认标为中等质量、买点确认中；默认标注只补空字段，不能覆盖候选对象自身已有的成本、风险或质量字段。后续真实评分接入后再替换这些默认标注。同代码候选合并时，先保留主买/补位角色，再补充后续样本里的风险、成本、持仓等证据字段，避免角色正确但证据丢失；风险和成本列表按先来在前、后来补充的顺序合并去重，不用后一个来源直接覆盖前一个来源；限制性成本如高成本可以覆盖默认“确认中”，低成本不能把主买对象改成便宜低吸语义。如需展示，调用侧传入 `action_plan_enabled_node_keys=["overview", "candidate_quality"]`；不传时不改变默认日报输出。

当前 V1 新增上限约束：今日新增上限为 0 时，即使 PK 上下文里存在主对象，候选质量样本也只能标为核心观察，不能在候选主表里显示主买或给新增参与动作。主买对象名称可以保留在总决策面板里，表示重点跟踪对象，但动作上限必须服从今日新增上限。

当前 V1 主买/补位显示口径：如果主买对象和补位对象是同一代码，候选质量总决策面板只显示主买对象，补位对象写暂无，避免同一只票同时承担两个角色造成主次混乱。

当前 V1 盘中继承落点：`scripts/selection/candidate_quality_contracts.py` 的 `resolve_intraday_action_update`。它只消费前一晚动作层级、今日新增上限和盘中新事实，输出中文可见字段“前一晚动作层级、盘中动作、变化方向、是否允许新增、原因、处理动作”。它不读取实时行情，不重新筛股，不生成完整盘中问股回答。

当前 V1 盘中继承输入口径：今日新增上限可以来自配置、JSON 或日报快照，允许传入数字或数字字符串；进入比较前必须先转成数值。字符串 `"0"` 必须等同于 0，不能触发新增参与；字符串 `"1"` 必须等同于 1，恢复条件完整命中时才允许逐级上调。

当前 V1 复盘校准落点：`scripts/selection/candidate_quality_contracts.py` 的 `build_candidate_quality_review_record` 和 `evaluate_sample_protection_change`。前者记录当时判断、实际走势、买点是否出现、用户是否偏离、错误原因、改进归因和样本保护结果；后者只判断一次规则变更是否伤到保护样本。它不自动调权重，不根据单个收益结果改写交易规则。

## 14.0 实现顺序建议

第一版最小纵向切片：

1. 先定义字段合同。
2. 再做样本驱动的评分与动作映射。
3. 再接日报展示。
4. 再接盘中继承。
5. 最后接复盘校准和样本保护检查。

不要先做自动调权重。先记录 10-20 个真实样本，再讨论权重调整。

每次权重调整必须保留至少一个必须修正样本、一个必须保护样本、一个必须拦截样本和一个成本约束样本。
