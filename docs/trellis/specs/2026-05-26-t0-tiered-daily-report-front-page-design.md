# T0 分层与日报首页账户建议设计

## 文档定位

本 spec 定义日报首页如何先给出 1w 账户可用的明日建议，以及附录里的候选、观察池、跨线线索如何统一进入 T0/T1/T2/T3 分层。本文档只确定第一版展示与排序规则，不在本阶段修改运行代码。

校准样本是 2026-05-26 日报：正文开头写 0% 不参与，个股前台给出华天科技，附录又出现步步高、大众公用、红星发展等不同名单，导致用户不知道明天到底看谁、在哪看、能不能买。

## In Scope

- 日报第一屏新增 `明日账户建议`，先回答明天 1w 账户到底怎么做。
- 首页 T0 只允许 0-1 个主对象和 0-1 个备用对象。
- 首页必须区分有昨日持仓和无昨日持仓：有持仓时先处理持仓，再判断是否允许新开一手。
- 附录所有候选名单统一增加分层含义：T1 主线核心、T2 次主线或备选方向、T3 观察线索。
- 同一只股票在多个附录名单里出现时，以最高分层为准展示，不在不同位置制造互相冲突的动作口径。
- 688 开头、一手金额超过当前账户能力、需要同时买多只才成立的方案，不得进入首页 T0 新开仓建议。
- 5月26日样本必须能收口为：T0 只给华天科技条件观察；步步高、大众公用、红星发展等只保留在附录分层里，不在首页制造新增动作。

## Out of Scope

- 不删除完整候选池。
- 不否定市场层面的强票、热票和跨线观察价值。
- 不重写候选生成逻辑。
- 不新增多账户管理系统。
- 不改变历史报告文件。
- 不把所有 T1/T2/T3 股票都补成完整单票诊断。

## Non-goals

- 不追求列全。
- 不追求每天都给新买点。
- 不让附录研究名单替代首页动作建议。
- 不让多个候选名单同时争夺“明天看谁”的解释权。
- 不用丰富名单制造可操作性的错觉。

## Done Definition

第一版实现完成时，必须满足：

- 日报开头在市场细节之前出现 `明日账户建议`。
- 首页明确写出：当前账户约束、昨日持仓处理、新开仓上限、T0 主对象、T0 备用对象、今日不看什么。
- T0 主对象最多 1 只；T0 备用对象最多 1 只；没有就写暂无。
- 如果当前建议是 0% 或只观察，首页不得再出现旧主买说法等新增动作表达。
- 附录候选表统一展示层级列，且 T1/T2/T3 的标题和动作口径一致。
- 同一只股票在多个池中出现时，最终只按最高层级进入首页摘要，附录可保留来源，但不能给出冲突动作。
- 用户可在报告第一屏知道明天是否处理持仓、是否新开一手、只看哪 1-2 个对象。

## 分层定义

### T0：明日账户动作层

T0 是首页唯一动作层，只回答 1w 账户明天怎么做。

T0 字段：

| 字段 | 含义 |
|------|------|
| 账户状态 | 约 1w；是否已有昨日持仓；是否有可卖数量约束 |
| 明日动作 | 处理持仓 / 新开一手 / 条件观察 / 不参与 |
| 主对象 | 最多 1 只 |
| 备用对象 | 最多 1 只 |
| 新开仓上限 | 0 / 1 |
| 触发条件 | 竞价、开盘承接、主线同步、回封或60分钟确认中的必要条件 |
| 失效条件 | 条件不满足就继续不参与，或已有持仓按预案处理 |
| 不看什么 | 说明 T1/T2/T3 只观察，不分散资金 |

T0 选择规则：

- 有昨日持仓且需要处理时，T0 优先写持仓处理，新增对象自动降级为观察。
- 无昨日持仓时，T0 才能给新开一手建议。
- 1w 账户不适配的股票不能进入 T0 新开仓建议，但可以保留在 T1/T2/T3。
- 市场不支持新增参与时，T0 可以有条件观察对象，但不能写成主买。
- T0 备用只在主对象买不到、未触发或不适合时才出现。

### T1：主线核心层

T1 是最可能升级到 T0 的主线内核心池。

T1 只回答：市场最值得继续盯的主线核心是谁。它不直接等于明日买入。

进入 T1 的条件：

- 属于当前主线或主线候选里最强的少数对象。
- 有资金、辨识度、承接或趋势密度支持。
- 没有被账户约束直接排除市场身份。

展示规则：

- 首页只写 T0 从 T1 里缩出来，不展开 T1 全名单。
- 附录可以列 1-3 只 T1，并写清“只观察还是可能升级”。

### T2：次主线 / 备选方向层

T2 是次强方向、主线内次核心、备用方向。

T2 只回答：如果主线不继续，哪些方向需要观察强弱变化。

展示规则：

- T2 不进入首页动作建议。
- T2 不使用“主买”“补位”这类动作词。
- T2 的动作口径统一为观察强弱、等待重新进入 T1。

### T3：观察线索池

T3 包含异动池、热榜池、跨线观察、涨停预期、历史记忆、冷却回看等素材。

T3 只回答：有哪些线索值得记录。它不回答明天买什么。

展示规则：

- T3 只能写观察线索、复盘样本、再激活条件。
- T3 不得写成旧主买说法或旧可做候选说法。
- T3 股票如果后续满足主线、承接和账户条件，下一次日报再升级到 T2/T1/T0。

## 5月26日样本重排

按本设计，2026-05-26 日报应当收口为：

| 层级 | 股票 | 口径 |
|------|------|------|
| T0 | 华天科技(002185) | 0%条件观察；只看强弱与承接是否重新成立，不满足继续不参与 |
| T1 | 华天科技(002185)、中船特气(688146)、晶方科技(603005) | 半导体主线核心观察，其中 688146 因账户约束不能进入 T0 新开仓建议 |
| T2 | 晶方科技(603005)、新洁能(605111)、三佳科技(600520) | 半导体次核心或备选观察，不直接给明日动作 |
| T3 | ST得润(002055)、*ST联翔(603272)、*ST景谷(600265)、*ST高科(600730)、步步高(002251)、大众公用(600635)、红星发展(600367) 等 | 异动、跨线、涨停惯性或历史记忆线索，只记录，不分散首页动作 |

首页第一屏应类似：

```text
明日账户建议
- 账户约束：约1w账户，先看是否有昨日持仓需要处理。
- 明日动作：不新开；只做条件观察。
- T0主对象：华天科技(002185)，只看强弱与承接是否重新成立。
- T0备用：暂无。
- 新开仓上限：0。
- 今日不看：其余 T1/T2/T3 只放附录观察，不同时盯多只，不为多个名单分散资金。
```

如果用户已有昨日持仓，首页第一屏改为：

```text
明日账户建议
- 账户约束：约1w账户，已有昨日持仓优先处理。
- 明日动作：先按持仓预案处理旧仓，不为新候选分散资金。
- T0主对象：昨日持仓对象或暂无。
- T0备用：华天科技(002185)仅作条件观察。
- 新开仓上限：0。
```

## 冲突消解规则

同一报告内如果多个列表给出不同股票，按以下优先级收口：

1. 账户持仓处理优先于新增。
2. T0 优先于 T1/T2/T3。
3. T1 优先于 T2/T3。
4. T2 优先于 T3。
5. 附录来源可以保留，但动作口径必须服从最高层级。

标题改写规则：

| 旧标题或口径 | 新口径 |
|------|------|
| 旧主买说法 | T0 主对象，仅在允许新增参与时使用 |
| 旧补位说法 | T0 备用对象，仅在允许新增参与时使用 |
| 旧可做候选说法 | T1 主线核心观察，是否可做由 T0 决定 |
| 旧跨线候选说法 | T3 跨线观察线索 |
| 旧观察池说法 | T1/T2/T3 分层观察池 |

## 验收样本

### 必须修复

2026-05-26 日报不允许出现以下体验：

- 开头写 0% 不参与，但附录仍把多只股票写成新增动作。
- 首页给华天科技，附录又让用户以为步步高、大众公用、红星发展也能成为明日动作。
- 明天观察池写 15 只，却不告诉用户 1w 账户实际只该看哪 1-2 只。

### 必须保留

- 完整候选池仍保留在附录。
- 市场核心身份不因账户约束被删除。
- 688 或一手金额不适配的股票仍可保留市场层级，但不能进入 T0 新开仓建议。

## 实现边界

第一版只做最小闭环：

- 增加 T0 首页决策卡。
- 给候选快照或渲染层增加 T0/T1/T2/T3 展示口径。
- 修改附录标题和动作词，避免 T3 写成可参与动作。
- 增加 2026-05-26 样本测试，锁定“首页最多 1+1、附录分层但不抢首页动作”的行为。

不新增复杂评分系统，不重做所有候选来源。
