# 量化锚点参与设计

## 背景

2026-05-21 盘面出现多个带有明显对子数或整数特征的价格：例如中微公司 533.33、芯源微 330.00、江丰电子 222.22、德龙激光 88.88、通富微电 66.88 等。用户指出，这类价格如果出现在区间顶部或底部，可能不是孤立巧合，而是量化、条件单、心理价位和场外待成交力量共同形成的价格反应点。

这类现象需要进入 LLM Wiki 和日报参与脚本，但不能被神化成独立买入理由。它应该与 VWAP、MA3、MA5、MA10、MA20、区间上下沿、前高前低和成交密集区配合使用，给均线和区间判断打辅助。

## In Scope

- 在 LLM Wiki 中沉淀“心理价位与量化锚点”的交易规则。
- 扩展“明日极度看好”的共同选择一致性，把量化动量和隐藏买卖盘纳入解释。
- 给 `planned_participation` 或候选本体新增附加字段，用于表达量化锚点、区间位置、均线/VWAP 共振、隐藏买卖盘和锚点动作。
- 在每日日报的主买/补位或重点观察参与脚本中，用短句展示量化锚点动作。
- 增加测试，保护“顶部卖压、底部承接、放量吃掉、反包兑现”四类行为。

## Out of Scope

- 不把对子数直接做成主买/补位排序的核心分数。
- 不修改 `entry_timing`、`participation_review.status` 等现有稳定枚举。
- 不让 snap-ui 重新计算买卖点。
- 不新建一个独立交易系统。
- 不建设完整的对子数历史回测数据库。

## Non-goals

- 不证明对子数天然有效。
- 不把对子数、整数位或心理价位写成无条件买点。
- 不用长篇理论污染日报正文。
- 不用固定价格格式替代价格行为、板块、资金、辨识度和承接。

## Done Definition

- Wiki 有稳定规则：对子数是量化/心理/隐藏买卖盘锚点，只能辅助 VWAP、MA、区间和承接。
- Compact LLM Wiki context 能读到核心规则。
- 日报主买/补位或参与脚本能显示简短的量化锚点动作说明。
- 现有主买/补位、速度档、买点线、卖点线、T+25 跟踪和复盘表不被破坏。
- 测试覆盖顶部卖压、底部承接、放量吃掉、反包兑现四类样本。

## 设计原则

对子数不是孤立价格，而是价格锚点的一种。它的价值在于提示某个区间顶部或底部可能存在比肉眼看到更大的待卖或待买力量。用利弗莫尔的语言，它更接近无形的场外力量：价格看似被买完或卖完，但上方仍有待卖，或下方仍有承接。

系统判断顺序必须是：

1. 先看位置：锚点处在区间顶部、区间底部，还是中间噪音。
2. 再看共振：锚点是否与 VWAP、MA3、MA5、MA10、MA20、前高前低、成交密集区重合。
3. 再看反应：冲不过、放量不涨、长上影，是隐藏卖盘；跌不破、缩量止跌、站回 VWAP，是隐藏买盘。
4. 最后定动作：顶部冲不过偏止盈；底部不直接买，必须等承接确认。

## LLM Wiki 设计

### 价格行为与能量框架

在 `wiki/交易思想/价格行为与能量框架.md` 新增小节：`心理价位与量化锚点`。

规则：

- 对子数、整数位、前高前低、涨停价、VWAP、MA、成交密集区，都属于价格锚点。
- 锚点只说明市场可能在这里反应，不说明一定能买或一定会涨。
- 顶部锚点冲不过、放量不涨、留下上影线，按隐藏卖盘和止盈观察处理。
- 底部锚点不直接买，只有缩量止跌、站回 VWAP、10 点确认、板块不继续走弱，才允许观察或小仓试错。
- 锚点被放量吃掉，回踩不破，才说明压力被消化。
- 高潮后反包优先按兑现窗口看，不能默认新一轮主升。

### 极度看好参与时机

在 `wiki/交易思想/极度看好参与时机.md` 扩展 `common_selection_check`。

共同选择一致性从三方扩成四方：

- 昨日持筹者：为什么不急着卖，或为什么会在锚点附近兑现。
- 明日新买盘：为什么愿意在锚点附近接。
- 主线资金：为什么仍选择这个方向。
- 量化动量：当前图形更可能被量化助攻，还是触发单边卖出。

可写成一句交易问题：我预判别人会怎么预判别人。

## 日报字段设计

不改现有字段名和枚举，只新增附加字段。

候选或 `planned_participation` 可新增：

| 字段 | 作用 | 示例 |
|------|------|------|
| `anchor_zone_role` | 锚点处在区间顶部、底部，还是中间噪音 | `区间顶部` |
| `anchor_line_confluence` | 是否与 VWAP / MA3 / MA5 / MA10 / MA20 / 前高前低共振 | `接近前高与MA5` |
| `hidden_liquidity_read` | 判断隐藏卖盘还是隐藏买盘更强 | `隐藏卖盘更强` |
| `anchor_action_plan` | 冲不过、跌不破、放量吃掉、跌破收不回分别怎么做 | `冲不过先止盈，放量吃掉并回踩不破再恢复候选` |
| `common_selection_factors` | 持筹者、新买盘、主线资金、量化动量四方解释 | `持筹者有兑现压力，新买盘需等VWAP确认` |
| `momentum_feedback_plan` | 动量助攻或反向砸盘的应对 | `越跌越弱时不低吸，站回VWAP后再看` |
| `reversal_exit_plan` | 高潮后反包处理 | `反包先按先手兑现点，吃掉压力后再观察` |

## 日报展示设计

不单独新增大表，避免正文变重。优先放在“明日主买与补位”或“重点观察参与脚本”里，用一列或一段短句展示。

示例：

```text
量化锚点动作：533.33 位于区间顶部且接近前高，冲不过并留下上影先按止盈；只有放量吃掉并回踩不破，才恢复持有或再参与。
```

```text
量化锚点动作：66.88 靠近 MA5/VWAP 与短线箱体下沿，只作承接观察；未站回 VWAP 前不参与，站回后只给小仓确认。
```

用户可见表达必须保持交易语言：资格、条件、参与、不参与、止盈、观察、恢复候选。避免工程实现词。

## 复盘设计

复盘不统计“碰到对子数就成功”。只复盘动作是否正确：

- 顶部锚点冲不过后回落：是否按计划止盈或降仓。
- 底部锚点无承接：是否避免低吸。
- 放量吃掉锚点并回踩不破：是否恢复候选资格。
- 高潮后反包：是否优先按先手兑现点处理。

## 测试设计

新增或扩展测试：

- `test_llm_wiki_context.py`：compact context 包含对子数辅助 VWAP/MA、隐藏买卖盘、顶部止盈、底部承接确认。
- `test_decision_ledger.py`：`planned_participation` 能保存量化锚点附加字段，且不破坏现有主买/补位字段。
- `test_front_page_v2_renderer.py` 或候选渲染测试：日报短句展示锚点动作，不写成长篇理论。
- `test_selection_trend_runtime.py`：顶部对子数冲不过不提高主买资格；底部对子数未站回 VWAP 不给直接参与；放量吃掉锚点只恢复候选，不自动主买。

## 子任务拆分

实施时可交给 subagent 并行，但写入范围要互不重叠：

- 子任务一：Wiki 与 compact context。负责 wiki 文档、`llm_wiki_context.py` 和对应测试。
- 子任务二：参与脚本字段。负责 `planned_participation` 或候选本体字段传递和 decision-ledger 测试。
- 子任务三：日报展示与验收。负责主买/补位展示短句和 renderer 测试。

每个子任务都不得修改现有枚举，不得重算 snap-ui 买卖点，不得把对子数直接写成主买排序核心分数。

## 风险与防漂移

- 风险一：对子数被误用成买入理由。
  - 处理：所有表达必须带“已有交易资格后辅助执行”的前提。
- 风险二：日报正文变长。
  - 处理：只显示短句动作，不展示理论。
- 风险三：字段过多导致维护成本上升。
  - 处理：先作为附加字段，不影响旧字段契约。
- 风险四：底部锚点被当作抄底按钮。
  - 处理：底部锚点必须叠加 VWAP/10 点确认/板块不继续走弱。
- 风险五：高潮后反包被追高。
  - 处理：默认按先手兑现点，除非放量吃掉压力并回踩不破。
