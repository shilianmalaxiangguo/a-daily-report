# A 股日报：市场与板块事实阅读

2026-10-26：默认入口已改为独立【板块日报】；当前主线先读 [交易 Wiki](wiki/README.md)，再用板块日报查看目标日事实。日报是带来源、日期和缺口的事实适配层，不是交易理念、盈利证明或视觉产品竞赛。页面继续图表优先，不用固定条件生成每天重复的“当前理解”“下一观察”“竞争解释”，不先生成旧完整版，也不推断账户或调用旧交易处方。实施边界见 [框架重建 PRD](docs/plans/2026-10-22-daily-report-framework-rebuild-prd.md)。

## 当前功能

- 板块图表：目标日涨跌按来源分组画图，行业净额单独画图；同日有效记录保留，单位、来源日期、查询日期和样本详情可核对。
- 跨日图表：板块接力、月度相对比较、全行冷暖矩阵、单板块/日期联动及价格、回撤、上涨面保留。
- 市场图表：涨跌家数、两市成交、Top50与创业板、完整Top30、期货60/20日、创新高、龙虎榜保留；封板金额有事实才画。
- 图表直接展示，完整数值表、来源和取得时间按需展开；周期文字日历、旧竞争表和模板分析不再占据日常页面。
- 新采集有独立事实来源，不依赖旧完整版或旧HTML。历史回放可复用经快照和原始凭据核对的板块原页；纯快照也可成页，不保证每一天都有相同图表数量。
- 来源日期、真实查询时间、历史隔离优先；缺数不冒充零，不自动变成账户结论。

板块是事实阅读入口，不是所有个股机会的唯一入口。当前交易路线由 Wiki 定义：用户明确不是价值投资路线，但这不是“价值投资普遍失败”的统计结论；短线、波段和其他方法不按名称排序，方法按可实现净收益、成本、风险、机会成本和后来反馈比较。没有绝对永远正确的系统，也不把单个投资案例当作流派证明。旧账户日序、分笔模板、固定仓位与交易时间、旧仓继承、均线动作不再是当前日报依据。新具体买卖参数尚未定案，不借代码改造补造。

## 快速开始

所有 Python 命令必须使用仓库解释器；不静默切换版本。采集客户端继续通过 `scripts/market_data/tushare_client.py` 读取本地 `.env` 中的 `TUSHARE_TOKEN` / `TUSHARE_HTTP_URL`，不要在文档、日志或提交中写入密钥。

```bash
# 默认板块阅读：优先读取已有目标日快照
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-10-20

# 纯快照回放，不联网刷新旧资料
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-10-20 --replay

# 无快照的历史日期：明确按目标日来源重新整理，仍只写 replay
.generated/venv-py314/bin/python3.14 scripts/daily_report_entry_demo.py 2026-10-20 --historical-rebuild

# 独立离线渲染，不要求完整版 HTML 存在
.generated/venv-py314/bin/python3.14 scripts/report/sector_daily_report.py - snapshots/2026-10-20.json --output reports/replay/2026-10-20_A股日报_板块日报_replay.html
```

未指定日期时读取上海日期的昨天；遇到休市日且无快照，不自动拿当前行情替代。已有快照默认不重新采集；`--force-live` 只能用于当日，历史无快照请显式 `--historical-rebuild`。当前日首次生成可保存正式页；非当日或已有正式页时转入 `reports/replay/`，不覆盖历史。历史行业缺口不借当前上市行业映射伪造。

## 旧完整版怎样处理

旧完整版可以抢救的是目标日事实、时间序列、来源、历史判断和研究资料；它不再适合作为当前首页或买卖处方。`--output-mode full` 只定位已有历史原件，不采集、不重算、不保存新旧建议；`short` 已停用，不是新版采样实现。重建快照需要显式 `--replay --snapshot-source replay`，避免静默读错版本。

旧 `scripts/report/compact_bear_report.py` 直接生成命令也已停用，避免独立脚本继续带入旧操作建议。正式快照与页面使用同一保存版本，既有或并发产生的正式文件不覆盖。

历史记录有明确事实日但未记录完整查询/来源字段时，保留数字、已有取得时间和原文件指纹，同时说明缺口；不拿文件保存时间补造查询日。明确错日、未来日期和相互矛盾的事实仍不接受。

保留旧源码是为了现有历史消费者，不代表旧策略继续有效；当前生产入口已停止调用旧账户生成链，不宣称物理删除了所有历史模块。后续物理删除必须先核对调用者，不能破坏历史查证，也不能让保留源码重新决定当前交易。详细模块处置见 PRD。

## 2026-10-21 板块资格链修复：方向名、扩散计数与旧证明复用

修复前的事实：`data/decision-ledger` 77 个交易日（2026-05-12~10-20）里 54 天 `0%不参与`，非零只出现在 6 月的 6 天；10-20 的 43 只候选全部是 `legacy_signal_only`。原因不是市场判断，而是三处让资格链走不通的实现问题。

- 方向名三套并存：报告用标准板块名 `光通信/CPO`，趋势快照用行业原始名 `元器件/半导体`，候选又用 `通信设备`。`_sector_names_match` 只做字符串相等和包含，所以标准板块永远匹配不到自己的成员行业，`内部扩散` 读到的趋势数/强势数恒为 0。现按报告自带的 `sector_ai_analysis.mapping` 与 `sector_tree` 建标准名索引：只承认“标准名与其成员行业”之间成立，两个成员行业互不相等；趋势行按成员行业求和后判定。
- 证明自引用：上一轮写进 `data/context/market_research_snapshot` 的证明会被下一次计算当成外部证据读回，`divergence_acceptance=false` 这类显式布尔一旦出现就每天沿用。现识别自身产物（`produced_by` 或同时带 `direction/complete/evidence_gaps`），只重算、不复用；状态区分 `unresolved`（没证据）与 `failed`（证据否定）。
- 板块内候选没有来源资格：过去只有 `sector_derived_candidates`/`sector_leader_candidates` 两个窄入口能取得 `sector_first`。现在板块证明成立时，属于该方向（含成员行业）的候选即具备来源；能否成为执行对象仍由板块角色、执行证据和目标日价格承接单独判定。
- 可观测：证明输出新增 `observed`（方向、命中的行业行、趋势数、强势数、扩散规则、承接原文、竞争原文），报告读者能看到卡在哪一项、看到的是什么值，而不是模板句。
- 当日实际效果（冻结 10-20 快照 A/B 对比）：`内部扩散` 从“读不到 0/0”变为 `元器件 6 涨 1 强`（未达 `趋势数≥2且强势数≥2`），`承接` 读到 `承接一般`（未确认）；明日执行对象仍是 `无`，仓位仍是 `0%不参与`，43 只候选来源不变。也就是说 0% 现在是可解释的市场结论，不再是被写死的路径。
