# 阿尔法与贝塔阅读 PRD（2026-10-29）

> 历史研究档案，保留用于阿尔法／贝塔独立复算和比较；不属于当前小盘日报入口，不恢复旧首屏、候选或执行建议。

## 1. 要改善的决定

用户 2026-10-29 原话：“我的理念是阿尔法。是个股自己的独立行情跟大盘涨跌关系不大，贝塔？是大盘涨跌带动个股共振的行情。现在的板块日报没有这个体现。”

日报每天要帮用户回答两件事：

1. 现在的行情以哪种为主：大盘涨跌带动个股一起动（贝塔），还是个股自己走、与大盘关系不大（阿尔法）？
2. 哪些个股、哪些概念正在走自己的行情；哪些看起来强，其实只是跟着大盘放大。

这个决定现在容易做错，原因是：

- 页面没有任何全市场层面的判断，原首屏明确写着“不自动替你贴标签”“不推断全市场由哪类行情主导”。
- 比较只覆盖自动选出的几个概念的成员，默认打开“证金持股”“同花顺漂亮100”这类篮子概念。
- “个股减大盘”的简单差值没有扣除个股自身的贝塔：高贝塔股票在大盘上涨时天然跑赢，会被误认成独立行情；大盘下跌时又被误认成独立走弱。
- 2026-10-29 正式页在当天 00:26 生成，目标日指数、涨跌家数、成交额和概念行情全部缺失仍然发布，正文还堆了约400条代码，图表却标“事实截至2026-10-29”。

## 2. 方法（本轮确定，写明即可修正）

| 项目 | 本轮口径 |
|---|---|
| 大盘基准 | 中证全指 `000985.CSI`，按 `index_daily` 的收盘价与前收盘价计算日收益 |
| 股票范围 | 沪深A股（`6xxxxx.SH`、`0/3xxxxx.SZ`），剔除目标日ST（`stock_st`）及资料区间首日之后上市的股票；北交所不含 |
| 日收益 | 来源收盘价 ÷ 来源前收盘价 − 1；与来源 `pct_chg` 相差超过0.011个百分点的行剔除并计数 |
| 窗口 | 默认最近20个交易日，可切60个交易日；窗口内每天都有有效收益才参与 |
| 模型 | 个股日收益 = a + 贝塔 × 大盘日收益 + 残差（普通最小二乘） |
| 贝塔 | 回归斜率：大盘每涨跌1%，个股平均跟着涨跌多少 |
| 关联度 | 回归 R²：个股日波动中能被大盘解释的比例（股价同步性） |
| 大盘贡献 | 贝塔 × 窗口内大盘日收益之和 |
| 独立收益 | 窗口内个股日收益之和 − 大盘贡献（等于窗口天数 × a） |
| 近5日独立收益 | 用同一贝塔，只看最后5个交易日 |

贝塔收缩：20个观测值估出的贝塔噪声大（实测凡拓数创普通回归贝塔5.05，按它推算的“大盘贡献”为−75个百分点，交易上不可信）。按 Vasicek 方法，每个窗口用全部合格股票贝塔的均值与方差作先验，单只股票的贝塔按自身估计误差向均值收缩（凡拓数创收到2.02）。大盘贡献与独立收益都用收缩后的贝塔。

个股与概念标签按“这段行情由谁驱动”分类（阅读分类，不是买卖指令）：

| 标签 | 条件 |
|---|---|
| 独立上涨（阿尔法） | 独立收益的 t 值 ≥ 临界值（20日窗口 2.101，60日窗口 2.002，约5%双侧显著），且窗口内确实上涨 |
| 抗跌 | 独立收益显著为正，但窗口内仍下跌（只比贝塔推算的跌得少，不算独立行情） |
| 跟随大盘（贝塔） | 独立收益不显著，且与大盘显著正相关 |
| 跟涨乏力 | 独立收益显著为负，但窗口内仍上涨 |
| 独立走弱 | 独立收益显著为负，且窗口内下跌 |
| 无明显方向 | 其余 |

关联度（R²）单独显示，表示每天跟大盘一起波动的程度；独立上涨的股票关联度也可能不低，即同时带有贝塔和阿尔法。

曾试过更严格的口径：阿尔法另要求关联度不显著。10-27 实测只剩8只，大盘20日跌约14.8%时上涨107%的凡拓数创也被排除（关联度0.48）；概念层面“MLOps概念”下跌3%却被标为独立上涨。前者违背用户原话里“独立行情”指的是行情由谁驱动，后者把抗跌误称为上涨，所以都不采用。

全市场判断：

- **共振度**：以某日为终点的20日窗口里，全部合格股票 R² 的中位数（股价同步性）。看它在近42个窗口中的位置：上三分之一为“大盘带动强”，下三分之一为“弱”，其余为“中”。
- **独立行情多少**：独立收益显著为正的只数（独立上涨加抗跌），与随机预期“合格股票数 × 2.5%”比较。5000只股票里即便全无独立行情，也会有约125只偶然显著，所以只看倍数：≥ 2 为“多”，1–2 为“一般”，< 1 为“少”。页面同时单列独立上涨只数。
- **今日同向比例**：当天与中证全指同方向涨跌的股票占比，平盘不计；两者无关时约为50%。
- **结论**：大盘带动强且独立行情不多 → 贝塔主导；带动弱且独立行情不少 → 阿尔法活跃；其余 → 两者并存。
- 同一模型用于同花顺概念指数（快照已有逐日涨跌），概念成分重叠，不相加、不当作独立样本。

这些分档是阅读约定，不是交易条件；改变时同步改本节和页面口径说明。

### 资料留存

快照新增 `reading_market_returns`（`market_returns.v1`）：61个交易日、沪深A股收盘价与前收盘价、中证全指、查询日简称与行业、目标日ST名单、剔除行数与缺口。价格按“每日一行文本”保存，避免带缩进写入时每个数字占一行（18.6MB 降到约5.3MB）。来源会返回收盘价为0、涨跌幅−100%的占位行（实测3个交易日共17行），这些行剔除并计数。快照写入上限由64MB调到80MB：原快照已约61MB，其中Top50原页约38MB；合并Top50与本资料的重复日线抓取另作后续提案。

### 已知限制

- 20个观测值的估计噪声大；涨跌停会截断收益；残差相关会让“偶然显著”的只数波动更大。
- 股票简称与行业为查询日资料（`latest_at_query`），不是历史简称或历史行业。
- 指数不能直接成交；结论不证明独立行情会持续，也不证明可以盈利。

## 4. 生成条件修正

当日生成（联网采集）时，若目标日中证全指和概念行情都未取得（未收盘或来源未更新），停止生成，不保存快照、不发布页面，提示收盘数据更新后再生成。历史快照重放不受影响。

## 5. 范围

### In Scope

1. 全市场日收益采集、校验与留存：快照新增 `reading_market_returns`（`market_returns.v1`），按日缓存且每次重新校验，目标日未收盘的数据不缓存。
2. 个股、全市场、概念指数三层的阿尔法/贝塔计算。
3. 首屏新区块、图表脚本与样式。
4. 原首屏改名后置、缺失概念汇总、报头一句结论。
5. 当日目标日行情全缺时停止生成。
6. 定向测试；2026-10-27 replay（向 replay 快照补充按目标日查询的全市场行情）与 2026-10-29 历史重建 replay。
7. 文档：本 PRD、Wiki 定义页的口径链接、AGENTS 记录。

### Out of Scope

- 买卖指令、仓位、订单、唯一对象。
- 概念成分全量映射、历史逐日成员、行业或风格多因子模型。
- 覆盖正式历史页面与正式快照（10-29 盘前坏页的处理见交付说明）。

### Non-goals

- 不证明阿尔法可持续或可盈利；不以单日逆市判定阿尔法；不把板块成员共涨称作贝塔。

## 6. Done Definition 与验证

- 新区块在 10-27 replay 与 10-29 replay 中可见，结论和数字与独立复算一致：用 numpy 另写一套回归，对全部合格股票的贝塔、R²、独立收益、t 值逐只比对。
- 合成数据：纯贝塔股票判为跟随大盘；独立上涨股票判为阿尔法；大盘下跌中少跌的股票只判抗跌；缺一日的股票不判；ST 与区间内新股排除；日期、指纹或价格明细被改动时拒绝。
- 交叉核对：新数据的目标日上涨/下跌家数与原快照 `market_stats` 对照（同一服务的不同查询，差异如实列出）。
- 当日行情全缺时停止生成有测试。
- 浏览器桌面窗口：无脚本错误、画布非空、点选表格行联动路径图、20/60日切换。
- 正式报告与正式快照哈希不变。

能证明的只是计算、展示与日期边界正确；标签是否有交易价值，要靠事前冻结标签后的后续表现检验（下一步提案：每日冻结独立上涨名单，5/10/20日后统计其相对大盘的表现与成本后收益）。

## 8. 后续提案（不在本轮范围）

1. 每日冻结“独立上涨”名单，在其后5/10/20个交易日统计相对中证全指的表现、回撤与成本后收益，用不挑样本的后续结果检验阿尔法是否持续、是否值得交易。
2. Top50 成交占比与本资料重复抓取同一日线接口；合并为同一份全市场日线留存，可让快照减少约30MB。
3. 为独立上涨个股补概念成分映射（目前按查询日行业汇总），把个股阿尔法与概念跟踪直接对上。
