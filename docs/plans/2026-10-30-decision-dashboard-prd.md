# 决策仪表盘 PRD：阿尔法与贝塔 PK 后怎么做（2026-10-30）

> 历史研究档案，保留阿尔法／贝塔模型与回测证据；当前日报不按本 PRD 生成仪表盘、仓位建议、候选卡或手机验收。

## 0. 用户诉求与改写

用户 2026-10-30 原话要点：整体样式要改；要说清哪些阿尔法有买的价值，哪些贝塔和哪些阿尔法 PK 之后整体建议如何操作；现在大盘很差；现有日报样式、逻辑、表达都很乱；最终要的是“总裁看到的报表数据”那样的图表结构。

用户定义不变：阿尔法是个股自己的独立行情，跟大盘涨跌关系不大；贝塔是大盘涨跌带动个股共振的行情。

### 0.1 顶尖从业者会做、但诉求里没写的

- **从决定倒推页面**：第一屏只回答“明天做什么、不做什么、什么情况下改主意”，其余都是证据，按“结论 → 依据 → 明细”逐层展开（金字塔原则）。
- **事先写死买入条件和失效条件**：哪只阿尔法“可做”由公开的检查表决定，每只候选都给失效价，而不是看完图再挑。
- **用后来的行情检验规则，而不是用入选理由证明自己**：按今天的名单回看过去20日，入选本身就因为过去走得好；真正的检验是“在过去每个交易日按同一规则选，之后5天怎样”。
- **按真实可成交的方式算**：次日开盘才能买、开盘涨停买不到、扣往返成本。
- **把建议记账**：每天的建议冻结，之后用结果对账，方法没有优势时直接降低参与。

### 0.2 最原始的材料

不是旧日报的图表、标签、GPT 写的段落或涨幅榜，而是：按明确交易日查询的全市场沪深A股日线（开盘、收盘、前收盘、成交额）、中证全指日线（开盘、收盘、前收盘）、交易日历、目标日ST名单、目标日涨跌停名单，以及每个历史决策日之后的真实价格。用户的交易原话（阿尔法/贝塔定义、“利好就是利空”“高开必卖”）是约束；真实账户与成交记录目前没有提供，页面不推断持仓。

### 0.3 方法与工具

- 市场模型 + Vasicek 贝塔收缩（沿用 10-29 口径），共振度（股价同步性）判断大盘带动强弱。
- 阿尔法候选五项检查表（见 2.2），通过项数与失效价公开。
- 贝塔敞口情景：大盘再跌2%或反弹2%时，按贝塔推算两组篮子的涨跌。
- 滚动前推检验：过去每个可检验交易日，只用当日及以前的数据按同一规则选出阿尔法篮子与贝塔篮子，次日开盘买入、第5个交易日收盘卖出，扣0.2%往返成本，与中证全指比较。
- 总体建议规则：大盘带动强弱 × 大盘20日趋势 × 前推检验是否有优势，三者决定“防守/均衡/进攻”和阿尔法、贝塔各自“可做/少做/不做”。
- 图表：管理层报表式仪表盘（结论卡、指标条带迷你走势、PK 对比、候选卡片、明细图），ECharts 与服务端 SVG 迷你图；Python 3.14 计算，numpy 独立复算，Chrome 实页检查。

### 0.4 除你我之外，什么能证明对错

- **后来的价格**：滚动前推检验的结果（相对每个决策日都是之后才发生的行情），以及从今天起冻结的每日建议在5/10/20日后的对账。
- **独立复算**：另写一套 numpy 实现复算检查表、篮子与前推收益，逐项一致。
- **真实浏览器**：Chrome 打开后第一屏（1440×900）就能看到总体建议、可做候选和失效价。

### 0.5 改写后的提示词

> 把板块日报改成一份决策仪表盘。第一屏回答：现在是大盘带动的贝塔行情还是个股独立的阿尔法行情；阿尔法与贝塔 PK 后明天整体怎么做（防守/均衡/进攻，贝塔和阿尔法各自可做/少做/不做）；哪些阿尔法有买入资格、凭什么、在哪个价格失效；什么情况出现就改判断。原料用按交易日查询的全市场日线（开盘、收盘、前收盘、成交额）、中证全指日线、ST 与涨跌停名单，不用旧日报的结论。阿尔法候选必须通过公开检查表：仍在走强、大盘跌时不跟跌、不是急涨末端、成交额足够、目标日没涨停；每只给失效价。PK 用两种证据：当前两组篮子的贝塔敞口情景，以及过去两个月每个交易日按同一规则选股、次日开盘买入、5日后卖出、扣成本后相对中证全指的前推结果；规则没有优势就直说并降低参与。页面按“结论 → 指标条带 → PK → 候选 → 大盘明细 → 板块 → 附图”排列，样式参照管理层报表：每张图一句结论、数字带单位、红涨绿跌、少文字。不推断账户持仓、不给固定仓位档、不恢复旧B1/B2；“利好就是利空”“高开必卖”写进纪律。用 numpy 独立复算、Chrome 实页检查第一屏、正式历史哈希不变来验收；先交 PRD 再实现，replay 只写 replay 目录。

## 1. 要改善的决定

每天收盘后：明天整体是防守、均衡还是进攻；贝塔（跟着大盘走的股票与板块）做不做；阿尔法里哪些有买入资格、怎么买、哪里失效；什么信号出现就改判断。现在的页面给不出这些，且样式像图表堆砌，没有从结论到证据的顺序。

## 2. 方法

### 2.1 沿用

市场模型、贝塔收缩、标签（独立上涨/抗跌/跟随大盘/跟涨乏力/独立走弱/无明显方向）、共振度与独立行情只数，见 `2026-10-29-alpha-beta-reading-prd.md`。

### 2.2 阿尔法买入资格检查表（20日窗口、只看“独立上涨”）

| 检查 | 口径 | 不通过意味着 |
|---|---|---|
| 仍在走强 | 近5日独立收益 > 0 | 独立行情可能在退潮 |
| 大盘跌时不跟跌 | 窗口内大盘下跌日，个股平均涨跌 ≥ 0 | 实际仍受大盘拖累 |
| 不是急涨末端 | 近3日日涨跌之和减去“3×窗口日均涨跌”（比自身节奏多出的部分）< 2 × 个股日波动 × √3 | 急涨后容易兑现（“利好就是利空”） |
| 止损距离可承受 | 失效价（近10日最低收盘）在现价下方15%以内 | 追在高位，止损太远、单笔可能亏损太大 |
| 成交额足够 | 20日日均成交额 ≥ 1亿元 | 进出困难、价格易被少量资金推动 |
| 目标日能买到 | 目标日未涨停（主板≥9.8%、创业板/科创板≥19.8%视为涨停） | 次日大概率高开，追高 |

- 六项全过：**检查全过**（相对最值得买）；只差“急涨末端”或“止损距离”：**等回调**；“成交额”或“能买到”未过：**不做**；其余：**观察**。是否真去买，由 2.4 的总体建议决定：规则近期没有优势时，检查全过的只是观察名单。
- 实施中的两处修订（如实记录）：
  1. 首版只有五项。预览页上大业股份20日涨90%、失效价在现价下方48%仍被判“可做”，从单笔风险出发加入“止损距离可承受”。
  2. 首版“急涨末端”用近3日涨幅直接比较，合成测试发现每天稳定涨1%左右的股票会被误判为急涨；改为比较超出自身节奏的加速部分。
  3. 两处修订都不是为了改善回测。前推结果（相对中证全指，5日后、扣成本）：首版五项 10-27 为 −1.23 个百分点、跑赢41%，10-29 为 −1.35、43%；最终六项 10-27 为 −1.85、30%，10-29 为 −2.02、30%；最终口径去掉止损检查 10-27 为 −0.63、46%，10-29 为 −0.80、46%。各版本都没有优势，止损检查在这段时间还让结果更差；保留它是因为它控制单笔最大亏损，而平均超额衡量不到这一点。总体建议在各版本下都是“阿尔法先观察”。
- 排序：通过项数，其次独立收益 t 值。
- 失效价：近10个交易日最低收盘价；收盘跌破即视为独立行情失效。页面同时给出失效价相对现价的百分比（失效价 ÷ 现价 − 1）。
- 纪律：次日高开超过3%不追；已持有的独立上涨股遇高开，按用户认可的“高开必卖”处理。不给仓位比例。

### 2.3 贝塔篮子与 PK

- 贝塔篮子：标签为“跟随大盘”、成交额足够、目标日未涨停，按收缩后贝塔从高到低取前10只，代表“大盘反弹最受益、继续下跌最受伤”的股票。
- 阿尔法篮子：检查表“可做”的股票（不足时取通过项最多的前10只）。
- 情景：两组篮子平均贝塔 × 大盘 −2% / +2%，只算大盘带来的部分。
- 前推检验：决策日 t 用 [t−19, t] 的数据按同一规则选两组篮子；t+1 开盘买入（开盘涨停视为买不到），持有到 t+5 收盘；收益按“t+1 收盘/开盘 × 之后每日收盘/前收盘”连乘，跨除权仍正确；等权、扣0.2%往返成本；与中证全指同区间比较。统计平均、中位数、跑赢比例；相邻日期区间重叠，等效独立样本约为日期数的五分之一，页面写明。

### 2.4 总体建议规则

| 条件 | 总体 | 贝塔 | 阿尔法 |
|---|---|---|---|
| 贝塔主导且中证全指20日下跌 | 防守 | 不做 | 前推有优势：只做“可做”；否则只观察 |
| 贝塔主导且20日上涨 | 进攻 | 可做（顺大盘） | 作为补充 |
| 阿尔法活跃 | 均衡 | 少做 | 前推有优势：精选“可做” |
| 其余 | 均衡 | 少做 | 同上 |

“前推有优势”= 阿尔法篮子扣成本后相对中证全指平均为正，且跑赢比例 ≥ 50%。

改判断的信号（展示约定）：同向比例连续3日低于60%（大盘带动减弱）；中证全指收盘重新站上20日均价（趋势转好）；显著独立收益只数超过随机预期2倍（阿尔法变多）。

## 3. 页面结构（仪表盘）

1. 顶栏：日期、行情截至、查询时间、总体建议徽标。
2. 结论卡：总体建议一句话；三条依据（带数字）；明天怎么做（贝塔 / 阿尔法 / 纪律）；改判断的信号。
3. 指标条带：中证全指、个股中位数、涨跌家数、同向比例、共振度、独立上涨、两市成交额，各带近两个月迷你走势。
4. 阿尔法 vs 贝塔 PK：两组篮子对比表与情景；前推检验图与统计；一句 PK 结论。
5. 有买入资格的阿尔法：候选卡片（检查表、关键数字、实际走势对“只跟大盘”迷你图、失效价），其下为全部独立上涨股的检查表。
6. 大盘明细：共振走势、分类列表、全市场散点、概念层面（10-29 区块，去掉与结论卡重复的指标）。
7. 板块与附图：原板块图表、跨日图表、成员同窗比较、市场图表，统一卡片样式，不删除事实。
8. 口径与限制（收起）。

## 4. 样式

管理层报表风格：浅灰紫底、白色卡片、细边框；每张卡片标题下一句结论；关键数字大号无衬线、带单位；红涨绿跌（#E73922 / #07C160），分类色只区分序列；徽标颜色：防守深蓝、均衡紫、进攻红；同一行卡片等高；文字段落不超过两行，说明进收起区或悬浮。第一屏（1440×900）必须看到总体建议、明天怎么做和至少一张可做候选（若有）。

## 5. 数据

`reading_market_returns` 升级为 `market_returns.v2`：每日一行“序号,收盘,前收盘,开盘,成交额(千元)”；中证全指加开盘价；缓存目录改为 `market-returns-v2`。快照约增加5MB，仍在80MB上限内。

## 6. 范围

- In Scope：数据 v2、决策计算（检查表、篮子、情景、前推检验、总体建议）、仪表盘渲染与样式、相关测试、10-27 与 10-29 replay、文档。
- Out of Scope：账户持仓与订单、仓位比例、旧B1/B2与固定时窗、盘中数据、覆盖正式历史、行业/风格多因子模型、概念成分全量映射。
- Non-goals：不承诺收益；不把两个月的前推结果说成长期规律；不删除冻结事实。

## 7. Done Definition 与验证

- 两份 replay 第一屏可见总体建议、明天怎么做、可做候选（或“暂无可做”）与失效价。
- 合成数据测试：检查表各项边界、涨停买不到、开盘涨停跳过、跨除权收益、成本扣减、无候选日期、规则表四种情形。
- numpy 独立复算：检查表结果、两组篮子、前推收益与统计逐项一致。
- 交叉核对：用新数据汇总的两市成交额、涨停股与快照原有值对照。
- Chrome 桌面窗口：无脚本错误、首屏元素检查、PK 图与迷你图非空。
- 定向测试通过（已知无关失败除外），replay 重复生成逐字节一致，正式历史哈希不变。
