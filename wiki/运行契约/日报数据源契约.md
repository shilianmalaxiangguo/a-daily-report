# 日报数据源契约

## 核心规则

fresh daily generation 必须按 Tushare-first 执行。目标是快速稳定高效生成日报，并同步产出 snap-ui public data，而不是每天先碰不稳定的网页抓取路径。

本仓库使用 Tushare gateway，不直接依赖默认公开端点。运行链路必须经过 `scripts/market_data/tushare_client.py` 的 `create_tushare_pro_api`，并保留 `TUSHARE_HTTP_URL = "http://a.sszhixia.cn/"` 的中转站设置。

Tushare 基本用法入口以官方“沪深股票”文档为准：<https://tushare.pro/document/2?doc_id=14>。新增或替换数据源时，先按这个基础文档确认 Pro API 调用方式、`ts_code` 后缀规范和沪深市场数据范围，再落到具体接口文档。

本仓库的本地检查和日报维护按 Python 3.14-first 执行；不要在 3.14 缺依赖时静默退回 3.11。若 3.14 环境尚未安装依赖，必须明确说明，并把“使用现有 venv 跑本次验证”或“创建/安装 3.14 venv”作为显式选择。

日报生成链路里已经登记的判断因子，失败就停止生成。采集阶段只要把某项写入 `data_status=False` 或 `step_status=False`，预检必须把它放进失败字段；只有明确允许为空的市场事实例外，例如当天没有涨停、没有跌停、没有对应板块分布。雪球热榜、雪球 AI 解释、创新高反馈、Top50 成交额占比趋势、龙虎榜、概念资金流、价格带风格趋势等都不是可静默跳过的装饰项，缺失时统一按“关键数据不完整，停止生成”处理。

## 默认顺序

- 首选：Tushare。日线、指数、成交额、个股成交额、行业映射、资金流向等结构化数据优先走 Tushare。
- 兜底：akshare / iwencai / Eastmoney / Tencent / 本地缓存只作为 fallback only。只有 Tushare 缺字段、无返回、接口失败，或者某个数据域 Tushare 当前没有对应能力时，才允许进入兜底路径。
- 禁止：fresh daily generation 一开始就直接跑 akshare 或 iwencai 的基础市场数据请求。

| 板块热榜 | `ths_hot(market="概念板块")` / `ths_hot(market="行业板块")` | 本地同花顺板块脚本 |
| 板块涨跌幅 | `ths_index` + `ths_daily` | iwencai / Tencent |

## 特色源边界

不是所有非 Tushare 请求都要替换。若某个数据域本身是外部加工模型、资讯流或社区榜单，保留原始 provider，但要把价格事实、成交额、指数、涨跌幅等结构化基础事实尽量交给 Tushare。

这类混合链路的日志必须同时写清模型/榜单源和结构化事实源。例如 `request.exchange_monitor` 的 `provider` 保持 `quicktiny.exchange_monitor`，同时用 `quote_provider` 标记触发判定补价来自 `tushare.daily` 还是 Tencent 兜底。

| 数据域 | 保留 provider | Tushare 可接管部分 |
|---|---|---|
| 板块四象限 | `quicktiny.sector_analysis_quadrant` | 暂无，属于 QuickTiny 加工模型 |
| 异动检测预测池 | `quicktiny.exchange_monitor` | 今日触发判定补价使用 `daily` 优先 |
| 选股通盘中异动 | `xuangubao.fetch_xuangubao_data` | 后续只补结构化行情事实 |
| 顽主杯热门前十 | `AShareDataCollector.get_wanzhu_top10` | 榜单股票行情字段使用 `daily` 优先补价 |
| 预期日历 | `tencent.get_calendar_events` | 暂无稳定 Tushare 等价替代前保留 |
| 雪球A股24小时热榜 | `xueqiu.hot_stock.type22` | 只作社区热度补充，行情字段用 `daily` 优先补价 |
| 雪球热榜AI解释 | `xueqiu.hot_stock.argument` | 只作当前炒作理由候选，事实字段仍要回到公告、问董秘和结构化行情确认 |

当前竖切已经接入 `stock_hot_rank`、`limit_pool_snapshot`、`sector_hot_plates`、`sector_change_rank`、`sector_fund_flow`、`lhb_snapshot`、`new_stock_calendar` 七个服务出口。入口层通过 `scripts/input/request_registry.py` 拿稳定能力名，不直接感知底层是 Tushare、旧脚本、Mongo、Postgres 或 JSON 文件。

## 社区热榜补充源

雪球热榜属于社区注意力数据，不是价格、成交额或行业归属的结构化事实源。它可用于和同花顺/淘股吧热榜互相校准热度，但不能单独决定主线或买点。

- A 股 24 小时热榜使用 `stock.xueqiu.com/v5/stock/hot_stock/list.json?detail=1&include=1&page=1&size=100&type=22`，provider 记为 `xueqiu.hot_stock.type22`。
- 抓包验证中 `type=22` 对应 A 股 / CN / 24 小时热榜，样例前排包括 `胜宏科技 SZ300476`、`信维通信 SZ300136`、`京东方A SZ000725`、`三环集团 SZ300408`、`贵州茅台 SH600519`。
- `type=12` 可作为 A 股短周期热榜观察，使用前要单独标注周期，不和 24 小时榜混写。
- `type=10` 是更泛的短周期热榜，可能混入 KWEB、腾讯、富途等非 A 股标的，不能当作纯 A 股热榜源。
- 雪球热榜 AI 解释使用 `api.xueqiu.com/rainbow/ai/question/generate/hot_stock_argument.json?symbols=...`，provider 记为 `xueqiu.hot_stock.argument`。抓包返回按股票代码映射，核心字段包括 `content`、`question`、`score`、`url`、`record_id`、`share_id`，日报归一化为“炒作理由候选”。
- 这个源比普通讨论帖更接近雪球产品侧对热榜股票的当下叙事摘要，适合帮助识别“市场正在用什么理由炒这个票”。但它仍然不是公告事实、业绩事实或合作事实；若问董秘/公告澄清和它冲突，以澄清内容作为反证，并用价格承接判断市场是否仍愿意买这个叙事。
- `rainbow/ai/question/generate/hot_stock_argument.json` 是热榜股票后的理由补充，不是热榜列表本身。
- 雪球接口通常需要 cookie / app UA；本地优先从 `XUEQIU_COOKIE` 读取，临时抓包可用 `XUEQIU_COOKIE_CAPTURE_DIR` 指向包含 `request_header_raw.txt` 的目录提取 cookie。雪球热榜和雪球 AI 解释属于当日 tag 池与炒作理由判断的关键因子，cookie 过期、缺失、接口失败或返回空时，必须记录“雪球登录态失效或缺失，关键数据不完整，停止生成”，不能用残缺证据继续生成日报。
- 融资承接压力是日报中的正式市场热度因子之一，正文只展示近 25 个交易日；250 日样本只用于历史校准，判断融资承接比和上证指数、中证全指之间的关系，不直接铺到日报正文。若 `margin`、`index_daily` 或合并后的融资承接压力结果为空/不完整，同样按“关键数据不完整，停止生成”处理。

## 个股风险快照

日报生成必须先对持仓、候选、明日主买对象和补位对象生成个股风险快照，再进入形态审美和主买比较。风险快照至少覆盖 ST/退市、减持、强制执行、司法冻结、监管异常、停牌核查、异常波动和热门题材澄清。

互动问答、同花顺问董秘、深交所互动易、投资者关系活动优先使用 Tushare 官方 `irm_qa_sh` / `irm_qa_sz` 接口。该接口属于大模型语料专题数据，可能需要单独权限；若无权限、接口失败或返回空，再使用 `INVESTOR_QA_ENDPOINT_URL` 接入外部 JSON 源。外部源只要求返回行列表，字段可包含 `code` / `ts_code` / `stock_code`、`question`、`answer`、`summary`、`content`、`reply`、`source`、`pub_date`、`url`；运行时会用 `trade_date=YYYY-MM-DD` 查询。

日报风险快照默认查询近 10 个自然日覆盖到的交易日互动问答，不只查目标交易日当天。原因是问董秘/互动易类回答常在盘后或周末发布，且市场炒作可能延续数日；只查当天容易漏掉圣阳股份这类 `2026-05-20` 发布、`2026-05-22` 仍影响题材空间的澄清。若调用方注入自定义函数且不支持窗口参数，运行时退回单日调用以兼容测试和离线回放。

若公司回应热门题材尚未合作、尚未形成收入或利润、业务占比小、无相关规划、无重组计划或传闻不实，按炒作预期降维处理。它不是直接等同暴雷：先从市场主线、候选理由、概念标签、关联板块和热门原因推导 `current_driver_tags`，再判断澄清是否命中当前上涨发动机；命中时加重扣分，未命中时只做提示。强行情、主线锚定、强价格形态时，保留观察资格并扣分，不作为主买加速或盘中加仓理由；非核心、形态弱或市场退潮时，直接不进入明日极度看好。未配置 `INVESTOR_QA_ENDPOINT_URL` 且 Tushare 问答源不可用时，该来源返回空列表，不影响日报生成，但风险快照会缺少这类澄清来源。

## snap-ui 公共数据

snap-ui public data 的生成也继承 Tushare-first：先把日报需要的结构化事实落成稳定 JSON，再让前端消费。Cloudflare 只负责展示和少量 API，不承担每日临场补数据。

## 验收标准

- 日报入口的基础市场请求默认绑定到 Tushare-first wrapper。
- 市场活跃度请求默认先调用 `stock_hot_rank`、`limit_pool_snapshot`、`sector_hot_plates`、`sector_change_rank`、`sector_fund_flow`、`lhb_snapshot` 服务出口，新股日历默认先调用 `new_stock_calendar` 服务出口；Tushare 成功时不得调用旧同花顺、AkShare、iWenCai、Tencent、finshare 或 Sina 兜底。
- 个股风险快照默认合并公告、股东交易、交易异常和问董秘/互动易类澄清来源；无问答源配置时安静跳过，有配置时必须在候选比较前完成合并。
- akshare / iwencai 在日志里出现时，必须是 fallback only 或兼容旧数据域。
- `tests.test_tushare_input_runtime` 是数据源顺序的回归测试。
