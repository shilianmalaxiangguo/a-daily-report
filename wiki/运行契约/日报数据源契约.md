# 日报数据源契约

## 核心规则

fresh daily generation 必须按 Tushare-first 执行。目标是快速稳定高效生成日报，并同步产出 snap-ui public data，而不是每天先碰不稳定的网页抓取路径。

本仓库使用 Tushare gateway，不直接依赖默认公开端点。运行链路必须经过 `scripts/market_data/tushare_client.py` 的 `create_tushare_pro_api`，并保留 `TUSHARE_HTTP_URL = "http://118.89.66.41:8010/"` 的中转站设置。

Tushare 基本用法入口以官方“沪深股票”文档为准：<https://tushare.pro/document/2?doc_id=14>。新增或替换数据源时，先按这个基础文档确认 Pro API 调用方式、`ts_code` 后缀规范和沪深市场数据范围，再落到具体接口文档。

本仓库的本地检查和日报维护按 Python 3.14-first 执行；不要在 3.14 缺依赖时静默退回 3.11。若 3.14 环境尚未安装依赖，必须明确说明，并把“使用现有 venv 跑本次验证”或“创建/安装 3.14 venv”作为显式选择。

## 默认顺序

- 首选：Tushare。日线、指数、成交额、个股成交额、行业映射、资金流向等结构化数据优先走 Tushare。
- 兜底：akshare / iwencai / Eastmoney / Tencent / 本地缓存只作为 fallback only。只有 Tushare 缺字段、无返回、接口失败，或者某个数据域 Tushare 当前没有对应能力时，才允许进入兜底路径。
- 禁止：fresh daily generation 一开始就直接跑 akshare 或 iwencai 的基础市场数据请求。

## Tushare 能力矩阵

| 日报能力 | Tushare 首选接口 | 旧 provider 降级 |
|---|---|---|
| 两市成交额 | `daily` 汇总 `amount` | iwencai / AkShare |
| 主要指数 | `index_daily` | iwencai / AkShare |
| 成交额排行 | `daily` 排序 | Eastmoney / iwencai / AkShare |
| 个股热榜 | `ths_hot(market="热股")` | 本地同花顺脚本 / Tencent |
| 涨跌停池 | `limit_list_ths`，必要时补 `limit_list_d` | AkShare 涨跌停池 |
| 板块热榜 | `ths_hot(market="概念板块")` / `ths_hot(market="行业板块")` | 本地同花顺板块脚本 |
| 板块涨跌幅 | `ths_index` + `ths_daily` | iwencai / Tencent |
| 行业资金流 | `moneyflow_ind_ths` | Tencent |
| 龙虎榜 | `top_list` / `top_inst` | finshare |
| 新股日历 | `new_share` | Sina / 本地解析 |
| 异动检测触发判定补价 | `daily` | Tencent 批量行情 |

## 特色源边界

不是所有非 Tushare 请求都要替换。若某个数据域本身是外部加工模型、资讯流或社区榜单，保留原始 provider，但要把价格事实、成交额、指数、涨跌幅等结构化基础事实尽量交给 Tushare。

这类混合链路的日志必须同时写清模型/榜单源和结构化事实源。例如 `request.exchange_monitor` 的 `provider` 保持 `quicktiny.exchange_monitor`，同时用 `quote_provider` 标记触发判定补价来自 `tushare.daily` 还是 Tencent 兜底。

| 数据域 | 保留 provider | Tushare 可接管部分 |
|---|---|---|
| 板块四象限 | `quicktiny.sector_analysis_quadrant` | 暂无，属于 QuickTiny 加工模型 |
| 异动检测预测池 | `quicktiny.exchange_monitor` | 今日触发判定补价使用 `daily` 优先 |
| 选股通盘中异动 | `xuangubao.fetch_xuangubao_data` | 后续只补结构化行情事实 |
| 顽主杯热门前十 | `AShareDataCollector.get_wanzhu_top10` | 榜单股票行情字段使用 `daily` 优先补价 |
| 预期日历 | `tencent.get_calendar_events` | 暂无稳定 Tushare 等价替代前保留 |

当前竖切已经接入 `stock_hot_rank`、`limit_pool_snapshot`、`sector_hot_plates`、`sector_change_rank`、`sector_fund_flow`、`lhb_snapshot`、`new_stock_calendar` 七个服务出口。入口层通过 `scripts/input/request_registry.py` 拿稳定能力名，不直接感知底层是 Tushare、旧脚本、Mongo、Postgres 或 JSON 文件。

## snap-ui 公共数据

snap-ui public data 的生成也继承 Tushare-first：先把日报需要的结构化事实落成稳定 JSON，再让前端消费。Cloudflare 只负责展示和少量 API，不承担每日临场补数据。

## 验收标准

- 日报入口的基础市场请求默认绑定到 Tushare-first wrapper。
- 市场活跃度请求默认先调用 `stock_hot_rank`、`limit_pool_snapshot`、`sector_hot_plates`、`sector_change_rank`、`sector_fund_flow`、`lhb_snapshot` 服务出口，新股日历默认先调用 `new_stock_calendar` 服务出口；Tushare 成功时不得调用旧同花顺、AkShare、iWenCai、Tencent、finshare 或 Sina 兜底。
- akshare / iwencai 在日志里出现时，必须是 fallback only 或兼容旧数据域。
- `tests.test_tushare_input_runtime` 是数据源顺序的回归测试。
